# 기능 계층 명세 v1.0 — 추가 항목

[FUNCTION_HIERARCHY_v1.0.md](FUNCTION_HIERARCHY_v1.0.md)는 사용자 원문이라 고치지 않는다(본문 SHA-256 고정). 오너가 새 기능을 지시하면, 원문의 적용 원칙에 따라 **가장 가까운 기존 화면의 3단계 번호 이하**에 더하고 여기에 적는다. 원칙은 "기능 추가만을 이유로 독립 메뉴·영역을 만들지 않는다", "여러 화면에서 같은 기능을 사용할 때는 주 소속을 하나로 정한다"이다.

- 기존 번호는 바꾸지 않는다.
- 진행 상태(설계·구현·병합·배포)는 [FUNCTION_STATUS](FUNCTION_STATUS.md)에 적는다.
- 새 앱 구조 트리(`#/tree`)는 이 파일의 번호 줄을 원문 번호 사이에 "추가 명세" 표시로 끼워 보인다(`web_app/screen-tree-live.js`, 시험 `tools/web_app_tree_browser_test.js`).

## 2.1.8 의외의 기업 (2.1 리더보드 아래, 오너 2026-11-06)

2.1.8 의외의 기업
화면 도장은 1.1.9다.

2.1.8.1 의외의 기업 목록
기업명·티커, 하는 일 한 줄, 발견 이유 한 줄, 기존 QGV 점수와 산출 상태를 보인다. 연구상 선정(SELECTED)과 선정 근거 재검토 필요(REVIEW_REQUIRED)만 싣고, 보류·해제·후보·검토 중은 싣지 않는다. 새로운 의외성 점수를 만들지 않는다.

2.1.8.2 섹터·기업 유형·사업 강점 필터
준비된 자료에 있는 값만 고를 수 있다. 결과가 0건이면 그렇게 보이고, 조건을 임의로 풀지 않는다.

2.1.8.3 정렬
최근 선정순(기본), 기업명순, 기존 QGV순으로 정렬한다. QGV가 없는 기업은 선정에서 빼지 않는다. QGV순에서는 그런 기업을 미산출 묶음으로 따로 두고, 0점으로 바꾸지 않는다. 공식 QGV 순위와 목록 안의 표시 순서를 구분한다.

2.1.8.4 기존 기업 상세 연결
기존의 안정적인 기업 식별자로 기존 기업 상세(2.4)로 간다. 티커 문자열만으로 결합하지 않는다.

## 2.4.6 의외의 기업 마크 (2.4 기업 상세 아래, 오너 2026-11-06)

2.4.6 의외의 기업 마크
기존 기업 상세 화면 안이다.

2.4.6.1 의외의 기업 마크
선정 기업의 기업명 옆에 표시한다. 검색·직접 링크로 들어와도 목록과 같은 판독기·같은 상태로 보인다. 선정 해제·보류 기업에는 남지 않는다.

2.4.6.2 선정 이유 펼침
기본은 접힘이다. 클릭·키보드로 펼친다. 순서는 ① 발견 이유, ② 기업 유형, ③ 눈여겨볼 사업 강점, ④ 사업지역과 성장 여력, ⑤ 추가로 주목할 신호, ⑥ 함께 확인할 위험이다. 위험은 첫 펼침 안에서 보인다. "린치 유형"·"8장 특성"은 화면 항목명으로 쓰지 않고, 책 출처는 방법론 설명에서만 안내한다.

2.4.6.3 확인 근거 펼침
⑦ 확인 근거·자료 기준일·마지막 검토일은 요약을 첫 펼침에 보이고, 긴 출처 내역은 한 번 더 펼친다. 확인되지 않은 주장은 사유와 함께 미확인으로 남긴다.

2.4.6.4 재검토 상태 표시
선정 근거 재검토 필요는 마크와 사유로 보인다. 자료가 오래되면 마지막 검토일을 보인다. 기존 기업 개요·QGV·재무·기술·뉴스 구조는 바꾸지 않는다.

## 2.2.7 섹터 QGV 설정(요소·가중치) (2.2 가중치 변화 · 사용자 설정 아래, 오너 2026-11-06)

2.2.7 섹터 QGV 설정(요소·가중치)
투자시스템 공통 10섹터·회계모형별로 Q/G/V 요소를 고른다. 요소 사전에서 찾고(PER·PBR·별칭 검색), 같은 역할 안에서 교체·추가·빼기를 한다. 기본값·추천·선택됨·계산 기능 준비 중·산식 적용 부적합을 글자로 나눠 보인다. 계산은 Codex 공통 엔진이 하고, 화면은 설정만 고친다. 기본 흐름은 "10섹터 기본값 → 내 설정"이다(오너 2026-11-07). 공격형·균형형·수비형은 이전 설정 호환으로만 남는다. 기본 프리셋 ID·버전은 원본 참조로 보존하고, 내 설정은 자기 설정 ID·버전과 적용 범위를 갖는다(#514 저장 계약). "최신 입력에 설정 적용"과 "과거 입력으로 결과 재현"을 나눈다. 새 기본값이 저장된 설정을 자동으로 덮어쓰지 않는다.

## 3.5 기술 조건 리더보드 필터 (화면 도장 1.1.8, 오너 2026-11-03)

3.5 기술 조건 리더보드 필터
기술 조건으로 리더보드 종목을 거른 뒤 기존 QGV 순으로 본다. 평가일과 비교 그룹을 보이고, 분위·분모는 고른 그룹 기준이다. 원래 QGV 순위는 바꾸지 않는다. 화면은 2.1 리더보드 안(1.1.8)에 있지만, 기능 번호는 기술적 분석 영역의 3.5다. 이 번호는 이 파일 전에 정했으므로 바꾸지 않는다.

## 4.5.1.1~4.5.4.1 정책·지정학 (4.5 나비효과 안, 오너 2026-11-07)

정책·지정학은 4.5 나비효과 안에 둔다. 새 메뉴(4.7)는 만들지 않는다. 화면은 매크로 메뉴 3.5 칸이다(메뉴 번호 3.5 = 기능 4.5).

4.5.1.1 정책 사건 목록
관세·수출통제·산업 보조금 같은 정책 사건을 목록으로 보인다. 유형·관할·상태·기업으로 거른다.

4.5.1.2 정책 상세·변경 이력
무엇이 바뀌었는지와 이전 개정을 보인다. 개정 뒤 이전 가설은 "이전 분석 · 재검토 필요"로 둔다.

4.5.2.1 기업 노출과 영향 가설
기업 노출 근거와 정책 적용 범위를 나눠 보인다. 연결 근거가 없으면 "연결 근거 미확인"이고, "영향 없음"으로 쓰지 않는다.

4.5.3.1 근거·반증·후속 확인
반대 조건, 원문·공시·변경 이력, 다음 확인할 것을 보인다. 점수·순위·확률은 만들지 않는다.

4.5.4.1 공통 화면 연결
기업 화면의 "관련 정책" 카드, 5.2 공시·뉴스의 "관련 정책", 4.1 지표 보기로 잇는다.

## 공통 분류 (가로 기준 · 기능 번호 없음, 오너 2026-11-07, DC-48)

새 메뉴나 새 기능 번호가 아니다. 여러 기능(기업 검색·상세, 2.1.3 분류 필터, 2.2.7, 3.5, 4.2·4.3·4.5)이 같은 분류 기록을 읽는 규칙이다. Main 소비 명세는 [COMMON_CLASSIFICATION.md](../../implementation/docs/frontend_v2/COMMON_CLASSIFICATION.md)다. 계산·판정은 Codex `common-classification/1`(#516 `9343b5e6`, 계약·fixture 수령 2026-11-08)이 맡고, 화면은 판독기 `web_app/classification.js`로 읽기만 한다(합성 연결, 실자료 미연결).

- 계층: 투자시스템 공통 10섹터(상위) → 하위 산업 → 기업. 이 10섹터는 책 기반 시스템 분류이며 GICS 11섹터·SIC 업종군·ETF 목록과 같지 않다(구 명칭 "책 10섹터", ID는 그대로 `book-sector-map/1`).
- 원천 SIC는 원천 분류로 따로 보이고, 섹터의 하위 코드로 쓰지 않는다. 투자시스템 공통 10섹터·SIC 10업종군·GICS 11·섹터 ETF는 같은 목록이 아니다.
- 회계모형은 적용 지표·입력 규칙, 태그는 설명·검색·노출(점수 영향 0), 섹터 ETF는 비교 가격계열이다.
- 매크로 4.2는 섹터 단위 상대 위치, 4.3은 산업 단위 사이클이다. 4.3 원문(SIC 기준 산업 선택)과 경로는 그대로 둔다.
- 화면은 SIC·회사명·티커로 분류를 다시 추론하지 않는다. 같은 기업·평가일에는 같은 분류 기록 ID·버전을 읽는다.
- 필터는 점수·순위·분모를 바꾸지 않는다. 원래 N, 지표별 유효 N, 실제 비교집단, 평가일을 보인다.
- 관문 비교집단 변경은 Codex 영향 분석 뒤 별도 모델 변경이다. REIT·통신서비스/미디어·관리의료 경계는 2026-11-08 오너 정책으로 정했다(시스템 적용 정책이며 책의 직접 설명이 아님). 정책 승인만으로 회사별 분류가 확정되지 않으며, 근거가 확인되지 않은 회사는 미확인으로 남는다.
- 세 ID를 따로 보인다: 기업 ID(Universe504 코드), 발행사 ID, 증권 ID(검증된 것이 없으면 "검증된 증권 ID 없음"). 상태 문구는 서로 다르다(확인 / 섹터 확인 · 하위 산업 미확인 / 분류 충돌 · 근거 불일치 / 평가일 …에 적용되는 분류 없음 / 분류 자료 없음 / 섹터 대응 미확인 · 근거 부족 / 분류 버전 불일치). 작은 표본은 기능마다 다르다: 섹터 QGV N<20 → 요소 점수 미산출, 기술 N<10 → 분위 미산출 · 순위·중앙값 유지(구성원·신원 확인 시), 구성원·신원 미확인 → 상대순위·중앙값도 미산출.
