1. 홈 · 기업검색
1.1 기업검색 및 기업 진입
1.1.1 기업 검색
기업명·한국어 기업명·티커로 검색하고 일치하는 기업을 선택한다. 기업명 표시와 계산용 증권 식별자를 구분한다.
1.1.2 기업 통합 진입
검색한 기업의 QGV 상세(2.4)를 중심으로 기술적 분석(3), 관련 매크로(4), 뉴스·관계망(5)에 연결한다. 화면을 이동해도 선택 기업을 유지한다.
1.1.3 검색 전 콘텐츠
전문 투자자의 명언·이야기를 무작위로 제공한다. 인용은 인물과 출처를 표시하고, 확인되지 않은 말을 실제 발언으로 단정하지 않는다.
1.1.4 검색 전 개인화
즐겨찾기 등 입력된 개인 설정을 반영한다. 개인 입력이 없으면 개발자 기본값을 사용하며 기본값임을 구분한다.
2. QGV
2.1 리더보드
2.1.1 평가 대상과 목록
Universe 전체를 기준으로 탐색한다. 기존 TARGET 19개는 별도 목록·필터로 다루며 전체 공식 모집단으로 간주하지 않는다. Universe 밖 TARGET은 따로 표시한다.
2.1.2 순위와 정렬
기존 승인된 공식 정렬 기준과 동점 처리 기준을 연결한다. 현재 정렬 항목·방향·순위 모집단을 명시한다. 평가 모집단, 순위 모집단, 후보 자격, 화면 필터를 서로 구분한다.
2.1.3 분류와 필터
SIC·산업·기업 유형·자료 상태 등으로 탐색한다. 산업 분류와 투자 유형은 독립적인 분류로 취급한다. 필터 후 표시 개수와 전체 순위 기준 개수를 구분한다.
2.1.4 기간별 수익률
1D·5D·20D 등 기간을 선택한다. 데이터가 없으면 미산출 사유를 표시한다. 수익률 정렬은 QGV 공식 순위와 구분한다.
2.1.5 산출 상태별 목록
QGV 종합순위, Q·G 참고 목록, 일부 축만 산출되는 기업, 자료 확인이 필요한 기업을 구분한다. 공식 후보 자격을 충족하지 않는 결과를 공식 QGV 순위에 섞지 않는다.
2.1.6 공식 결과와 개인 결과
공식 가중치 결과와 사용자 설정 결과를 구분한다. 계산 장소·가격 출처와 가중치의 공식 여부도 별도로 표시한다.
2.1.7 후보 선정 연결
N10·N15·N20 후보와 선정·제외 근거를 확인하고 포트폴리오(6.1)로 연결한다. 상위 N개 목록과 비중·자격 조건을 통과한 포트폴리오는 구분한다.
2.2 가중치 변화 · 사용자 설정
2.2.1 축 가중치
Q·G·V의 비중을 변경하고 기본값과 비교한다.
2.2.2 내부 요인 가중치
Q1·Q2 등 각 축 내부 요인의 비중을 변경한다. 기존 축 비중 변경 기능과 구분하여 구현 범위를 확인한다.
2.2.3 프리셋
공격형·균형형·수비형을 제공한다. 구체 비중은 결정된 값만 적용하며, 균형형을 임의로 균등 가중치와 동일시하지 않는다.
2.2.4 변경 영향
변경 전후 점수·순위·후보 구성과 적용 범위를 비교한다. 연구로 검증되지 않은 프리셋을 최적 전략으로 표현하지 않는다.
2.2.5 결측과 적용 비중
원래 가중치, 확보된 요인의 비중, 재배분 후 적용 비중을 구분한다. 결측 처리 방식은 승인된 엔진 규칙을 사용한다.
2.2.6 설정 관리
개인 설정 저장·불러오기·기본값 복원을 제공한다. 개인 변경은 공식 점수·공식 순위를 덮어쓰지 않는다.
2.3 13F 기반 가중치 연구
2.3.1 과거 보유 기록
운용사별 과거 13F 보유와 변화를 확인한다. 분기말·제출일·수집 시각을 구분한다.
2.3.2 가중치 탐색
과거 보유와 유사한 기업을 선정하는 Q·G·V 축 가중치와 Q1·Q2 등 내부 요인 가중치를 탐색한다. 보유 변화 조회만으로 이 기능의 구현이 완료된 것으로 보지 않는다.
2.3.3 백테스트 연결
Lab(9.1)의 공통 연구 엔진으로 시장 대비 결과와 재현성을 비교한다. 보유 유사도와 투자 성과는 별도로 평가한다.
2.3.4 연구와 채택 구분
연구 후보·검증 결과·공식 채택 여부를 표시한다. 연구 결과를 공식 가중치에 자동 반영하지 않는다.
2.4 QGV 상세
2.4.1 기업 설명과 분류
기업이 하는 사업, 산업·SIC, 기업 유형과 판단 근거를 제공한다.
2.4.2 점수와 원지표 상세
Q·G·V → 내부 요인 → 원지표로 내려가며 원값·계산 의미·기준기간·출처를 확인한다. 기존 QGV 항목의 경제적 의미를 유지한다.
2.4.3 자료 상태와 커버리지
정상·부분 산출·미산출·해당 없음·모델 미지원을 구분한다. 확보 요인 수, 원래 가중치 기준 충족률, 누락 사유를 표시한다. 전체 기준과 적용 대상 기준의 분모를 구분한다.
2.4.4 V의 입력 기준
가격 기준 시각·출처·통화·주식수 기준·계산 버전을 표시한다. 공통 게시 결과와 개인 가격 미리보기를 구분한다. 금융업 모델 미지원과 일반기업의 입력 결측을 구분한다.
2.4.5 기업 비교 레이더
Q·G·V를 포함하고 추가 축을 더한 다각형으로 기업을 비교한다. QGV와 별개의 보완 지표만으로 구성된 레이더가 아니다.
2.4.5.1 축 구성
Q·G·V와 추가 축 약 3개를 기본 구상으로 한다. 현재 논의한 추가 축은 가격 안정성·낙폭 방어력·상대 강도다. 실제 확보 가능한 정보와 커버리지에 따라 채택 상태를 명시한다.
2.4.5.2 비교군
기업·산업·SIC·경쟁기업 비교군을 같은 도형에서 비교한다. 비교군 정의·표본 수·기준 시점·척도를 공개하고, 같은 구성원인 비교군은 중복 표시하지 않는다.
2.4.5.3 결측 처리
산출되지 않는 축은 0이나 평균으로 채우지 않는다. 미산출 원인과 실제 축별·공통 커버리지를 표시한다. 도형을 완성하기 위해 계산 기준을 완화하지 않는다.
2.4.5.4 상세 확인
각 축의 원지표·기간·백분위 산정 기준을 확인할 수 있게 한다. 이익률 안정성은 보조 정보 또는 선택 축으로 연결한다. 레이더가 공식 QGV 점수·순위를 바꾸지 않는다.
2.5 QGV 내용구성 트리
2.5.1 구조 탐색
입력 자료 → Q·G·V → 요인 → 원지표 → 점수·순위의 관계를 보여준다.
2.5.2 설명과 예시
각 항목의 의미·산식·조건을 설명하고 아래에 예시 값을 제공한다. 실제 기업 값과 설명용 예시를 구분한다.
2.5.3 상세 연결
트리에서 QGV 상세(2.4), 가중치(2.2), 연구(2.3·9.1)로 연결한다.
3. 기술적 분석
3.1 기술적 지표 · 시나리오
3.1.1 차트 탐색
일봉·주봉, 확대·축소·이동·교차선·구간 측정을 제공한다. 기존 차트·지표 계산을 우선 재사용한다.
3.1.2 지표와 정도 설정
기존 기술적 지표, 고점·저점 구조, 지지·저항을 표시한다. 기간·민감도 등 설정의 의미와 적용 범위를 명시한다.
3.1.3 시나리오
상승·횡보·하락 경로와 주요 가격대·성립 조건·무효화 조건을 작성한다. 장기와 스윙 관점을 지원한다.
3.1.4 결과 구분
공식 감지, 사용자 설정에 따른 탐색, 직접 작성한 시나리오를 구분한다. 사용자 조작은 공식 감지 이력을 바꾸지 않는다.
3.2 차트 패턴 · 시나리오
3.2.1 패턴 탐색
박스권 돌파·이탈, 이중 바닥·천장을 초기 범위로 두고, 재시험·실패 돌파·삼각 수렴 등 후속 후보를 단계적으로 연결한다.
3.2.2 정도 설정
패턴의 관측 기간·민감도 등 허용된 설정을 제공하고 설정값을 결과와 함께 기록한다.
3.2.3 확인·실패·무효화
패턴이 확인 가능한 시점과 실패·무효화 조건을 함께 표시한다. 미래 봉을 사용한 확인을 과거 시점 신호로 소급하지 않는다.
3.2.4 패턴 카드와 시나리오
근거·기준일·조건·시나리오를 연결한다. 형태 적합도와 상승 확률을 혼동하지 않는다.
3.2.5 데이터 적합성
최소 봉 수, 분할 등 기업행사, 가격 기준 연속성을 확인한다. 확인되지 않는 구간은 판정 불가와 사유를 표시한다.
3.3 차트 노트
3.3.1 직접 작성
차트 위에 선·구간·메모를 작성한다.
3.3.2 편집과 저장
수정·삭제·저장·재조회하며 기업·기간·가격 좌표와 연결한다.
3.3.3 분석과 분리
사용자 노트를 시스템 신호와 구분하고 공식 감지·성과 이력을 수정하지 않는다.
3.4 기술적 분석 내용구성 트리
3.4.1 구조 탐색
가격 입력 → 지표 → 구조·패턴 → 시나리오의 연결을 보여준다.
3.4.2 설명과 예시
각 항목의 조건·시점·예시 값을 제공하고 해당 차트 상세로 연결한다.
4. 매크로
4.1 경기·주식시장 국면
4.1.1 국면 그래프
경기와 주식시장의 사이클을 구분하고 현재 예상 위치 또는 예상 구간을 표시한다. 모델이 없으면 위치를 임의로 지정하지 않는다.
4.1.2 국면 탐색
그래프의 국면을 이동하며 설명과 근거를 확인한다. 원형 순환 그래프의 탐색 상태는 데이터 갱신과 구분하여 유지한다.
4.1.3 근거 세로선
운송·금리·고용·제조·주택·신용 등 판단 근거가 되는 사건을 그래프에 연결한다. 독립된 매크로 영역으로 만들지 않는다.
4.1.3.1 근거 시점
관측 대상 시점, 발표 시점, 당시 확인 가능한 시점을 구분한다.
4.1.3.2 근거 설명
어떤 국면 전환을 지지하는지, 선행·동행 여부, 반대 근거와 출처를 확인한다.
4.1.3.3 근거 탐색
일부 근거를 우선 표시하고 전체 목록·세부 설명으로 확장한다. 목록에 등록된 지표와 실제 수집·계산되는 지표를 구분한다.
4.1.4 기존 매크로 연결
기존 경고등과 상태 설명을 통합한다. 공개 지표와 기기 계산 지표를 구분한다. 참고 모드와 실제 투자 제한에 쓰이는 게이트를 혼동하지 않는다.
4.1.5 판단 상태
판단 근거·반대 근거·기준일·미판정 사유를 표시한다. 미검증 규칙은 가설로 표시한다.
4.2 순환매
4.2.1 위치
4.1의 국면 판단과 연결하여 산업·자산의 저점·고점 예상 위치를 보여준다.
4.2.2 조정 조건
상향 조정·유지·하향 조정 조건과 근거를 제공한다.
4.2.3 확률
검증된 산정 근거가 있을 때만 확률을 표시한다. 모델 부재를 임의 수치로 대체하지 않는다.
4.3 SIC 산업 사이클
4.3.1 산업 선택
SIC 기준으로 산업을 선택하고 해당 사이클을 탐색한다.
4.3.2 현재 예상 위치
산업별 근거와 기준일을 사용하여 위치 또는 구간을 표시한다.
4.3.3 조정 조건과 확률
상향·유지·하향 조건, 반대 근거와 확률의 검증 상태를 표시한다.
4.4 사용자 국면 판단
4.4.1 위치 선택
사용자가 현재 예상 위치를 직접 선택한다.
4.4.2 저장과 비교
선택 시점·근거와 함께 저장하고 시스템 판단·이전 사용자 판단과 비교한다.
4.5 연쇄 효과 분석 — 명칭 미정
4.5.1 사건과 파급 경로
날씨·원자재·정책·인수합병 등 사건에서 산업·기업으로 이어지는 관계를 탐색한다.
4.5.2 투자 가설
사건 → 공급·수요·비용·매출 → 이익 → 투자 가설을 연결한다. 브라질 강우와 커피 원가, 동종 기업의 인수합병 가능성 등은 가설 예시이며 확정된 인과관계가 아니다.
4.5.3 근거와 반증
각 연결의 출처·조건·반증 가능성을 표시하고 확인 사실과 추론을 구분한다.
4.5.4 관계망 연결
뉴스·관계망(5.1·5.2)의 기존 연결 기준과 엔진을 재사용한다.
4.6 매크로 내용구성 트리
4.6.1 구조 탐색
자료 → 지표 → 국면 → 산업 → 기업 영향의 관계를 보여준다.
4.6.2 설명과 예시
계산·판단 방식과 예시 값을 제공한다. 미확정 모델과 실제 계산 결과를 구분한다.
5. 뉴스 · 공시 · 관계망
5.1 관계망
5.1.1 기업 중심 관계
검색 기업을 중심으로 기존 관계망의 관계 유형·선정 기준·근거를 유지한다. 기존 기준을 확인하지 않고 새 관계 정의로 대체하지 않는다.
5.1.2 연결 근거
기업·산업·사건 간 연결의 근거와 출처·기준 시점을 확인한다. 내부 식별 용어 대신 사용자에게 의미가 전달되는 설명을 제공한다.
5.1.3 검색 전 추천
매크로에서 관심을 가질 기업 중 무작위로 소개하고 관심 대상으로 선정된 이유를 제공한다.
5.1.4 개인 설정
즐겨찾기 기업·그룹을 지정하고 관계망 탐색에 반영한다.
5.2 공시 · 뉴스
5.2.1 목록과 개인화
검색 기업의 공시·뉴스를 제공한다. 검색값이 없으면 매크로 관심 기업·즐겨찾기와 연결한다.
5.2.2 요약
항목별 5줄 이내 요약과 원문·출처·발표 날짜 및 시각을 제공한다.
5.2.3 영향 분석
Q·G에 대한 예상 영향, 단기·구조적 호재·악재를 구분한다. 예상 영향을 공식 점수 변화로 취급하지 않는다.
5.2.4 주가 반영 여부
판단에 사용할 수 있는 근거와 한계를 제시한다. 확정할 수 없는 반영 여부는 미확인 또는 추정으로 표시한다.
5.2.5 신규·중복·변경
새 기사·반복 보도·내용 변경을 구분하고 관련 기존 항목과 연결한다.
5.2.6 컨센서스 변화
확보 가능한 경우 주요 증권사의 컨센서스 변화 유무와 변경 전후·기준일을 표로 제공한다. 자료 부재와 변화 없음을 구분한다.
5.2.7 수집 상태
새 수집과 이전 항목 보존, 실패와 마지막 성공 시각을 구분한다. 보존된 항목을 새로 수집된 것으로 표시하지 않는다.
5.3 뉴스 내용구성 트리
5.3.1 구조 탐색
자료원 → 사건 → 기업·산업 관계 → 영향 분석의 연결을 보여준다.
5.3.2 설명과 예시
분류·연결 기준과 예시를 제공하고 원문·관계망으로 연결한다.
6. 포트폴리오
6.1 포트폴리오 구성
6.1.1 종류 구분
모델 적합 포트폴리오, 사용자 실제 포트폴리오, 모의 포트폴리오를 구분한다.
6.1.2 모델 후보와 선정
QGV 기준 N10·N15·N20과 선정·제외 사유를 제공한다. 과거 임의 TARGET 19개를 QGV가 선정한 포트폴리오로 표현하지 않는다.
6.1.3 비중과 조건
승인된 종목·산업 한도, 핵심·일반 등급, 중복 발행사 처리, 부족 인원·현금 처리 규칙을 적용하고 근거를 표시한다.
6.1.4 입력과 버전
가중치·계산 버전·모집단·가격 및 재무 기준을 기록한다. 초안과 확정 시점 입력이 달라지면 기존 확정 규칙으로 재검사한다.
6.1.5 개인·모의 구성 관리
실제 보유와 모의 보유를 별도로 입력·조회한다. 모델 결과와 개인 보유를 혼동하지 않는다.
6.2 실제 포트폴리오 일일·주간 보고
6.2.1 보고 내용
보유 현황·성과·위험·주요 변화·관련 뉴스와 공시를 연결한다.
6.2.2 기간 선택
일일 또는 주간 기준으로 보고를 확인하고 기준 기간을 명시한다.
6.2.3 보고 불가 시 프롬프트
부족한 자료와 사유를 표시하고, 필요한 맥락을 포함한 복사용 프롬프트를 제공한다. 프롬프트 라이브러리(7.1)를 재사용한다.
6.2.4 결과 검토
외부에서 받은 답변은 사용자가 검토한 뒤 저장하며 시스템의 검증된 계산 결과와 구분한다.
6.3 모의 포트폴리오 일일·주간 보고
6.3.1 모의 성과
모의 구성과 변경 이력·성과를 실제 투자와 분리해 보여준다.
6.3.2 판단 추적
모델 또는 사용자 판단과 이후 결과를 연결한다.
6.3.3 보고 불가 시 프롬프트
6.2.3과 같은 공통 기능을 사용하되 모의 포트폴리오 맥락을 명시한다.
6.4 포트폴리오 내용구성 트리
6.4.1 구조 탐색
후보 → 자격·비중 → 구성 → 추적 → 보고의 관계를 보여준다.
6.4.2 설명과 예시
규칙과 예시 값을 제공하고 실제·모델·모의 데이터를 구분한다.
7. 프롬프트 라이브러리
7.1 프롬프트 탐색 · 사용 · 개인화
7.1.1 분야별 탐색
기업·QGV·기술적 분석·매크로·뉴스·포트폴리오·연구 목적별로 찾는다.
7.1.2 맥락 반영
현재 기업·화면·보고 기간·확보 정보·부족 정보를 반영한 프롬프트를 제공한다.
7.1.3 복사와 실행 안내
프롬프트를 복사하고 필요한 입력·확인 항목을 알 수 있게 한다. 민감한 개인 정보가 포함되는 경우 복사 전에 내용을 확인할 수 있게 한다.
7.1.4 내 사본
즐겨찾기·수정·저장·기본값 복원을 제공하고 개발자 기본본과 개인 사본을 구분한다.
7.1.5 화면 연결
보고 불가 등 각 화면의 프롬프트 요청은 이 공통 기능으로 연결한다.
8. 투자시스템 전체 내용구성 트리
8.1 전체 구조와 영역 연결
8.1.1 시스템 구조
자료 → 계산 → 판단 → 후보 → 포트폴리오 → 검증의 흐름을 보여준다.
8.1.2 영역 상세
QGV·기술적 분석·매크로·뉴스·포트폴리오의 하위 트리로 연결한다. 동일 내용을 별도 엔진으로 구현하지 않는다.
8.1.3 구현 상태
기존 구현·부분 구현·구현 예정·결정 대기를 구분한다. 개발 완료·병합·게시·실제 확인도 구분한다.
8.1.4 예시와 근거
예시 값과 실제 결과를 구분하고 해당 화면·설명·근거로 이동한다.
9. Lab
9.1 백테스트
9.1.1 연구 목적
현재 QGV 가중치가 투자 결과에 효과가 있는지를 검증한다.
9.1.2 실험 구성
N10·N15·N20, QGV 단독, QGV+기술적 분석 등 사전 등록한 실험을 비교한다.
9.1.3 가중치 연구
축 비중·내부 요인 비중·공격형/균형형/수비형·13F 유사도 기반 후보를 비교한다.
9.1.4 평가 기준
시장 총수익 벤치마크와 비교하고 수익률·낙폭·변동성·회전율·비용·기간별 안정성을 함께 보고한다. 구체 평가식과 가정은 연구 등록부를 따른다.
9.1.5 데이터 조건
당시 모집단·공개 시점·상장폐지·배당·분할·체결 조건을 명시한다. 현재 생존 기업만 쓴 탐색과 정식 과거 검증을 구분한다.
9.1.6 결과 보고
설정·데이터·버전·기간·제약·결과를 재현 가능하게 기록한다. 연구 결과를 공식 운영 규칙으로 자동 승격하지 않는다.
9.2 전진검증
9.2.1 관측 기록
관측 당시 입력·규칙·모집단·커버리지와 결과를 기록한다.
9.2.2 이후 성과
관측 당시 판단과 이후 결과를 연결한다. 과거 기록을 사후 수정하지 않는다.
9.2.3 평가 가능 여부
버전 차이·커버리지 부족 등 평가 제외 사유를 표시한다.
9.2.4 운영 증거
첫 저장·비공개 사본 저장·다음 실행의 사본 읽기·배포 실패 뒤 복구를 별도로 확인한다.
공통 적용 규칙 — 별도 제품 영역을 신설하지 않음
개인화와 기본값
로그인 시 계정 설정, 비로그인 시 해당 기기 설정, 입력이 없으면 개발자 기본값을 사용하는 목표다. 계정 동기화가 구현되지 않았다면 구현된 것으로 표시하지 않는다. 이 규칙은 검색·가중치·즐겨찾기·노트·프롬프트 등 해당 기능에 적용한다.
결과와 데이터의 구분
공식·개인·연구·설명용 예시를 구분한다. 공통 V와 개인 가격 미리보기의 출처를 표시한다. 공개 공통 데이터와 보유·거래·개인 설정을 분리한다.
시각과 상태
자료 기준 시각·수집 시각·검증 및 게시 시각·화면 조회 시각을 구분한다. 정상·부분·미산출·해당 없음·모델 미지원·오래됨·실패는 의미에 맞게 표시한다. 확보하지 못한 수치나 확률을 임의로 채우지 않는다.
화면 간 일관성과 갱신
동일 입력·버전·가격·설정이면 화면마다 같은 결과를 보여준다. 새 자료 반영과 사용자 필터·노트·편집·탐색 상태를 분리한다. 늦게 끝난 옛 계산이 새 결과를 덮어쓰지 않도록 한다.
구현 인수와 범위 관리
각 기능 번호에 대응 코드·입력·재사용 범위·미구현 백엔드·검증을 연결한다. 기존 UI가 있다는 이유로 백엔드까지 구현됐다고 판단하지 않는다. 개발 작업·PR·시험이 새로 생겼다는 이유로 제품의 1단계·2단계 영역을 신설하지 않는다.
