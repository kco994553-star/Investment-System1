## Findings that affect design

1. Canonical already contains the correct model/actual separation and actual-weight calculation in `implementation/src/investment_system/personal/portfolio.py`: immutable `ModelPortfolioSnapshot`; `ActualPortfolioSnapshot` built from `BROKER`/`USER_ENTERED` positions; base-currency requirement; `total_value()` includes positions and cash; `weights()` aggregates the same security across accounts using Decimal. Reuse these domain outputs rather than compute market values/weights in charts, API, or MCP.
2. Canonical `qgv/portfolio.py` constructors explicitly produce reference fixtures. Their `Holding.actual_weight` is a model-side value, not evidence of holdings. `PortfolioEngine.evaluate()` can retain this fallback and uses `actual - target`; Personal `portfolio_gap()` uses `target - actual`. A generic unlabelled `weight_gap` bridge is unsafe. For future gap display consume Personal output with explicit definition, never silently invert or mix paths.
3. PR41 `portfolio_contract.mjs` is display aggregation only. It requires caller-supplied exact safe-integer units and exact equality; all observed-data render calls remain withheld. Production `Decimal` actual weights and float target weights cannot universally be converted to such units without precision/rounding decisions (e.g. one-third). The production wire contract should preserve domain numeric representation and calculation identity; do not create a new rounding/renormalization policy just to satisfy the demo contract. Existing sum tolerances stay producer-owned.
4. Existing Personal schema has position and price observation times, snapshot `as_of`, quality, and source category, but lacks source artifact hashes, per-input `available_at`, and retained FX evidence on `ActualPortfolioSnapshot`. `Money.convert()` has proper FX availability/staleness protection and returns `ConvertedMoney` including original value and FX metadata; projecting only its `.converted` value discards this lineage. A wrapper/producer evidence package is needed without changing Frozen domain classes.
5. Concrete broker ingestion is not present in the inspected canonical/trial `src`: `personal/ports.py:BrokerAdapter` is a read-only Protocol only. Existing tests exercise synthetic inputs. A real user-entered/imported snapshot can eventually satisfy the source boundary, but the old 19 target weights cannot.
6. The identifier boundary is explicit: `personal/security.py` security identity is distinct from company identity. `CompanyLink` is a placeholder defaulting to PROPOSED, never generated by the resolver. Reuse `InMemorySecurityResolver` for supported explicit records, but do not manufacture current or historical security records/company links from ticker strings. `qgv/identifiers.py` preserves unresolved Tokyo Electron/TEL ambiguity.
7. No source-backed temporal industry/type-membership producer was found in targeted source/tests search (`classification_version`, `industry_classification`, `company_types`, `type_membership`, `type_catalog`, classification functions). `contracts/models.py:Identifier` has optional `industry` and `sector` fields only. `qgv/identifiers.py` portfolio sectors are allocation groups (Semicap/AI/BigTech/Other), not a standard industry taxonomy.
8. Trial `product/entity_catalog.py` can use `record.industry or record.sector` for search display. `product/entity_metadata.py` explicitly declares SEARCH_PRESENTATION_ONLY and forbids reuse as Portfolio/PIT input. It is useful for labels, not classification authority. Trial `product/web_mvp.py` supplies a synthetic model Portfolio; frontend currently uses `actual_weight ?? target_weight` and labels a present actual field as actual. Production chart wiring needs an explicit basis, not this fallback; that change is Web-owner work.

## Proposed contract responsibilities (not a frozen schema)

One verified Portfolio product snapshot feeds all three views, the API, and future MCP. Domain computations occur once upstream; one deterministic shared projection/aggregation service groups the returned weights. Renderer/API/MCP must not separately calculate positions, valuation, FX, target weights, industry assignments, or company types.

| Contract part | Required semantics | Existing reusable authority | Gap / dependency |
|---|---|---|---|
| Identity | portfolio id/version, immutable snapshot ref/hash, explicit TARGET or ACTUAL, account scope/completeness for ACTUAL | Personal snapshots, versioning.content_hash | Actual stable persistence ref and retrieval path; reference fixture remains a different data role |
| Holding identity | resolved security_id; reviewed company-link ref only when supplied; label is non-authoritative | SecurityRecord/Identifiers/Resolution; CompanyLink | Production dated security dataset and reviewed link binding; unresolved entries stay visibly unresolved |
| Weight values | pass through producer values plus numeric encoding/scale/calculation version; cash explicitly separate | ModelHolding.target_weight/cash_target; Actual.weights()/total_value() | Lossless serialization/profile across Python/JS; do not import PR41 integer normalization as production numeric policy |
| Denominator | identify base-currency portfolio value or target allocation total; completeness and included accounts | Actual base_currency/complete/account_scope, model cash target | Incomplete actual snapshots cannot be presented as complete portfolio-wide weights; no unknown account total invented |
| Quality | source data kind, sync/row quality, completeness, reason codes; missing distinct from zero | Personal quality enums; Actual.complete; Position.source | Product admission/projector needs explicit current-use vs PIT eligibility, unsupported/unknown/partial handling |
| Time / lineage | snapshot as_of, producer observation times, independently evidenced available_at, acquired/calculated time, source artifacts/hashes, producer version | Position.price_as_of/position_as_of; TimeStamps/usable_at; versioning | Actual/model publication availability evidence and immutable snapshot storage absent from the current chart path |
| FX lineage | base currency plus references to original Money and each used FxRate, its times and quality | Money/FxRate/ConvertedMoney/convert | Preserve evidence outside frozen snapshot object; caller-specified freshness policy, no invented TTL |
| Classification | taxonomy kind/id/version, assignment version, classification subject (security/company), source/evidence ref, effective interval, observed/available time, reason/quality | Existing optional labels only; PR41 classification source/version header | Industry and type assignment need independent provenance, preferably per assignment; do not assume same source/date for all rows |
| Industry composition | supplied industry assignment at chosen taxonomy level; unknown and cash visible | PR41 grouping semantics and renderer | Resolve taxonomy/assignment authority; user allocation-group view remains labelled as such |
| Type composition | explicit catalogue ref; zero-to-many memberships; null=unknown versus []=affirmative no types; common portfolio denominator | PR41 multi-membership aggregator/tests | Verified classification inputs; never infer Growth/Quality etc from name, sector, QGV scores or demo fixtures |
| Overlap | exclusive exact membership-set buckets (not pairwise correlation); each holding appears in one set; unknown/no-types/cash distinct | PR41 exact-set grouping/tests | Shared production grouping and numeric serialization; retaining this view semantics avoids a second calculation path |
| Quarterly history | immutable dated snapshots of both basis and classifications, version-bound; period identifier distinct from available_at | Root Portfolio spec §14; content hashes; time guard utilities | Snapshot repository/history selector, evidence-bound as-known-at filtering, correction lineage; never backfill old snapshots with today's types |

Type exposures may intentionally sum above 100%; never renormalize type totals into a pie claiming mutually exclusive shares. PR41 independent rings and exact-set overlap represent different questions while sharing the same input. Unknown classification does not mean zero exposure. A cash-zero reference snapshot does not impose a permanent cash policy.

## Dependency / wiring order

1. Pin exact producer contracts and classify supported inputs. Preserve TARGET reference fixture and verified producer TARGET/ACTUAL as separate roles. Do not make `qgv_version` mandatory for the three composition charts: include optional bound QGV snapshot/version only if supplied; avoid inventing QGV binding merely to render holdings.
2. Define common evidence/identity/numeric envelopes and data-admission outcomes; map existing domain types into wrappers without changing their calculations. Current source availability and historical PIT eligibility must remain separate claims.
3. Bind dated security identity, actual-source receipts or genuine target-producer snapshots, and classification records. Schema alone is not data ingestion. Missing identity blocks affected production binding; missing classification becomes UNKNOWN with coverage visible; incomplete holdings prevent a complete-portfolio claim.
4. Have a single shared product projection call authoritative domain outputs and group classifications once; API serializes that product result; MCP later exposes the same result/reference with the same auth and validation. No API/MCP-specific weights or classifiers.
5. Connect verified snapshot to the existing Web shell with explicit target/actual selector and no field fallback. Adopt/reuse PR41 renderer semantics only after admission checks are implemented; current demo restrictions are not bypassed.
6. Verify multi-account aggregation, cash, incomplete accounts, missing/empty classification, multi-membership, temporal classification revisions, FX lineage, repeating-decimal weights, and cross-surface contract equality. Existing domain tests remain evidence of domain behavior, not evidence of production ingestion. Then browser/mobile checks against the wired product snapshot.

## Boundaries requiring implementation reporting

- Track B Personal P0 is Frozen: no edits to portfolio/money/security/timecontract semantics or existing regression expectations. Read-only consumption/wrappers are candidates, but integration location must respect owners and current source-hash gates.
- New Python under `src/investment_system` can alter Track C code identity; do not add adapter modules there without reporting/owner coordination.
- Security-to-company identifier reconciliation and unresolved TEL require explicit upstream evidence/ownership; no ticker exceptions.
- Classification source/taxonomy is an unresolved producer dependency, not permission to invent company types.
- Actual account credentials/imports and paid data access remain user boundaries; design can finish without either.
- V/Reverse DCF/MOS/scenario-target semantics are out of P0 composition scope and wait for QGV reconciliation. No V-derived classification or target-weight method is introduced.
- Web-shell wiring, publication admission, and canonical merge remain respective owner/integration actions. This review grants none.
