# QGV SSoT Autonomous Execution Loop v1.0

User-approved execution policy; not a methodology, method-selection or production authorization.

Fresh GitHub → scoped Handoff → Global routing → decisions/approval → exact evidence/CI → owner contract → historical discussion. Reconcile CURRENT/STALE/SUPERSEDED/HISTORICAL/UNVERIFIED/CONFLICTING. Immutable evidence and explicit scoped approval determine their own authority; Global routing cannot approve a QGV method.

Discover finite tasks as READY, WAIT_DEPENDENCY, D3_REQUIRED, DONE, SUPERSEDED or INVALID. Execute READY tasks by shared blocker, critical path, integrity, owner closure, integration, acceptance, bounded implementation, then cleanup. One blocked lane does not block independent READY work.

Execute → risk-proportional verify → approved GitHub API publish → history-preserving scoped Handoff → re-evaluate → next READY task. FAST/STANDARD stop instructions stop that task's verification, not the whole execution loop. CRITICAL financial/semantic/PIT/Official checks remain strict. Reuse exact input/contract/source/dependency evidence and do not relabel old PASS as new-HEAD Actions.

FAIL → classify RETRY/REPAIR/REPLAN/WAIT_DEPENDENCY/D3 → finite correction → retest. Retain initial failure and repair history. Do not retry a failed unchanged fingerprint without a corrective action. Respect the current review CONTROL lease and never steal the Missing-Data owner's active lease. Writes are restricted to this review's lanes and scoped CURRENT_HANDOFF; Global and other owner branches remain read-only.

Owner returns retain SENT → ACKNOWLEDGED → IN_PROGRESS → RETURNED → INDEPENDENTLY_VERIFIED → CONSUMED → CLOSED. Terminal CI must be consumed when relevant; unrelated or already-consumed CI is not new work. Running CI blocks only the dependent lane; record exact run/head/attempt and release the lease while waiting.

WAIT requires zero READY tasks, independent READY lanes, bounded repair, immediately consumable owner returns, immediately consumable CI results and outstanding SSoT closure. Record exact dependency/owner/decision, resume material trigger and next action. No busy polling, duplicate research, self-receipt CI loops or timestamp-only progress.

Material owner/CI/source/blocker/decision/integration/canonical changes resume the execution loop. Existing configured follow-ups are updated; no new watcher or scheduler canary is created. Genuine scheduler HOP1/HOP2 remain separate; manual execution/configuration changes credit zero hops.

G1/G2 approved economic meanings and legacy score/history remain preserved. Actual method, horizon/numerics, G2 replacement, B2/B3/B5/B6 authority/criteria/activation, V1/V2, migration, production, Frozen/PIT/Holdout/Official/canonical changes remain D3 as already recorded. Main performs integration. This audit supplies bounded PASS/FINDING/BLOCKER/D3_REQUIRED returns through scoped evidence.

Measure blockers/gates/owner returns/dependencies/acceptance and remaining D1/D2/D3. Policies, agent counts, commits and repeated tests do not count as product completion. Report a checkpoint only at real WAIT/D3/DONE.
