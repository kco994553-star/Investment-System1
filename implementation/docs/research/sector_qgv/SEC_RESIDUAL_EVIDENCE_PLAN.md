# SEC 잔여 근거의 최소 취득 계획

이 문서는 잔여 입력의 계획이다. 신규 요청 실행·기존 승인 범위 확대·기본 모형
채택·공개 게시·병합·배포 승인이 아니다. 대상 회사·기간·accession·보관 위치와
실측 가용 수는 승인된 비공개 계획표에 둔다. 공개 예시는 합성 자료만 사용한다.

## 원자료 재사용과 중복 제거

우선 기존 제출본·일괄 자료·원문 첨부·보관 XBRL의 manifest/색인을 사용한다.
본문을 같은 이유로 반복 검색하거나, 메타데이터 누락을 곧 원문 부재로 바꾸지 않는다.

- 회사별 companyfacts의 `accn`, `filed`, 기간·단위·원래 취득시각은 관측값 연결에
  재사용한다. companyfacts에 없는 context/정밀도/각주가 원 공시에 없다고 단정하지 않는다.
- companyfacts만 수록한 색인은 전체 보관소의 본문·iXBRL 재고가 아니다.
- 이미 보유한 공시 본문·첨부도 해당 기간과 주장에 맞는지 확인한다. 과거 사례 몇 건이
  현재 금융·주당 표본 전체를 포괄한다고 확대하지 않는다.
- 중복 키는 `(기존 발행사 ID, accession, member, 원본 SHA-256)`이다. 같은 accession도
  다른 첨부는 다른 member이고, 같은 경로의 바이트 변경은 별도 개정/취득 이력이다.
- [#460](https://github.com/kco994553-star/Investment-System1/pull/460)의 bulk·full-index·FSDS
  계획과 기존 취득본을 대조한다. 열린 계획 PR을 실행 완료로 간주하지 않으며, 실제
  잔여 결손만을 위해 같은 bulk를 다시 받는 것을 기본안으로 삼지 않는다.
- 이미 수령한 공시는 새 승인·취득 대기로 되돌리지 않는다. 전달 위치 확인이 필요하면
  `RECEIVED_HANDOFF_LOCATOR_CONFIRMATION_PENDING`으로 구분한다.

## 목적 A: 역사 주당 기준

동일 회계기간의 보고값 일치, EPS×분모의 산술 일관성, 계산 전 기간의 주식 기준은
각각 다른 검사다. 수집은 다음 중 실제로 빠진 주장만 대상으로 한다.

|필요 원문 항목|해소할 단계|자동으로 해소하지 않는 단계|
|---|---|---|
|iXBRL/instance의 contextRef·unitRef·decimals/precision, 기간·단위·연결/종류주 차원|보고 사실의 문맥·반올림 범위|분할 없음, 기간 전체 적격성|
|희석 EPS 각주와 보통주 귀속·희석조정 분자 조정표|EPS 산술·귀속|주당 FCF의 CFO/CAPEX·가격 결합|
|같은 제출본 비교연도·명시적 소급조정·실제 공통연도 연결|계산에 쓰는 연도의 기준 연결|당시 시스템 보유, 다른 종류주·ADR 연속성|
|분할/종류주/ADR 관련 명시적 공시|해당 사건·주식 기준 보정|다른 기간에 추가 사건이 없었다는 주장|

정밀도가 없는 숫자 일치 자체는 기록할 수 있다. 추가 정밀도 근거가 필요한
산술·보정 판단과 분리한다. 차원이 없다는 사실만으로 종류주 귀속 실패라고
결론내리지 않고, 개념 정의·공시 각주와 실제 귀속 근거를 구분한다.
명시적 충돌·확인된 오류는 공식 가정을 재사용하는 연구안에서도 제외한다.

## 목적 B: 금융 회계모형별 입력

[금융555 후보표](FINANCIAL_555_CANDIDATES.md)의 variant별 필수 입력만 요청한다.
은행·생명/손해보험·브로커·자산운용·모기지/지분형 REIT는 별도 대상이다.

- 보통주 귀속 자본·이익은 총자본·연결 순이익으로 바꾸지 않는다.
- 보통주 BPS에는 같은 시점의 적격 주당 기준이 필요하며 불필요한 EV는 요구하지 않는다.
- TTM 희석 EPS는 검증된 기간 구성·귀속·주식 기준이 필요하다. 연간·누적값을 임의
  합산하거나 순이익/현재 주식수로 대체하지 않는다.
- FFO/AFFO는 회사 조정표·Nareit 범위·보통주/OP단위 귀속·유지보수 투자 정의를
  보존한다. 산식 미완결 역할을 수집으로 해결됐다고 하지 않는다.
- 평가일 가격·통화·종류주·기업행사·시총 구성은 금융 원문 확보와 별도 조건이다.

## 작은 표본 실행안

먼저 기존 보유 파일의 재사용·정확한 첨부 위치를 확인한다. 새 취득이 승인되는 경우
초기 표본은 **최대 세 발행사·각 한 제출본**으로 제한한다. 수익률·유리한 점수로
고르지 않고 실제 잔여 필드, 사업모형 차이, 제출본 연결을 기준으로 고정한다.

기존 submissions/보관 색인에서 primary member가 확인되면 해당 파일만 요청한다.
정확한 member가 없을 때만 filing index 한 번과 확인된 primary/iXBRL 한 번을 제안한다.
후속 attachment·추가 연도·추가 회사는 자동 확대하지 않는다.

|제안 상한|정책|
|---|---|
|논리 요청|최대 여섯 GET(index+primary를 각 한 번); 기존 primary 위치가 있으면 그만큼 감소|
|동시성·속도|직렬 한 요청, 시작 간격 최소1초. 기존 SEC 식별 User-Agent와 승인된 요청 예산 재사용|
|index 본문 상한|각1 MiB|
|primary/iXBRL 본문 상한|각16 MiB; 최대 수신51 MiB. 이는 다운로드 차단 상한이며 예상 파일 크기가 아님|
|예상 실제 용량·비용|보관 크기/Content-Length가 없으면 용량 null. 무료 공식 원천이며 유료 계약을 제안하지 않음|
|재시도|이 표본 계획은 실패 뒤 자동 재요청 없음. 403·429·5xx·timeout·해시/형식/크기 문제는 중단·receipt 보존|
|중단|예산 초과, 비공개 목적지 확인 실패, 보관 중복, 원치 않은 형식, 잘린 본문, 쓰기/해시 검증 실패 시 다음 파일로 진행하지 않음|

HEAD나 크기 확인을 위한 별도 요청도 숨기지 않는다. 기존 manifest·보관 크기 또는
승인된 GET의 응답 헤더로 크기를 기록한다. index가 필요한 파일을 가리키지 않거나
primary에 필요한 문맥이 없으면 필요한 attachment를 구체화해 남기고 자동 추가 취득하지 않는다.

## 보존·실패·재개

기존 승인 비공개 인계 위치의 새 append-only 하위 묶음에 원본 바이트와 receipt를 보존한다.
코드·합성 예시만 공개 저장소에 둔다. manifest의 파일 단위 필수 기록은 다음과 같다.

```json
{
  "issuer_id": "SYNTHETIC:ISSUER-A",
  "accession": "SYNTHETIC-FILING-A",
  "member": "synthetic-primary.htm",
  "purpose": ["HISTORICAL_SHARE_BASIS", "COMMON_EQUITY_INPUT"],
  "published_at": null,
  "published_precision": "DATE_ONLY",
  "acquired_at": "2026-11-14T12:00:00Z",
  "reviewed_at": null,
  "sha256": "<actual bytes SHA-256>",
  "bytes": null,
  "collection_outcome": "PLANNED",
  "prior_member_ref": null,
  "resolved_claims": [],
  "unresolved_claims": ["FULL_PERIOD_COMMON_BASIS"]
}
```

발표일만 있는 자료에 임의 시각을 넣지 않는다. 새 취득 시각을 과거로 바꾸지 않고,
현재 보관 자료로 재구성한 결과와 역사 당시 시스템 보유를 구분한다.

완료 파일은 바이트·크기·SHA·재열기를 검증한 뒤 체크포인트에 기록한다. 실패 파일을
변경 없음/자료 없음/정상 빈 결과로 바꾸지 않는다. 재개 시 완료 파일의 해시를 확인해
중복 요청을 건너뛰고, 기존 정상본과 원래 확인 시각을 유지한다. Main의 실행 기반·Secret·
워크플로·공개 게시를 이 자료 계획에서 수정하지 않는다.

## 표본 이후 확대 판단

취득 성공과 계산 채택 성공을 각각 집계한다. 다음 조건을 실제 표본에서 대조한 후에만
추가 범위를 제안한다.

1. 계획한 member에 필요한 문맥·귀속·비교연도 또는 금융 필드가 실제로 존재하는가.
2. 기존 파서·검증기로 원값을 연결할 수 있고 자료형·통화·단위·기간·최신 충돌을 보존하는가.
3. 전기간 주식 기준과 지표별 분모가 연결되며 중복 보정 없이 기존 커널을 재사용하는가.
4. 실제 요청 수·바이트·실패·추출 가능한 주장 수가 계획과 얼마나 다른가.
5. 여전히 남는 산식 적용 한계·정의 미완결·가격·증권·관문·표본 부족을 분리했는가.

회복 가능 원지표 수, 점수화 가능 수, 축·적격 총점은 별도다. 원자료만 확보하면
95%가 된다고 확정하거나, 금융 제외 모집단 상한을 이 계획으로 해소했다고 보고하지 않는다.
