상태: **설계 제안.** 바구니 목록은 오너 승인 뒤 고정한다(`FV3-BASKETS`). 코드·워크플로·가드·공개 파일은 이 PR에서 바꾸지 않는다.

원문(사용자, 2026-10-31): 「전진검증 v3 방침이다(앞 지시를 이것으로 대체한다). 설계 문서 PR을 먼저 올리고, 바구니 목록은 내가 승인한 뒤 고정한다. 1. 기존 v1·v2(TARGET v0)는 v3 시작과 함께 새 기록을 멈추고 기존 기록은 보존한다(a안 승인). 멈춰도 연속 성공 집계·원장 PRIMARY·배포 신선도 검사가 유지되게 필요한 것을 v3로 옮긴다. 2. 시작 시점: 과거 QGV를 구할 수 있는 가장 이른 날부터 한다. (보관본 구간 / 재구성 구간 / calc_version 분리 / 실시간은 오늘 이후) 3. 바구니: QGV 10분위·5분위, 상위 10·20·30종목, Q·G·V 축별 상위·하위 10%, 업종 중립 상위 10%, 대형·중형별 상위 10%, 프리셋(공격·균형·수비)별 상위 10%. 비교 기준: Universe504 동일가중, SPY, 그리고 『월가의 퀀트 투자 바이블』 전략(Codex가 규칙 문서를 낸다). 모두 동일가중으로 하고, 재조정 주기와 종목이 빠질 때의 처리를 정하라. 4. 수익률은 중앙 파이프라인이 IEX로 바구니 단위만 계산해 기록한다. 종목별 가격은 원장에 넣지 않는다. 모멘텀 계산에 필요한 과거 IEX 파일 양과 수집 시간을 추정하라. 5. 원장 크기 한도와 파일 구성, 화면 9.2 표시(누적 수익률, 상위−하위 차이, 기준 대비, "판단에 기간 부족" 표시 기준)를 함께 제안하라. 6. 바이블 전략은 Codex가 낸 규칙 문서가 승인되면 같은 v3 바구니로 넣는다. 그 전에는 자리만 만든다.」

## 2. v1·v2 멈춤과 v3로 옮길 것 (a안)

- **멈춤:** v3 시작일(구현 PR 병합 뒤 첫 완료 세션)부터 `forward_validation_ledger.py`는 v1·v2 기록을 더하지 않는다. 파일은 그날 상태 그대로 공개에 남긴다. 상태 표시만 바꾼다(화면에 "v1·v2: 기록 멈춤 · 보존"). 파일 형식은 바꾸지 않는다.
- **옮길 것:**

| 지금 v1·v2가 하는 일 | v3에서 |
| --- | --- |
| 완료 세션마다 기록 1줄 + 비공개 dated 사본 + 다음 실행이 사본을 먼저 읽음(연속 성공의 근거) | v3 실시간 구간이 완료 세션마다 기록 1줄(그날 바구니 값) + 비공개 `forward-v3-YYYY-MM-DD` 사본 + `RAW_FIRST` 읽기. 연속 성공 집계는 v3 기록으로 센다. 첫 v3 세션부터 다시 센다(옛 3/7은 이력으로 남김) |
| `observation_basis` PRIMARY / PREPARATORY | v3 기록마다 그날 쓴 공식 QGV의 기준: `calc_version`, `publication_id`·sha256, 가격 기준일, Q·G·V 산출 수, 순위 수. **PRIMARY = 그날 유효한 공식 게시본(V 포함)이 있고, 순위 300 이상, calc_version이 구간과 같음.** 아니면 PREPARATORY(사유 코드) |
| 배포 신선도: 원장 추가만 | `pages_freshness_guard`에 v3 파일 규칙을 더한다(라이브 기록이 모두 그대로·순서대로 남아야 함). v1·v2 파일은 **라이브와 바이트가 같아야 함**(멈춘 뒤 바뀌면 거부) |

  - 이 모집단이 준비되기 전에는 재구성 구간을 "재구성 · 생존 편향 있음"으로 표시하고 판정에 쓰지 않는다.

## 4. 바구니 (제안 — 오너 승인 뒤 고정, `FV3-BASKETS`)

공통 규칙:
- 모두 **동일가중**이다.
- 한 발행사는 한 자리만 차지하고, 대표 증권 규칙은 공식 게시본과 같다(S06 원칙).
- 순위 바구니는 공식 순위(V 포함, D11)만 쓴다. Q·G만 있는 행은 넣지 않는다.

| ID | 바구니 | 정의 |
| --- | --- | --- |
| `D01`~`D10` | QGV 10분위 | 그날 공식 순위가 있는 행을 종합 점수로 10등분(동점은 게시본 정렬 규칙) |
| `Q1`~`Q5` | QGV 5분위 | 같은 방식 5등분 |
| `T10`·`T20`·`T30` | 상위 10·20·30종목 | 공식 순위 1~N |
| `AXQ-TOP`·`AXQ-BOT`, `AXG-*`, `AXV-*` | Q·G·V 축별 상위·하위 10% | 축 점수가 있는 행에서 축 점수 상위·하위 10% |
| `SN-TOP` | 업종 중립 상위 10% | 업종 묶음마다 종합 점수 상위 10%(묶음마다 올림 1개 이상)를 모아 동일가중 |
| `SZL-TOP`·`SZM-TOP` | 대형·중형별 상위 10% | 그날 모집단을 발행사 시가총액 중앙값으로 대형·중형으로 나누고 각각 종합 상위 10% |
| `PA-TOP`·`PB-TOP`·`PD-TOP` | 프리셋(공격·균형·수비)별 상위 10% | 게시된 요인 점수로 프리셋 가중치를 다시 계산한 종합 점수 상위 10%(리더보드 프리셋 보기와 같은 계산) |
| `BM-EW` | 비교: Universe504 동일가중 | 그날 모집단 전체(가격 있는 행) |
| `BM-SPY` | 비교: SPY | IEX의 SPY 마지막 체결가(가격 수익률) |
| `BIBLE-*` | 비교: 『월가의 퀀트 투자 바이블』 전략 | **자리만.** Codex 규칙 문서가 승인되면 같은 규칙(동일가중·월 재조정·가격 수익률)으로 채운다. 그 전에는 "규칙 승인 대기" |

**재조정:**
- 주기는 **월 1회**다. 점수 기준은 그달 마지막 거래일의 공식 QGV다(재구성 구간은 그날 다시 계산한 점수).
- 진입은 **다음 거래일 IEX 마지막 체결가**로 한다. 같은 종가로 점수도 매기고 진입도 하면 미리보기 편향이 생겨서다.
- 다음 재조정까지는 보유만 하고 비중을 다시 맞추지 않는다.
- 비용은 넣지 않은 총수익(비용 미반영)이고, 표시에 그 사실을 적는다.

**종목이 빠질 때:**

| 경우 | 처리 |
| --- | --- |
| 표시일에 IEX 체결이 없음 | 직전 5거래일 안의 마지막 체결가를 쓰고 "오래된 가격"으로 센다. 실시간 구간은 매일 값을 가지므로 직전 값을 쓴다. 5거래일보다 오래되면 그 종목은 그 기간 계산에서 빠진다(커버리지에 셈) |
| 상장폐지·인수 | 마지막 체결가로 현금화한 것으로 보고 다음 재조정까지 그 가치를 유지한다(수익률 0을 지어내는 것이 아니라 마지막 가치 유지, 사유 표시) |
| 분할 | 확인된 분할(SEC 주식수 + 가격 정수비 계단, 기존 SPLITS 검토 목록)은 진입가를 조정한다. 확인되지 않은 큰 변동(±40% 이상 + 주식수 사건)은 그 기간 계산에서 뺀다(사유) |
| 커버리지 | 기간마다 "계산에 쓴 종목 / 바구니 종목". 80% 미만이면 그 바구니의 그 기간 수익률은 NA(0으로 채우지 않음) |

## 5. 수익률 계산 — 중앙 파이프라인, 바구니 단위만

- 계산은 공개 저장소의 중앙 파이프라인이 한다. 가격은 메모리에서만 쓰고 IEX HIST를 스트리밍한다(지금 V와 같은 방식).
- 공개 원장에는 바구니 단위 값만 남긴다: 기간 수익률, 누적 지수, 커버리지, 사유 코드. **종목별 가격·진입가·종목별 수익률은 넣지 않는다.**
- 다음 날 계산에 필요한 진입가·보유 목록은 비공개 저장소(`investment-system1-raw`)의 dated release `fv3-state-YYYY-MM-DD`(+sha256)에 둔다. 월말 가격 저장(`iex-v4-monthend`)과 같은 방식이다.
- 수익률은 **가격 수익률(배당 제외)**이다. IEX는 가격만 주므로 SPY도 가격 수익률로 맞춘다. 화면에 "배당 제외"를 적는다.
- 공개 범위: 바구니 단위 수익률은 IEX HIST 약관 판정(GSQ-024·025: 정밀값 공개 허용)과 오너 지시(바구니 단위만 기록)에 따른다. 종목별 가격은 계속 공개하지 않는다.

- 위험:
  - 2017~2019년 IEX 점유율이 낮아 체결이 없는 날이 늘 수 있다(커버리지로 드러냄). 첫 재구성 전에 해마다 표본 1개월씩 측정한다.
  - TOPS 1.5 파서 지원이 필요하다(`FV3-START`).

## 7. 화면 9.2 (새 앱 Lab, 묶음 2)

- **누적 수익률:** 구간(재구성·보관본·실시간)과 calc_version마다 따로 100에서 시작한다. 바구니는 고를 수 있고 기본은 D10·D01·T20·BM-EW·BM-SPY. 구간 경계는 세로선이다.
- **상위−하위 차이:** D10−D01, Q5−Q1, 축별 상위−하위의 누적 차이와 연율화. 월별 차이가 양수인 달의 비율도 보인다.
- **기준 대비:** 각 바구니의 BM-EW·BM-SPY 대비 초과(누적·연율화), 최대 낙폭, 커버리지.
- **"판단에 기간 부족":**
  - 그 구간의 월 관측이 **36개월 미만**이면 연율화·차이 판단 자리에 "판단에 기간 부족(n/36개월)"을 보이고 결론 문구를 쓰지 않는다.
  - 실시간 구간은 재구성과 합치지 않는다.
  - 12개월 미만이면 연율화 숫자도 숨기고 누적만 보인다.
- **표시 규칙:**
  - "재구성 · 생존 편향 있음"은 PIT 모집단 전까지 판정에서 뺀다.
  - "비용 미반영 · 배당 제외 · IEX 마지막 체결가(공식 종가 아님)"를 함께 보인다.
  - 커버리지 80% 미만 기간은 NA와 사유로 보인다.
  - v1·v2는 "기록 멈춤 · 보존" 탭으로 남긴다.
- 2층 표(FUNCTION_STATUS 1-3절) 9.2 공개 칸은 v3 바구니 수익률로 바뀐다(구현 때 고침). 비공개 추가분(KIS 분할 반영 관측일별 D+N 수익률)은 그대로 둔다.
