## 2. 기업행사·가격 기준 연속성 요구

설계 §7.2·§7.3(결정 Q3)이 덮는다. 요약:

- 패턴은 원시 OHLC만 쓴다. 조정 종가를 섞지 않는다.
- 가격을 임의로 보정하지 않는다. 새 조정 방법을 만들지 않는다.
- 연속성을 확인하지 못한 창은 `PRICE_BASIS_CONTINUITY_UNCONFIRMED`로 판정 불가다.
- 창이 분할 효력일을 가로지르면 `CORPORATE_ACTION_IN_WINDOW`로 판정 불가다.
- 배당은 연속성 판정 대상이 아니다.
- 분할 이벤트는 Worker 별도 PR(P1-W)로 받는다. 1단계 의존 작업이다.

현재 상태:

- Worker 응답에 분할·배당 이벤트가 없다(`worker/src/index.js`에 split 필드 없음).
- 그래서 지금 코드로 패턴을 돌리면 **모든 창이 판정 불가**가 되어야 한다. 이것이 맞는 동작이다.
- P1-W는 Worker 배포가 필요하다. Worker 배포는 별도 사용자 승인 대상이다.

## 3. 지원 종목 (보유·TARGET·관심)

설계 §6.1이 덮는다. 현재 사실:

- 보유(`device-actual` 카탈로그), 관심(`watchlist.js`), 차트(`private-history.js`)가 **모두 같은 19종목 신원 목록**에 묶여 있다.
- 그래서 지금은 보유·관심 종목이 TARGET 19를 벗어날 수 없다.
- Worker 허용 목록은 더 넓다: 미국 504 + 벤치마크 ETF 17 + `042700.KS` + `8035.T` + 환율.
- 허용 목록 밖 종목은 `WORKER_ALLOWLIST`로 NA다. 0이나 대체값을 넣지 않는다.
- `042700.KS`의 KRX 대체 출처는 `1mo`만 된다. 주봉 패턴은 NA가 될 수 있다.
- TARGET v1(#248 → #263)이 확정되면 TARGET 목록이 바뀐다. 차트 범위는 그 목록을 따른다.
- 504 전체 확장은 설계 §6.4 측정 보고 뒤에만 한다.

## 4. 요청 큐와 중복 제거

설계 §6.3과 P1-11이 덮는다. 요약:

- 사용자가 차트를 열거나 버튼을 누를 때만 요청한다(결정 Q4).
- 종목당 세션에 `5y` 한 번이 기본이다. 일봉 약 1260봉으로 일봉·주봉을 모두 만든다.
- RAM 캐시 키는 기호다. 받은 범위가 요청 범위를 덮으면 다시 받지 않는다.
- 같은 종목을 두 화면이 요청해도 Worker 요청은 1건이어야 한다.
- 모든 요청은 `price-store.js`의 같은 큐(`exclusive`)를 탄다. 간격 5.2초, `RATE_LIMITED` 재시도 15초·2회.
- 새 봉 갱신은 `1mo`만 받아 날짜로 합친다. 값이 다르면 덮어쓰지 않고 `PRICE_REVISED`를 남긴다.
- Worker 상한: 소유자 1인 분당 12건, 최소 간격 5초, 응답 최대 1500봉·512KB.

## 7. 기존 자산 재사용 범위

설계 §3이 덮는다. 요약:

- **SVG(`technical-chart.js`):** 대체 경로로 남긴다. LWC 기본 전환 뒤에도 유지한다(결정 Q6). 대체 경로에서는 기능 제한을 화면에 쓴다.
- **지표(`chart-indicators.js`):** 그대로 쓴다. ATR14를 패턴 허용오차 단위로 쓴다. 새 ATR을 만들지 않는다.
- **가격 경로(`private-history.js`):** 응답 형식(`private-history/1`)과 `validateHistory`, RAM 전용·`pagehide` 정리를 그대로 쓴다. 허용 목록만 넓힌다(P1-11).
- **큐(`price-store.js`):** `exclusive` 큐·간격·재시도를 공유한다. `Prices_D` 종가는 원시 종가 일치 확인에만 쓴다.
- **카드(`technical-cards.js`):** "구조" 카드의 NA 문구를 패턴 카드로 바꾼다(P1-10). 다른 카드는 그대로.

- **TradingView 위젯:** 재사용하지 않는다. 별개로 유지한다.

## 8. 장기 보유 모드와 스윙 모드

설계 §1.1·§12가 덮는다. 두 모드를 **모두 유지**한다.

- 두 모드는 같은 봉 모델·같은 패턴 엔진·같은 공식 이력을 쓴다. 화면 강조점과 기록 양식만 다르다.
- 장기: 주봉 구조 먼저. QGV와 나란히 표시. 패턴은 QGV·TARGET·플레이북을 바꾸지 않는다.
- 스윙(2단계): 손익비·수량·시나리오 A/B/C. "주문 아님 · 가정 계산" 문구 고정.
- 기록·집계는 모드별, 실시간·리플레이별, 규칙 버전별로 나눈다.

- 카드에 확률·승률·점수를 쓰지 않는다. 투자 유용성은 "미검증"이다.
- TARGET v1과 충돌하면 TARGET v1이 우선한다.

남은 공백:

- **G1. 분할 이벤트 출처 미정.** 설계는 P1-W를 1단계 의존 작업으로 두었다. 하지만 어느 공급자 필드를 쓸지 정하지 않았다. Worker는 Yahoo chart와 Tiingo daily를 읽는다. 지금은 두 곳 모두 이벤트를 요청·전달하지 않는다. 구현 전 정할 것: 출처, 응답 필드 이름, 이벤트가 없을 때와 조회 실패를 구분하는 코드, Worker 응답 크기 영향.
- **G2. 관심·보유 종목 확장 경로 미정.** 보유·관심 목록이 19종목 신원 카탈로그에 묶여 있다(§3). 설계 P1-11은 `PrivateHistory` 허용 목록만 넓힌다. 카탈로그 밖 종목을 관심 목록에 넣는 경로는 작업 분해에 없다. TARGET v1 확정 뒤 카탈로그가 어떻게 바뀌는지에 따라 정한다.
- **G3. 주봉 지표 범위 미정.** 현재 지표는 일봉 전용이다(1500봉 상한). 설계 1단계는 주봉 패턴만 정의하고 주봉 지표(SMA·RSI 등)는 언급하지 않는다. "1단계는 주봉 지표 없음"으로 한 줄 확인이 필요하다.

G1~G3은 착수 조건(§10)과 별개다. 착수 승인 전에 설계 보완 문서로 닫을 수 있다.
