### 3.1 기존 비공개 원자료 저장소(RAW_REPO_READ_TOKEN) 재사용 판단

**판단: 기술적으로는 가능하지만 권장하지 않는다. 새 비공개 저장소를 만든다(`PRIV-REPO`).**

| 근거 | 내용 |
| --- | --- |
| 토큰 경계가 없다 | 원자료 저장소는 공개 저장소 Secrets의 `RAW_REPO_TOKEN`(읽기·쓰기)과 `RAW_REPO_READ_TOKEN`(읽기)이 **저장소 전체**를 읽는다. 두 토큰은 공개 Actions에서 돈다. fine-grained 토큰은 경로·태그 단위로 좁힐 수 없다. KIS 자료를 거기 두면 공개 워크플로의 실수 하나로 공개 로그에 새어 나갈 수 있다 |
| 한 토큰 한 용도 | 중앙 V D2 (a) 결정은 읽는 쪽마다 새 단일 용도 토큰을 쓰기로 했다. Worker가 `RAW_REPO_READ_TOKEN`을 같이 쓰면 그 원칙과 어긋나고, 따로 폐기할 수 없다 |
| 원자료 저장소는 지금 Actions가 없다 | 문서상 README만 있는 Release 저장소다. 워크플로를 새로 넣어야 하는 것은 새 저장소와 같다 |

## 5. 접근 — Cloudflare Access + Worker (대체됨(10/31) → NO_ZT §4)

> **대체됨(10/31 오너 승인 `PRIV-AUTH-GOOGLE`).** 이 절의 Access·`kis-auth` Worker·Access JWT 검증은 쓰지 않는다. 현재 설계: [PRIVATE_AREA_NO_ZT_ACCESS_20261031](PRIVATE_AREA_NO_ZT_ACCESS_20261031.md) 4절.

### 5.1 왜 로그인 전용 Worker를 따로 두나

- Access의 "workers.dev 한 번에 켜기"는 **Worker 전체**를 막는다. 경로(`/auth`만)로 좁힐 수 없다.
- 기존 `private-investment-history` Worker에 켜면 지금의 `/history` 경로, 사전 요청(OPTIONS), 배포 뒤 익명 확인 단계가 모두 막힌다.
- 그래서 로그인만 하는 작은 Worker `kis-auth`를 새로 두고 거기에만 Access를 켠다. 자료는 기존 Worker의 새 경로가 준다. 자료 Worker의 주소는 이미 앱 CSP `connect-src`에 있으므로 **CSP·index.html·가드 해시를 바꾸지 않는다.**

### 5.2 왜 쿠키가 아니라 토큰인가 (아이폰 Safari)

- 앱(`kco994553-star.github.io`)과 Worker(`*.workers.dev`)는 다른 사이트다(둘 다 공개 접미사 목록에 있다).
- iOS Safari는 제3자 쿠키를 예외 없이 막는다. 따라서 앱의 fetch에는 Access 쿠키(`CF_Authorization`)가 실리지 않는다. 기존 앱 모듈도 `credentials: 'omit'`이다.
- 맨 위 화면 이동(로그인 화면으로 갔다가 돌아오기)은 막히지 않는다. 그래서 아래 흐름을 쓴다.

### 5.3 로그인 흐름

1. 앱의 "로그인" 버튼(사용자 클릭) → 무작위 `state`를 메모리에 두고 `https://kis-auth.<계정>.workers.dev/login?state=…`로 화면 이동.
2. Access가 이메일 일회용 코드 화면을 보인다. 허용된 이메일에만 코드가 간다(10분 유효, 1회용).
3. 로그인되면 `kis-auth`가 요청 헤더 `Cf-Access-Jwt-Assertion`을 직접 검증한 뒤(5.4), **코드에 고정한 앱 주소**로 302 이동한다. 토큰과 `state`는 주소의 `#` 뒤 조각에만 담는다. `return_to` 같은 매개변수는 받지 않는다(열린 리다이렉트 방지).
4. 앱은 `state`를 확인하고 `history.replaceState`로 조각을 지운 뒤 토큰을 **메모리에만** 둔다(저장소·쿠키 없음). 새로고침하면 사라지고, Access 세션이 살아 있으면 코드 입력 없이 1~3단계가 바로 지나간다.
5. 비공개 자료 요청은 `Authorization: Bearer <토큰>`으로 자료 Worker의 `/kis/*`에 보낸다.

### 5.4 Worker의 Access JWT 직접 검증

- `alg`는 RS256만 받는다. `kid`로 팀 도메인의 공개키 목록(`https://<팀>.cloudflareaccess.com/cdn-cgi/access/certs`)에서 키를 찾는다.
  - 키 목록은 isolate 메모리에 `kid`별로 둔다. 모르는 `kid`면 한 번 다시 받는다(키는 6주마다 바뀌고, 이전 키는 7일 유효하다).
- 클레임:
  - `aud`에 `kis-auth` 앱의 AUD가 있어야 한다.
  - `iss`는 팀 도메인과 정확히 같아야 한다.
  - `exp`·`nbf`·`iat`를 확인한다(작은 오차만 허용).
  - `type`은 `app`, `sub`는 비어 있지 않아야 한다(서비스 토큰 거부).
  - `email`은 Worker Secret `ALLOWED_EMAIL`(이미 있음)과 같아야 한다.
- WebCrypto(RSASSA-PKCS1-v1_5, SHA-256)로 검증한다. 외부 라이브러리를 쓰지 않아 지금의 단일 모듈 구조를 유지한다.
- 이메일·AUD·팀 도메인은 Worker 설정에만 둔다(이메일은 저장소에 두지 않는다. Pages 가드의 이메일 패턴이 막는다).

## 6. 화면 — 새 앱(web_app)

- 새 모듈 하나(예: `private-kis.js`)를 `loader.js` LOAD_ORDER 끝에 더한다. 담당은 Main(DC-32 담당표).

  - `PRIVATE_LOGIN`: 로그인 화면으로 이동.
  - `PRIVATE_READ`: `/kis/*`만 허용하는 새 목적지 분류.

- 로그인하지 않았을 때:
  - 비공개 칸에만 "로그인 필요"(이미 있는 `AUTH_REQUIRED` 문구)와 로그인 버튼을 보인다.
  - 공개 화면·공개 숫자는 그대로다.
- 자료는 RAM에만 둔다. localStorage·IndexedDB·백업에 넣지 않는다. 토큰도 메모리에만 둔다.
- 가격 요청은 클릭 때만 한다는 규칙과 맞춘다.
  - 기본안: 로그인에서 돌아온 뒤 "비공개 자료 불러오기"를 한 번 더 누른다.
  - 대안: 로그인에서 돌아오면 바로 불러온다(같은 사용자 동작의 연속으로 본다). 이 경우 방향 전환 대장 한 줄이 필요하다. → `PRIV-LOAD`
- 새 앱은 P3 전환 전까지 배포되지 않는다. 비공개 칸도 P3 때 함께 보인다(그 전에는 시험 사이트에서만).

## 18. 설계 원칙 (2026-10-31 오너) — 지금은 1인용, 확장 경계만 잡는다

### 18.1 KIS는 비공개 구역 전체의 기본 공급처

- 비공개 구역의 기본 공급처는 KIS다. 기술적 분석만이 아니라 통합 일봉·거래량·장중 가격, 이후 한국 종목까지 KIS로 받는다.
- V는 중앙 V(IEX) 그대로다(17절). KIS 자료로 공개 점수·순위·TARGET을 바꾸지 않는다.

### 18.2 공급처 어댑터 한 층

- 공급처 연결은 **어댑터** 한 층에 모은다. 화면·계산·Worker는 어댑터가 주는 공통 형식만 읽는다.
- 공통 형식(비공개, 스키마 이름은 `kis-` 접두어 — 보안 검토 B1(10/31)로 옛 `private-` 이름에서 바꿈. 공개 정적 시험과 Pages 가드가 둘 다 잡는다. 다른 공급처 어댑터를 더하면 그때 공급처 접두어를 정하고 가드를 같이 넓힌다):

  | 형식 | 내용 |
  | --- | --- |
  | `kis-bars/1` | 종목·날짜·OHLC·거래량·거래대금·조정 기준(원주가 / 분할 반영)·확인 구간·보류 구간·출처·받은 시각·정정 여부 |
  | `kis-quote/1` | 장중 가격·시각·출처·지연 여부 |
  | `kis-liquidity/1` | 63거래일 거래대금 중앙값·표본 수·기준 통과 여부·사유 |
  | `kis-ohlcv/1` | 원자료 CSV 장부(17.2, 첫 줄 주석으로 표시) |

- 어댑터 계약:
  - `fetch_daily(code, start, end, adjust)` → 원자료 행(공급처 고유 형식은 어댑터 안에서만).
  - `normalize(rows)` → 공통 형식.
  - `provenance()` → 공급처 이름·약관 범위·기준 시각.
- 첫 어댑터는 `kis`다. 다른 유료·무료 API를 더할 때는 어댑터 하나와 등록만 늘린다. 화면·Worker는 바꾸지 않는다.
- 공급처 이름은 공통 형식의 출처 칸에만 남는다. 화면은 그 칸을 그대로 보인다("출처: KIS 통합 일봉 · 기준 YYYY-MM-DD").

### 18.3 공개와 비공개 경계

- 공개 화면·공개 파일은 비공개 공급처 자료에 **절대 의존하지 않는다.** 비공개 자료가 없어도 공개 화면은 완전히 동작해야 한다.
- 비공개 칸은 공개 화면 위에 덧붙는 칸이다. 같은 자리의 공개 표시를 지우지 않는다.
- 로그인하지 않았거나 비공개 자료가 없거나 실패하면 그 칸만 상태를 보이고, 공개 부분은 그대로다.
- 가드(첫 구현 PR):
  - Pages 산출물에 `private-`·`kis-` 스키마 이름, KIS 호스트·TR 번호·KIS Secret 이름이 있으면 빌드가 실패한다.
  - 공개 화면 시험은 비공개 상태 `NOT_READY`에서 돌린다. 공개 화면의 내용·요청이 비공개 기능이 없을 때와 같아야 한다.
  - 정적 시험: 공개 자료 파일·공개 빌드가 비공개 경로(`/kis/*`, `/lab/*`, `/private/*`)를 부르지 않는다.
- 2층 구조의 화면별 표는 `docs/SPEC/FUNCTION_STATUS.md` "공개 + 비공개 2층 구조" 절에 둔다(오너가 승인한 뒤 확정).

## 20. 연구 자료 요청 수집 (2026-10-31 오너, 첫 구현 PR에 넣는다)

- Codex(백테스트 연구)가 KIS 자료가 필요하면 **요청서**를 낸다. 요청서는 비공개 저장소의 **이슈 본문**(JSON 하나)이다(보안 검토 A3, 10/31: 옛 안 "`requests/` 아래 JSON 파일"은 Codex에 Contents 쓰기를 줘야 해서 바꿈. GitHub Free 비공개 저장소에서는 그 쓰기 권한이 곧 KIS 키 접근이다).
  - 형식: `research-request/1`.
  - 칸: 요청 ID, 종목 목록, 기간, 항목(일봉 원주가·수정주가·거래량·거래대금), 빈도(한 번 / 매일), 목적 한 줄.
  - Codex 권한: 비공개 저장소 Contents 읽기 + Issues 쓰기뿐(폰 설정 8단계).
- 비공개 저장소의 Actions(Main이 만든 워크플로 하나, 실행 조건은 `issues: types: [opened]`·`schedule`·`workflow_dispatch`뿐, `push` 없음)가 이슈 본문을 env 변수로 받아(`run:` 안에 `${{ github.event.issue.body }}`를 쓰지 않는다) 요청서를 검사해 KIS 어댑터로 받는다. 결과는 비공개 저장소 `shared/research/<요청 ID>/`에 그 워크플로의 `GITHUB_TOKEN`으로 쓴다.
- 검사는 요청 크기 한도, 허용 항목, 주문·계좌 경로 금지, **호출 수 상한**이다. 공개 로그에는 개수·코드만 남긴다.
- **호출 수(보안 검토 A8, 10/31):**
  - `plan()`이 `estimated_calls` = 종목마다 계열 수 × ceil(구간의 평일 수 ÷ 100)의 합을 돌려준다(평일은 미국 거래일의 상한이라 적게 세지 않는다. 토큰 호출은 빼고 센다). 첫 실행이 **6,000회**(초당 10건이면 약 10분)를 넘는 요청은 `REQUEST_TOO_COSTLY`로 거부한다. 최대 종목 600 × 10년은 이제 거부된다(약 16,000~31,000회).
  - `daily` 요청은 첫 채우기(backfill) 뒤에는 **최신 한 쪽(BYMD = 최근 미국 거래일)만** 받는다(종목 × 계열 회). 첫 채우기가 끝났다는 상태는 비공개 저장소 `shared/research/<요청 ID>/state.json`에 둔다. 요청 워크플로가 채우기를 다 마친 뒤 쓰고, `plan(request, backfill_done=...)`을 부르기 전에 읽는다(검사 모듈은 파일을 읽지 않는다). `once` 요청은 채우기가 끝나면 다시 돌지 않는다(`REQUEST_ALREADY_DONE`).
  - 요청 워크플로(요청 수집 PR)는 월 호출·분 예산을 `status/private-area.json`에 두고, 매일 수집 **뒤에** 돌며, 실행마다 요청 하나만 처리하고, 매일 수집 몫(월 약 330분)에 닿기 전에 `BUDGET_EXHAUSTED`로 멈춘다. 결제 수단이 없어 2,000분을 넘으면 매일 수집까지 막히기 때문이다.
- **Codex에 주는 것(보안 검토 A9, 10/31):** KIS 서면 회신(12절 ⑥) 전까지 원 KIS 계열(가격·거래량 행)은 비공개 저장소 Actions 안에만 둔다. Codex에는 가격이 아닌 **파생 통계**(개수·기간·일치율·백테스트 요약 수치)만 준다. KIS 파생 lab 파일은 `kis-` 스키마를 달아 가드가 잡게 한다.
