## 0. 요약

1. 기존 매크로 엔진·경고등·원자료 축·수집기·재생 도구를 그대로 재사용한다. 새 엔진 코드는 이 문서에 없다.
2. 국면 모델은 세 개로 나눈다. 경기(A), 주식시장(B), 산업 SIC 그룹(C). 서로의 결과를 입력으로 쓰지 않는다.
3. 어휘는 IA-4 고정 어휘를 쓴다. 경기 = 확장·둔화·수축·회복. 시장 = 상승 초기·상승 후기·하락·바닥. 산업 어휘는 IA-4에 없어서 결정 항목으로 둔다(PM-7).
4. 출력은 **추정 구간**이다. 예: "확장 후반~둔화 초입". 받치는 근거와 반대 근거를 계열 단위로 같이 낸다.
5. 근거가 모자라거나, 낡았거나, 엇갈리거나, 수정됐거나, 규칙이 미승인이면 **판정 유보**와 사유를 낸다.
6. 지금 공개 입력만으로 돌릴 수 있는 것은 경기 모델의 일부 계열뿐이다. 그것도 대부분 규칙이 [제안]이라 "v0 · 미검증" 탐색 표시까지만 가능하다(MEV-10).
7. 매크로 참고 모드와 재가동(M-REENABLE) 조건은 바꾸지 않는다. 국면 모델은 게이트·경고등·U3·확대 차단의 입력이 아니다.

## 3. 세 모델의 공통 원칙

1. **분리.** 경기·시장·산업은 따로 판정한다. 한 모델의 출력은 다른 모델의 입력이 아니다(CAT §7-1, #313 8항).
2. **계열 단위로 센다.** 한 사이클·한 방향에서 계열 하나 = 근거 하나. 같은 계열 안에서 방향이 엇갈리면 "엇갈림"으로 두고 어느 쪽에도 세지 않는다. 종합지수(Z)와 기준선(REF)은 세지 않는다(CAT §7-3).
3. **v0는 공식에 들어가지 않는다.** [제안] 규칙 사건은 "v0 · 미검증" 표식으로 탐색 화면에만 쓴다(MEV-10). 공식 판정 층은 승인된 해석과 검증이 있을 때만 값을 낸다.
4. **시각.** 판정 시각은 실행 시각이다. 각 근거의 시각은 조건을 확인할 수 있었던 발표 시각이다. 모르면 "수집 시각 기준"이라고 쓴다(MEV-9, IA-16).
5. **추가만.** 지난 판정은 고치지 않는다. 규칙이 바뀌면 새 버전 열을 쌓는다. 과거 재생 결과는 재구성 층에만 둔다(FDC §4, CAT §9).
6. **구간만.** 고리 위 점 좌표, 각도, 확률, 신뢰도 숫자를 내지 않는다. 자료 신뢰도를 확률로 바꾸지 않는다(IMP b-1).
7. **같은 사건, 다른 사이클.** 금리곡선(E09)처럼 여러 사이클에 걸친 지표는 사이클마다 따로 센다. 사이클끼리 더하지 않는다.

## 4. 출력 객체 (세 모델 공통, 초안)

### 4-1. 국면 고리와 구간

- 고리는 네 국면을 정해진 순서로 잇는다. 순서는 시계 방향이고 끝에서 처음으로 돌아온다.
  - 경기: 회복 → 확장 → 둔화 → 수축 → (회복)
  - 시장: 바닥 → 상승 초기 → 상승 후기 → 하락 → (바닥)
- 각 국면을 "초입"과 "후반" 두 칸으로 나눈다. 고리는 8칸이다. **세분 여부는 초안 · 소유자 결정 필요(PM-1).**
- 칸은 순서만 뜻한다. 칸 길이는 기간이나 확률이 아니다. 화면의 호 길이도 같다.
- **구간** = 고리 위의 연속된 칸 묶음. 시작 칸과 끝 칸으로 적는다. 예: "확장 후반~둔화 초입"(2칸).
- 구간 최대 폭 `W_max`: 후보 3칸. **초안 · 소유자 결정 필요.** 더 넓으면 판정 유보(사유 `INTERVAL_TOO_WIDE`).

### 4-2. 객체 형태

값은 모두 자리 표시다. 실제 판정이 아니다.

```json
{
  "cycle": "economy | market | industry:<industry_group>",
  "model_id": "phase-economy/v0-draft",
  "layer": "EXPLORATORY_V0 | OFFICIAL",
  "status": "ESTIMATED_INTERVAL | ABSTAIN",
  "interval": {"from": {"phase": "확장", "part": "후반"}, "to": {"phase": "둔화", "part": "초입"}, "span": 2},
  "point": null,
  "probability": {"state": "NOT_COMPUTED", "reason": "NO_APPROVED_EVIDENCE_RULE"},
  "supporting": [{"family": "C", "events": ["<event_id>"], "direction": "확장→둔화", "rule_version": "...", "v0": false, "release_at": "...", "release_basis": "SCHEDULE | POSTING | CAPTURE"}],
  "opposing":   [{"family": "PO", "events": ["<event_id>"], "direction": "...", "...": "..."}],
  "mixed":      [{"family": "LD", "events": ["..."]}],
  "missing":    [{"family": "MO", "reason": "SOURCE_NOT_COLLECTED"}],
  "abstain_reasons": [],
  "as_of": "<실행 시각>",
  "oldest_input_release_at": "<가장 오래된 근거 발표 시각>",
  "counts": {"supporting_families": 0, "opposing_families": 0, "v0_only_families": 0},
  "marker": "v0 · 미검증"
}
```

- `point`는 늘 `null`이다. `probability.state`는 승인된 근거 규칙이 생길 때까지 `NOT_COMPUTED`다.
- `status = ABSTAIN`이면 `interval`은 `null`이고 `abstain_reasons`가 비지 않는다.
- 근거는 사건 id로만 가리킨다. 사건 기록 형식은 CAT §9-11(rig `Evidence` 재사용)을 따른다.
- 가격 파생 근거(모델 B)는 기기 RAM 객체에만 있다. 공개 객체에는 들어가지 않는다.

### 4-3. 구간을 정하는 절차 (세 모델 공통, 초안)

1. 계열마다 "현재 유효" 사건을 고른다(CAT §6-3 후보 정의, EVL-1 미결정).
2. 계열마다 가리키는 국면 칸 집합을 정한다(각 모델의 §x-3 표). 한 계열이 여러 칸을 가리킬 수 있다.
3. 받치는 계열 수가 가장 많은 연속 칸 묶음을 후보 구간으로 잡는다.
4. 후보 구간과 반대 방향인 계열을 반대 근거로 적는다.
5. 유보 조건(각 모델 §x-6)을 검사한다. 하나라도 맞으면 유보한다.
6. 바로 전 판정과 비교해 전환 조건(§x-4)을 만족할 때만 구간을 옮긴다. 아니면 이전 구간을 유지하고 "유지"로 적는다.

3단계의 "가장 많은" 동률 처리, 최소 계열 수 `N_min`, 반대 계열 허용 수 `M_max`는 **초안 · 소유자 결정 필요(PM-3).**

### 5-3. 국면별 근거 패턴 (해석 후보 · 미승인)

방향 표기는 CAT §5-1 "국면 해석 후보"를 그대로 옮겼다. **이 해석은 승인되지 않았다(MEV-1).**

| 국면 칸 | 받치는 패턴(계열 · 방향) | 대표 지표 |
|---|---|---|
| 회복 초입 | PO 음→양 전환 [문헌]. LU 개선 시작. HO 증가 전환 | E25·E22 상향, E14 하향 교차, E26 |
| 회복 후반 | PO 양 유지. MO 증가 전환. BK 긴축 종료 | E21, E36 0 하향 |
| 확장 초입 | PO 양 유지. LD 개선. LU 안정 | E16·E17 |
| 확장 후반 | IN 가속. BK 긴축 시작. C 평탄화(역전 전) | E39 가속, E36 0 상향 |
| 둔화 초입 | C 역전 [문헌, 확장→둔화 경고]. HO 감소 전환 | E09, E26 |
| 둔화 후반 | LD 악화. MO 감소 전환. LU 악화 시작 | E16·E17, E21, E14 상향 교차 |
| 수축 초입 | **LU Sahm 발동 [문헌, 확장→수축 전환]**. PO 양→음 | E13, E25·E22 하향 |
| 수축 후반 | PO 음 유지. LE 감소 지속 | E25, E18 |

- Sahm(E13)의 위치는 하나다: 확장→수축 전환(침체 초기 확인). 고점·둔화 신호로 쓰지 않는다(CAT 머리말, #313 8항). 모델에서는 "수축 초입"을 가리키는 동행 확인 근거다.
- E10(역전 해소)은 회복 근거로 쓰지 않는다(CAT §2-B).
- FOMC 사건(E40)은 사실 기록이다. 국면 칸을 가리키지 않는다. 해석 칸은 따로 둔다(CAT §2-H).

### 5-4. 전환 조건 (초안 · 소유자 결정 필요)

공통 형태: **"다음 칸 방향 계열 ≥ `N_t`, 반대 방향 계열 ≤ `M_t`, 조건이 연속 `K_t`회 실행에서 유지."** `N_t`·`M_t`·`K_t`는 정하지 않았다. 후보는 괄호에 적고 모두 **초안 · 소유자 결정 필요**다.

| 전환 | 필요한 근거(후보) | 막는 근거 |
|---|---|---|
| 회복 → 확장 | PO 양 유지 + LD 또는 MO 개선 (후보 `N_t` = 2계열) | LU 악화 지속 |
| 확장 → 둔화 | C 역전 또는 IN 가속 + LD·MO·HO 중 하나 악화 (후보 2계열) | PO·LU 모두 개선 중 |
| 둔화 → 수축 | LU Sahm 발동 **또는** PO 양→음, 그리고 다른 1계열 악화 (후보 2계열) | PO 양 유지 + LU 개선 |
| 수축 → 회복 | PO 음→양 [문헌] + LU 또는 HO 개선 (후보 2계열) | LU 악화 지속 |
| 역방향(예: 둔화 → 확장) | 둔화 근거 계열이 해제되고 확장 근거 ≥ `N_t` | — |

- 국면을 건너뛰는 이동(예: 확장 → 수축)은 허용한다. 구간이 넓어지는 것으로 표현한다. 폭이 `W_max`를 넘으면 유보한다.
- 단일 계열로 국면을 옮기지 않는다. Sahm 발동도 혼자서는 "둔화 후반~수축 초입" 구간까지만 넓힌다(후보).

### 5-5. 반대 증거 (판정을 막거나 약하게 하는 것)

| 반대 증거 | 효과(초안) |
|---|---|
| 후보 구간 반대 방향의 현재 유효 계열 | 반대 계열 수 > `M_max` → 구간을 반대쪽으로 넓힘. 넓힌 뒤 `W_max` 초과 → 유보 |
| 같은 계열 안 엇갈림(예: E16 개선·E17 악화) | 그 계열을 세지 않음. "엇갈림"으로 표시 |
| 속보 기반 근거(E25 속보, E21 속보) | 근거로 세되 "속보 · 수정 가능" 표식. 다음 발표에서 조건이 풀리면 해제 사건(MEV-9 §9-6) |
| 금리 인하 사건만 있음 | 국면을 옮기지 않음. 예방적 인하 가능성 [미확인] |
| 역전 해소(E10) | 회복 근거로 세지 않음 |
| 헤드라인 물가만 있음 | IN 계열을 "자료 없음"으로 둠. 헤드라인으로 대신하지 않음 |
| 발표 공백(예: 2025-10 예산 공백 기간 미발표) | 해당 계열 "자료 지연". 신선도 조건(§5-6)에 따라 유보 |

### 5-6. 판정 유보 조건

하나라도 맞으면 `status = ABSTAIN`이다. 사유 코드는 기존 코드를 먼저 재사용한다.

| 사유 | 조건(초안 · 소유자 결정 필요) | 기존 코드 재사용 |
|---|---|---|
| 근거 부족 | 셀 수 있는 계열 < `K_min`(후보 3) | `MISSING_SOURCE`, `SOURCE_NOT_COLLECTED` |
| 자료 낡음 | 계열 최신 발표가 정해진 주기 2회 밖(주간 2주, 월간 2개월, 분기 2분기, CAT §6-3 후보) | `STALE` 상태 |
| 근거 충돌 | 받치는 계열 수 ≤ 반대 계열 수 | 새 코드 후보 `CONFLICTING_FAMILIES` |
| 구간 과대 | 구간 폭 > `W_max` | 새 코드 후보 `INTERVAL_TOO_WIDE` |
| 수정 직후 | 이번 실행에서 수정 발표로 근거 조건이 해제·성립 → 다음 정기 발표까지 유보(후보) | `CONFLICTING_VINTAGE`, `HISTORICAL_VINTAGE_NOT_PROVEN` |
| 규칙 미승인 | 공식 층: 쓰려는 해석이 승인되지 않음 | `NO_APPROVED_STATE_RULE` |
| v0만 있음 | 공식 층: 받치는 계열이 모두 v0 | `NO_APPROVED_STATE_RULE` + 탐색 층에만 표시 |
| 시각 의문 | 근거 시각이 판정 시각보다 뒤 | `AVAILABLE_AFTER_AS_OF`, `SOURCE_AFTER_AS_OF` |

**지금 상태로 공식 층은 늘 "판정 유보 · 규칙 미승인"이다.** 탐색 층은 PM-2 결정 뒤에만 구간을 낸다.

### 5-7. 지금 가능한 것 / 새 입력·권리가 필요한 것

| 하락 초입 | MT 장기선 하향 교차. CR 급악화. MV 급등 |

- 시장은 경기를 앞설 수 있다(S&P 500은 LEI 구성요소, CAT §2-J). 그래서 "경기 수축 + 시장 상승 초기"는 모순으로 보지 않는다. 경기 구간을 시장 반대 근거로 세지 않는다.

### 6-4. 전환 조건 (초안 · 소유자 결정 필요)

| 전환 | 필요한 근거(후보) | 막는 근거 |
|---|---|---|
| 바닥 → 상승 초기 | MT 상향 교차 + CR 개선 (후보 2계열, `K_t` 후보 월말 2회) | MV 재급등 |
| 상승 초기 → 상승 후기 | ME 증가 비율 하락 또는 C 역전 + MT 유지 | CR 개선 지속 + ME 상승 |
| 상승 후기 → 하락 | MT 하향 교차 + CR 악화 (후보 2계열) | MT 즉시 복귀(후보: 다음 월말) |
| 하락 → 바닥 | MV 하락 전환 + CR 악화 멈춤 | MT 하향 지속 + CR 악화 지속 |

### 6-5. 반대 증거

- MT 교차가 짧게 반복되면(휩쏘) 교차 계열을 "엇갈림"으로 둔다. 반복 횟수 기준은 초안 · 소유자 결정 필요.
- HYG÷IEF는 듀레이션·자금 흐름 영향을 받는다. CR 단독으로 국면을 옮기지 않는다.
- ME(E51)는 공시 후행이다. 전환의 막는 근거로만 쓰고 단독 전환 근거로 쓰지 않는다(후보).

### 6-6. 판정 유보 조건

| 사유 | 조건 | 기존 코드 |
|---|---|---|
| 기기 자료 없음 | 기기에 가격이 로드되지 않음 | `DEVICE_NOT_LOADED`(경고등 사유) |
| 허용 목록 밖 | 필요한 기호가 Worker 허용 목록 밖 | `WORKER_ALLOWLIST_REQUIRED` |
| 이력 부족 | rv 3년 이력 미달, 장기선 창 미달 | 경고등 기존 결측 사유 |
| 공개 층 | 가격 근거를 공개에 쓸 수 없음 | 새 코드 후보 `PUBLIC_PRICE_BOUNDARY` |

## 7. 모델 C — 산업 국면 (SIC 그룹)

### 7-1. 어휘와 단위

- 단위: `industry_group`(`sic_industry_groups/v0`) + 하위 그룹(IA-5 (b) 권장). `manufacturing_industrial_tech`(SIC 2200~3999)는 사이클에 너무 넓다. 하위 그룹(반도체·컴퓨터·의료기기) 없이는 유보한다.
- 어휘: IA-4에 산업 어휘가 없다. 후보는 경기 어휘(확장·둔화·수축·회복)를 그룹 활동에 그대로 쓰는 것이다. **초안 · 소유자 결정 필요(PM-7).**
- 3.2 순환매(저점·고점)는 별도 화면이다. 이 모델의 출력을 순환매 위치로 바꾸지 않는다.

### 7-2. 재사용 근거

| 근거 | 출처 | 상태 |
|---|---|---|
| 그룹 매출 TTM 증가율(중앙값·합계 비율·증가 폭) | SEC 공시, CAT §8 사양(MEV-8 승인) | 원자료 있음(504 companyfacts). 집계 미구현 |
| 영업이익 증가 발행인 비율(E51) | 같음 | 같음 |
| 재고/매출 | `InventoryNet`(커버리지 미확인) | 같음. 서비스 그룹 제외 |
| 설비투자 증가 | `capital_expenditure` | 같음 |
| 그룹별 무료 공식 지표 | CAT §11 표(EIA, Census C30·소매·도매, G.17 업종, M3, QSS, FDIC 등) | 모두 새 수집기 필요 |
| 공통 거시 계열 | E09·E36 등 | 그룹마다 따로 셈 |

- 이름은 늘 "분석 대상 내 표본 집계"다. 산업 전체라고 쓰지 않는다(MEV-8).
- 공시 시차: 분기 끝 40~90일. 잠정 기간(분기 말 + 45일 + 5영업일, Q4는 90일)에는 사건을 만들지 않는다(CAT §8-6).

### 7-3. 국면별 근거 패턴 (해석 후보 · 미승인)

| 국면 칸 | 받치는 패턴 |
|---|---|
| 회복 | 매출 증가율 중앙값 음→양. 재고/매출 하락 뒤 안정. 이익 증가 비율 상승 |
| 확장 | 매출·이익 증가 폭 넓음. 설비투자 증가 |
| 둔화 | 증가율 양이지만 하락. 재고/매출 상승. 이익 증가 비율 하락 |
| 수축 | 중앙값 음. 증가 폭 낮음. 재고 조정 |

초입·후반 구분은 그룹 지표의 방향 지속 횟수로 나눈다(후보). 기준은 초안 · 소유자 결정 필요.

### 7-4. 전환 조건 (초안 · 소유자 결정 필요)

### 7-5. 반대 증거

- 합계 비율과 중앙값 방향이 다르면 "엇갈림"(대형사 한 곳 영향).
- 한 발행인이 쌍 집합 매출의 50% 초과 → "집중", 합계 비율 근거 제외(CAT §8-4 후보).

### 7-6. 판정 유보 조건

| 사유 | 조건(초안) | 코드 |

| 표본 부족 | 쌍 < 8 또는 커버리지 < 60%(CAT §8-4 후보) | 새 코드 후보 `SAMPLE_TOO_SMALL` |

## 8. 화면 초안 (기본안)

정렬 대상: 병렬 작성 중인 상호작용 명세(브랜치 `claude/frontend-interaction-contract`). **2026-10-19 작성 시점에 origin에 그 브랜치가 없었다.** 그래서 지시에 적힌 두 원칙만 맞췄다. 명세가 올라오면 이 절을 그에 맞춘다. 그 파일은 고치지 않았다.

- 원칙 1: 고리는 원형으로 돌아가며 넘긴다(마지막 국면 다음이 첫 국면).
- 원칙 2: 표시점(마커)은 승인된 모델의 출력일 때만 그린다.

### 8-1. 구성 (3.1·3.3 공통)

| 요소 | 내용 |
|---|---|
| 사이클 선택 | 탭 "경기 / 주식시장 / 산업(그룹 선택)". 세 고리를 한 그림에 겹치지 않는다 |
| 국면 고리 | 8칸 고리. 제목 "개념도 · 칸 길이는 기간이 아님" |
| 추정 구간 | 해당 칸들을 형광 호로 칠한다. 호 옆에 글자로 "확장 후반~둔화 초입". 색만으로 구분하지 않는다 |
| 층 표식 | 탐색 층: "추정 구간 · v0 · 미검증". 공식 층: 승인 전에는 "공식 판정 미산출" |
| 점·확률 | 그리지 않는다. 문구 "확률 미산출" 고정 |
| 근거 요약 | "받치는 근거 n계열 · 반대 근거 n계열 · 엇갈림 n · 자료 없음 n". 사건 수가 아니라 계열 수 |
| 근거 목록 | 계열 → 소속 사건. 사건마다 지표명, 방향 화살표, 발표 시각(또는 "수집 시각 기준"), 규칙 버전, v0 표식, 출처 열기 |
| 기준 시각 | 판정 시각과 가장 오래된 근거의 발표 시각을 함께 |
| 판정 유보 | 호를 그리지 않는다. 고리는 회색. "판정 유보" + 사유를 쉬운 말로(예: "근거 계열 2개뿐 · 3개 필요(초안 기준)") + 무엇이 오면 풀리는지 |
| 관측 시간축 | 고리 아래 패널. 실제 날짜 축과 근거 세로선(MEV-9, CAT §6-5). 고리에는 날짜선을 그리지 않는다 |
| 내 선택(3.4) | 사용자가 고른 칸은 보라 펜 표시. 시스템 구간과 따로 저장. 점수에 안 씀. 저장 위치 결정 대기(DRAW-STORE·IA-6) |
| 기존 매크로 | 상태판·경고등·참고 표식(§1-2)은 그대로 위에 둔다. 국면 고리와 섞지 않는다 |

### 8-2. 상호작용

- 좌우로 넘기면 칸 설명 카드가 바뀐다. 수축 다음은 회복, 하락 다음은 바닥으로 돌아간다.
- 넘기기는 **보는 칸만 바꾼다.** 추정 구간을 옮기지 않는다.
- 카드 내용: 그 칸의 근거 패턴(§5-3·6-3·7-3), 들어오고 나가는 전환 조건, 현재 그 칸을 받치거나 반대하는 계열.
- 호를 누르면 근거 목록이 열린다. 유보 문구를 누르면 사유별 필요한 입력이 열린다.

### 8-3. 모바일(390px)

- 고리(위) → 근거 요약 한 줄 → 근거 목록(최근 5 + 더 보기, MEV-2) → 관측 시간축.
- 유효 경고·반대 근거 요약은 최근 5개 밖이어도 늘 보인다(MEV-2).

### 8-4. 시안과의 차이

- S09 시안의 "현재 국면: 신뢰도·확률" 칸은 이 초안에서 "추정 구간 + 근거 계열 수 + 확률 미산출"로 바꾼다. 신뢰도 숫자는 만들지 않는다.
- IA 시안의 위치 점은 쓰지 않는다. 고리 좌표를 손으로 정하지 않는다(FDC §4).

## 9. 검증 계획 (재가동·공식 표시 전)

### 9-1. 범위

- 이 검증은 **국면 모델 공식 층**을 켜기 위한 것이다. M-REENABLE(경고등 게이트)과 별개다.
- 확률은 이 검증의 대상이 아니다. 확률은 IA-3·MEV-10 조건(목표 사건·예측 기간·표본 수·검증 방법)이 정해진 뒤 따로 한다. 근거 방식은 소유자 결정대로 "과거 국면 전환 빈도"이다(UDP 10-18 4항). **지금은 그 조건을 채운 규칙이 없다.**

### 9-2. 시점 기준 재생 (미래 정보 금지)

1. 평가일마다 그날까지 발표된 관측만 쓴다. 발표 시각은 기관 과거 일정·보도자료를 먼저 쓴다. 없으면 재생 도구의 근사(월 = 다음 달 15일, 분기 = 분기 말 + 30일)를 쓰고 "근사"로 표시한다.
2. 당시 발표값이 있으면 그것을 쓴다. 없으면 현재 빈티지를 쓰고 "수정치 기준"이라고 표시한다. 두 결과를 섞지 않는다.
3. FRED/ALFRED를 저장하지 않는다. RTDSM은 약관 확인 뒤에만 쓴다.
4. 재생 결과는 재구성 층에만 둔다. 실시간 기록에 끼워 넣지 않는다.
5. 규칙은 재생 전에 고정하고 버전을 붙인다. 재생을 보고 기준을 고치면 새 버전으로 다시 재생하고 둘 다 보고한다.
6. **Holdout은 쓰지 않는다.** 지정된 Holdout 구간이 없다(BT-10, `forward_ledger.py` `UNCONFIRMED_NOT_USED`). 어떤 구간도 "미사용 검증 구간"이라 부르지 않는다.
7. 문헌 규칙(E09: 1968~2005, E13: 1960년 이후)은 그 기간에 맞춰진 규칙이다. 그 구간 결과는 "규칙 개발 구간 안"이라고 표시한다.

### 9-3. 기준 날짜와의 차이 측정 (경기 모델)

- 기준: NBER 정점·저점(E44). 기준 월과 공표일을 둘 다 저장한다. 근거로 세지 않는다. NBER 약관은 검증 대기다.
- 대응(초안 · 소유자 결정 필요): NBER는 두 상태(확장·수축)다. 확장 = 회복·확장·둔화, 수축 = 수축. 회복 초입 = 저점 뒤 첫 칸 후보.
- 측정 항목(값은 아직 없음):

| 항목 | 정의(초안) |
|---|---|
| 포함률 | NBER 상태가 그 달 추정 구간 안에 드는 달의 비율 |
| 탐지 지연 | NBER 정점(저점) 기준 월부터 구간이 처음 수축(회복)을 포함한 실행까지 개월 수. NBER 공표 지연과 나란히 |
| 오경보 | 구간이 수축을 포함했는데 정해진 창(후보 12개월, 초안) 안에 NBER 수축이 없던 횟수 |
| 유보 비율 | 전체 평가일 중 유보 비율, 사유별 |
| 구간 폭 | 평균 폭. 넓은 구간은 포함률을 쉽게 올리므로 반드시 같이 보고 |
| 뒤집힘 | 구간이 앞뒤로 오간 횟수 |

- 표본 한계: 1960년 이후 NBER 침체는 9번 안팎이다. 국면 전환 빈도를 확률로 쓰기에는 표본이 작다. 보고에 표본 수를 늘 적는다.

### 9-4. 시장·산업 모델

- 시장: 공식 기준 날짜가 없다. 기준 후보(예: 낙폭 기반 하락장 정의)는 가격 계산이라 기기에서만 돈다. 기기 가격 이력은 최대 5년(BACKTEST_DATA_AUDIT §0)이라 순환이 한두 번뿐이다. 결과를 저장소에 어떤 형태로 남길지(개수·지연만 등)는 결정 항목이다(PM-13).
- 산업: 당시 투자 모집단이 없어(`NEEDS_HISTORICAL_UNIVERSE`) 재생이 막혀 있다. 모집단 자료가 생기기 전에는 현재 시점 탐색만 한다.

### 9-5. 소유자 승인에 필요한 증거 묶음

1. 고정된 규칙 버전과 모든 수치 기준(PM-3 결정값).
2. 계열별 입력 출처·권리·발표 시각 근거 종류 표.
3. 재생 기간별 결과(§9-3 항목), 근사·수정치 여부 표시, 규칙 개발 구간 표시.
4. 유보 사례 목록과 사유 분포.
5. 실패 사례(놓친 전환, 오경보) 원인.
6. 실시간 전진 기록(공식 층 끈 상태로 탐색 층만) 일정 기간 결과. 기간은 PM-10.
7. 국면 모델이 게이트·점수에 연결되지 않았다는 확인.

## 11. 하지 않은 것

- 엔진·앱·화면·가드·워크플로·CI 변경. `macro-screen.json` 형식 변경.
- 참고 모드·재가동 조건·경고등 규칙 변경. #262 변경.
- 확률·신뢰도 숫자·고리 좌표 생성. 수치 기준 확정.
- 가격·가격 파생값·지수 수준 기록. 예시 값도 넣지 않았다.
- 상호작용 명세 파일 수정(그 브랜치는 작성 시점에 origin에 없었다).
- 결정 기록(UDP)·대기열·인수인계 수정. PM 항목의 기록 반영은 Main이 한다.
