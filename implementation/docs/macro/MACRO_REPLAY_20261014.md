# 매크로 경고등 5개 과거 재생 보고 (2026-10-14, 대기열 3-2·3-3)

- 이 문서는 보고만 한다. 경고등 규칙, 임계값, 코드 동작은 바꾸지 않았다. 상태는 계속 `v1 · UNCALIBRATED`이다.
- 규칙 원문: `implementation/docs/playbook/PLAYBOOK_V1.md` 13-5, 숫자: `implementation/src/investment_system/macro/macro_lights_v1.json`, 계산: `macro_lights_v1.py`(JS 미러 `macro-lights.js`). 재생은 저장소의 `implementation/tools/macro_lights_replay.py`의 `evaluate()`를 수정 없이 불러서 했다.
- 매크로 게이트는 #239(승인 대기)에서 참고 표시로 바꾸는 중이다. 이 보고는 #239를 바꾸지 않는다.
- 사용한 자료는 매크로 정부 통계(실업률, CPI, 실질 GDP, 국채 10년−3개월 금리차)뿐이다. 주가, ETF 가격, 보유·개인 자료, 비밀값은 쓰지 않았다.

## 1. 요약

1. 2000·2008·2020·2022 네 구간 모두 공개 경고등 3개(고용·물가·곡선)만 쓸 수 있었다(매일 3/5). 시장(SPY)·신용(HYG/IEF)은 가격에서 나오는 값이고 컨테이너에서 받을 수 없어 모든 날이 NA다.
2. 2000년과 2020년은 경고·위기가 하루도 없었다. 2008년은 경고만 66평일(2008-07-15~10-14) 나왔고 리먼 이후에는 정상으로 돌아갔다. 2022년은 위기 152평일·경고 29평일이었고, 위기는 모두 "물가 > 8%" 한 조건에서 나왔다.
3. #239 `replay_findings`의 "위기 31일"은 금요일마다 1번씩 평가한 **31주**다. 일 단위로는 위기 152평일(채권시장 영업일 145일)이다.
4. 지금 실제 공개 상태는 **0/5**다. 마지막 배포의 `macro-screen.json`은 경고등 v1 코드보다 먼저 만들어져 경고등 블록이 없다. 미러 자료로 계산하면 3/5, 정상이다(자료는 2026-06~08까지, 참고용).
5. HYG/IEF 신용 경고등은 공개 파이프라인에 자료가 없다. 기기 Worker로만 읽는데, HYG·IEF를 허용한 Worker 코드(#229)는 아직 배포되지 않았다. 컨테이너에는 Worker 주소와 Google 세션이 없다. 그래서 재생하지 못했고, 아래에는 원인만 적었다.

## 2. 방법

**평가 방식.** 저장소 재생 도구와 같다. 월 자료는 다음 달 15일부터, 분기 GDP는 분기 말 + 30일부터 쓸 수 있다고 본다(발표 지연 근사). 자료는 모두 현재 빈티지(수정치)다. 당시 실제 발표값을 재현하는 PIT 검증은 아니다.

**날짜 단위.** 같은 평가를 세 단위로 셌다.
- 평일: 월~금, 휴일 포함.
- 채권시장 영업일: 재무부 금리가 발표된 날.
- 주: 금요일만. 도구의 기본 주기이고 10-13 보고와 같은 단위다.

**구간.**

| 구간 | 기간 |
|---|---|
| 2000 | 2000-01-01~2002-12-31 |
| 2008 | 2007-07-01~2009-06-30 |
| 2020 | 2020-01-01~12-31 |
| 2022 | 2022-01-01~12-31 |
| 대조 | 2004~2006, 2013~2019 |

**자료와 접근 시도.** 각 경로는 한 번만 시도했다.

| 자료 | 저장소 기존 경로 | 결과 | 사용한 자료 |
|---|---|---|---|
| 실업률 LNS14000000 | BLS API(`api.bls.gov`) POST | 프록시 403 | 공개 GitHub 저장소에 있는 FRED UNRATE CSV 사본. 서로 다른 사본 8개를 대조했다. 2019년 이전은 모두 같았고, 2019년 이후는 계절조정 개정으로 ±0.1%p 차이가 있어 가장 최신 빈티지(2026-06까지)를 썼다. |
| CPI-U NSA CUUR0000SA0 | BLS API | 프록시 403 | `datasets/cpi-us` `cpiai.csv`의 `Index`(10-13 재생과 같은 미러, 2026-08까지) |

- 원자료와 변환 파일은 세션 임시 디렉터리에만 두었다. 저장소에는 넣지 않았다.

## 7. HYG/IEF 신용 경고등 (3-3)

**자료 경로.** 공개 파이프라인에는 없다. 가격 경계 정책상 `macro-screen.json`에 신용 값은 들어가지 않는다.
- 신용 경고등은 기기 RAM에서만 계산한다. `macro-lights.js`가 Worker에서 HYG·IEF를 `1y` 범위로 읽는다.
- Worker 코드에는 HYG·IEF가 허용 목록에 있다(`BENCHMARK_SYMBOLS`, #229 병합 `6717c896`). 하지만 Worker 배포는 하지 않았다(인수인계 기록). 배포된 구 Worker는 HYG를 거부한다. 그래서 신용은 "확인 불가"로 남고 다시 요청하지 않는다(브라우저 테스트로 고정됨).

**규칙대로 계산하면.**
- 두 ETF가 모두 종가를 가진 날만 이어 붙인다.
- 비율 R = HYG ÷ IEF로 놓고, 최신일의 R을 20세션 전의 R로 나눈 값에서 1을 뺀다. 이 값이 −5% 이하이면 켜진다(`credit_light`, 추정 표시).
- 원 종가(배당 미조정)를 쓴다. HYG의 월 분배락이 IEF보다 커서 20세션마다 비율이 0.1~0.2%p쯤 아래로 치우칠 수 있다. 기준 −5%에 비해 작다.
- 신용이 켜지면 시장과 함께 켜졌을 때 위기 조건 `MARKET_AND_CREDIT_LIT`이 된다.

**재생 결과: 하지 못함.** 원인은 다음과 같다.
1. 컨테이너에서 가격 자료에 닿을 저장소 경로가 없다. 저장소에 쓸 수 있는 Worker 주소가 없다(사용자 기기 설정). Worker는 Google ID 토큰과 승인된 출처를 요구한다. 그래서 시도할 수 있는 저장소 경로 자체가 없었고, 요청은 보내지 않았다. 이번 작업 범위도 매크로 통계만으로 제한되어 있다.
2. 기기 경로로도 과거 재생은 되지 않는다. Worker 범위는 최대 `5y`라서 지금(2026-10) 기준 2021-10 이후만 읽을 수 있다. 2022는 가능하지만 2008·2020은 불가능하다.
3. 2000년은 원래 측정할 수 없다. HYG 상장은 2007-04, IEF는 2002-07이다. 2008 구간은 2007-05쯤부터 계산할 수 있다.
4. 저장소 정책상 가격 기반 재생 결과(시장·신용)는 공개 저장소, Pages, Actions 로그에 넣을 수 없다(`macro_lights_replay.py` 머리말). 사용자 기기에서 `--spy/--hyg/--ief` 로컬 CSV로 돌리고 결과는 사용자만 본다.
