  - 후보를 명시해야 한다.
    - `INTEGRATED` → `unified-roa-core/0.1.0`(U1) 또는 `unified-sales-core/0.1.0`(U2).
    - `SECTOR` → `sector-reduced-core/0.1.0`(S1).
  - 화면 대신 기본·최적·채택 후보를 고르지 않는다.
  - 거부 코드: `MODEL_UNKNOWN` / `MODEL_ID_REQUIRED` / `MODEL_ID_UNKNOWN` / `CONFIG_NOT_CANDIDATE` / `MODEL_OP_UNSUPPORTED`(comparisons·comparison).
  - context·view는 Codex `candidate_configs()`·`evidence_catalog()`를 그대로 쓴다. S1의 view는 기존 `preset(sector_config, …)`로 범위별 preset을 보인다.

    - 입력은 Codex 합성 평가·참조 두 개(고정 manifest `65c5e549…`)이고, 하나로 합치지 않는다.
    - 입력 종류: `DUAL_BOTH_VALID`, `DUAL_QG_ONLY`(cases.json QG_ONLY: V 핵심 관측 제거).
  - save는 `save_board`다. replay는 `replay_board(saved, 원래 평가, 원래 참조, 원래 request_id)`다.
    - `qgv-dual-saved/1`만 받는다. 섹터 저장 기록은 `SAVED_SCHEMA_MISMATCH`로 거부하고 바꾸지 않는다.
    - 원래 입력이 없으면 `RETAINED_INPUT_NOT_FOUND`다. 최신 입력으로 「정확 재현」이라고 하지 않는다.
  - 응답은 요청한 `model`·`model_id`를 다시 적는다. 엔진 결과의 `model_id`·설정 해시가 다르면 `MODEL_RESPONSE_MISMATCH`다.
  - 모델 필드가 없는 기존 섹터 요청은 그대로다.
- **결과 종류**: 보관 결과 읽기(§3), 합성 실제 재계산(`kind: SYNTHETIC_RECALCULATION`), 정확 재현(`EXACT_REPLAY`)을 나눠 적는다.
  - 합성 U1·U2·S1 재계산 결과 해시 = Codex 합성 전달본의 `result_hash`.
  - 실자료 실제 재계산은 이 경로에 없다(합성만, 배포 안 됨).
- **화면 연구 버튼 (2.2.7, `screen-dual-engine-live.js`, 080e38a5)**: 1.2 섹터 QGV 설정 아래 별도 칸이다. 섹터 QGV 저장 설정은 읽지도 바꾸지도 않는다.

  - V·총점이 null이어도 Q/G를 보이고, 총점이 없으면 「총점 없음 · 순위 없음」이다.
  - 계산 = preview + 같은 결과의 save 기록(RAM). 저장 = 그 기록을 이 기기의 별도 키(`investment.web.v2.dual-qgv-saved`)에 씀. 취소 = 저장 안 한 결과를 버림. 복원 = 엔진에 정확 재현(replay)을 요청하고, 원래 입력이 없으면 `RETAINED_INPUT_NOT_FOUND`로 멈춘다(최신 입력 재계산은 계산 버튼).
  - 공개 사이트에는 엔진 경로가 없다(`ENGINE_NOT_CONNECTED`).

## 2. 리더보드 모형 구분 (`qgv-models.js`, IS2.qgvModels)

- 2.1.1 「QGV 모형」 줄: **공식 QGV / 통합 연구 U1 / 통합 연구 U2 / 섹터 연구 S1**.
  - U1과 U2는 서로 다른 통합 후보다. S1은 섹터 후보(핵심 요소 축소)다.
- 공식은 언제나 고를 수 있다.
- 연구 후보는 검증한 운영504 전달본이 RAM에 있고 그 모형이 들어 있으면 고를 수 있다(`READY`). 없으면 「비공개 연구 결과 읽기 전」이다.
- V·총점이 없다는 이유로 모형 전체를 「계산 연결 전」에 두지 않는다. Q·G·개별 요소·결손 사유는 조회한다. 총점이 null이면 총점 순위가 없다.
- 연구 모형을 고르면 그 모형의 보관 결과판을 보인다.
  - 생산자 행 순서 그대로이고, 점수로 다시 정렬하지 않는다.
  - 순위 범위: S1은 섹터×회계모형 안, U1/U2는 평가 집단 안.
  - 함께 보이는 것: 단계별 수, 95% 줄, 「화면 재계산 연결 안 됨」.
  - 공식 표는 연구 이름 아래 보이지 않는다. 공식을 다시 고르면 공식 표가 그대로 돌아온다.
- 규칙:
  - 모형마다 척도가 다르다. 평균·합산·차이를 만들지 않는다.
  - 섹터 순위를 이어 붙이지 않는다.
  - 필터는 원값을 바꾸지 않는다.
  - 공식 QGV·포트폴리오 목표에 반영하지 않는다.
  - 2.1.1에 TARGET 낱말을 쓰지 않는다(DC-24).

## 3. 두 모형 연구 결과 판독 (`dual-qgv.js`, IS2.dualQgv)

- **계약**: Codex `dual_qgv.delivery_artifacts` → `qgv-dual-delivery/1`.
  - 범위마다 `manifest.json`(`qgv-dual-delivery-manifest/1`), `summary.json`, `index.json`, `detail-NNN.json`.
- **바이트**: 요약·색인·상세는 각 파일의 바이트를 manifest의 크기·SHA-256과 대조한다. 다시 직렬화한 값이 아니라 받은 바이트로 대조한다.
- **신뢰 고리**: 지금 받은 확장 묶음의 커버리지 범위와 맞아야 받는다.
  - 운영504는 `operating` 범위, 보유1057은 `held_financial_subsample` 범위다.
  - 모집단 ID·판·구성원 해시·코드 행 분모와 평가일이 같아야 한다.
  - 입력 해시: 운영504는 평가 입력, 보유1057은 참조 원천 입력이 그 범위의 입력과 같아야 한다(§7 질의 1).
- **검사**:
  - 키는 정확히 일치해야 한다. PRIVATE_RESEARCH · NOT_ADOPTED · NOT_MEASURED여야 한다.
  - 모형 ID: U1 `unified-roa-core/0.1.0`, U2 `unified-sales-core/0.1.0`, S1 `sector-reduced-core/0.1.0`.
  - bindings: 평가 = 평가 모집단, 참조 = 후보 집단, model_hash = 설정 해시.
  - 참조집단은 같은 평가일·마감시각이어야 한다.
  - 커버리지:
    - 분모 = 평가 모집단.
    - 95% 부족분 = max(0, 목표 − 단계).
    - 원인은 겹칠 수 있다고 표시되어야 한다.
    - 전체시장 칸은 null이어야 한다.
  - 색인:
    - 행 수 = 코드 행. 중복이 없어야 한다.
    - 총점 없음 → 순위 없음. 관문 UNKNOWN → 총점 없음.
    - 순위 범위: S1은 `SECTOR|…`, U1/U2는 `COMMON`.
    - 단계별 수 = 전달된 행 수(코드 행·발행사).
  - 상세:
    - 그 파일의 행이 색인 순서·머리 값과 같아야 한다.
    - `raw_value`가 없어야 한다.
    - CORE ⇔ selected_variants.
    - 점수 없음 → 요소 순위·십분위 없음.
- **RAM**: 판독기가 검사한 전달본만 담는다. 분류 묶음이 접히거나 연결이 끊기면 같이 버린다. 저장하지 않는다.

### 7-4. 요소 10분위 표시 (오너 2026-11-12 「QGV 요소의 상위 퍼센트는 10분위」)

- **지금 생산자 규칙** (`research/dual_qgv.py` `_rank_factors`, 읽기만 함):
  - 비교집단은 각 행의 `ranking_scope`다. U1·U2는 `COMMON`(통합), S1은 `SECTOR|섹터|템플릿`이다. 섹터 분위를 합친 통합 분위는 없다.
