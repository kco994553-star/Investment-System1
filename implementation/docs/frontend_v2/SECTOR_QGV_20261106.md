## 2. 화면 동작

- **모델 셋은 섞지 않는다.**

| 모델 | 뜻 | 편집 |
| --- | --- | --- |
| 공식 QGV | 1.1 리더보드의 게시본 | 이 화면은 바꾸지 않음 |
| 연구 프리셋 `sector-qgv-default/0.1.0` | 기본값 · 초기 설정 | 읽기만 |
| 내 QGV | 기본 프리셋 + 내 변경 | 편집 |

  - 다른 모델의 총점을 한 순위에 넣지 않는다.
  - 1.1 표와 그 필터는 이 화면 때문에 순위를 다시 만들지 않는다.
- **편집 순서:**
  1. 섹터(책 10섹터)·회계모형을 고른다.
  2. Q/G/V 비중(%, 내부는 basis point)을 정한다.
  3. 축 탭에서 역할별 요소를 본다: 역할 안 비중, 총점 실효비중, 배지, 산식·출처·추천 이유 펼침.
  4. 요소를 바꾼다. **요소 교체**는 같은 역할의 대안만 보인다. **전체 후보 검색**은 PER·PBR 같은 익숙한 이름으로 찾는다. 빼기도 된다.
  5. 고급 모드에서는 역할·요소 비중도 바꿀 수 있다.
  6. 결과 미리보기 → 내 설정으로 저장 / 변경 취소(마지막 저장 상태) / 기본값 복원(이 섹터·회계모형만 기본 프리셋으로).
- **배지(색만이 아니라 글자로)**

| 배지 | 뜻 | 선택 |
| --- | --- | --- |
| 기본값 · 초기 설정 | 기본 프리셋에 있는 요소 | |
| 추천 | 이유·근거 종류·출처·검토일과 함께 | |
| ✓ 선택됨 | 지금 편집 중인 구성에 있음 | |
| 계산 기능 준비 중 | 계산기가 아직 없음 | 선택 불가 |
| 산식 적용 부적합 | 이 회계모형에 맞지 않는 산식 | 선택 불가 |
| 자료 일부 부족 n/N | 계산기는 있으나 점수 없는 기업이 있음 | 선택 가능 |

  - 추천하지 않은 요소도 계산 기능이 있으면 고를 수 있다.
- **역할 예산:** 같은 역할에 요소를 더하면 역할 비중을 나눠 갖는다(예: 40% 역할에 둘 → 20% + 20%). 새 역할은 0%로 시작하고, 역할 예산을 저절로 늘리지 않는다.
- **적용 범위:**
  - 기본은 "현재 섹터·회계모형만"이다.
  - "전체 섹터에 적용"은 모든 대상에 명시적으로 복사하고, 맞지 않는 곳은 미리보기에 "제외"로 적는다.
  - 은행 변경은 보험·자산운용·REIT로 번지지 않는다.
- **미리보기:** 같은 기준일·같은 원래 모집단 전체를 계산한다. 보이는 것:
  - 전·후 총점 산출 수 / 원래 모집단(비율)
  - 축별 산출 수, 둘 다 산출된 기업 수
  - 미산출 사유별 수
  - 이 섹터·회계모형의 실효비중
  - 기업별 Q·G·V·총점 전 → 후, 순위 전 → 후, 공통 순위 전 → 후
  - 모델·설정 해시·기준일·모집단 버전
  - 미산출은 0이 아니라 "미산출 · 사유"로 보인다.
- **저장:**
  - 가장 최근에 성공한 미리보기와 **같은 키**일 때만 할 수 있다. 키는 snapshot·universe·engine·normalization·mapping·preset 버전 + 설정 해시다.
  - 설정을 바꾸면 이전 미리보기는 숨기고 다시 계산하게 한다.
  - 늦게 온 이전 요청의 답은 버린다.
- **저장 위치:**
  - 이 기기(브라우저)뿐이다. 키는 `investment.web.v2.sector-qgv-user-config`이고 계정 동기화가 없으며 백업 파일에도 넣지 않는다. 화면에 그렇게 적는다.
  - 저장한 설정은 만든 기준 버전을 기억한다. 새 기본값 버전이 나와도 덮어쓰지 않고 "기준 버전 다름"을 알린다. 새 기본값으로 다시 시작하는 것은 사용자가 누를 때만 한다.

## 3. 계산 실행 위치 (Codex에 합의 요청)

- **제안:** 요소 점수(비교집단 안 백분위)는 Codex가 만들고, 공개해도 되는 범위에서만 묶음 파일로 낸다. 화면은 그 위에서 설계서 §7.3의 합산만 한다.
  - 역할 = Σ 요소점수 × 요소 bp / 10000
  - 축 = Σ 역할 × 역할 bp / 10000
  - 총점 = Σ 축 × 축 bp / 10000
- **엄격 결측(§8):** 축·역할·요소 비중의 곱이 0보다 큰 필수요소에 점수가 하나라도 없으면 그 축이 미산출이고, 활성 축이 하나라도 미산출이면 총점·순위도 없다.
  - 0점 채움·중립값·대체 요소는 쓰지 않는다.
  - 비중 0인 축·역할·요소는 필수가 아니다. 그 축은 "제외(사용자)"로 보인다.
- **이 위치를 제안하는 이유:**
  - 요소 점수의 비교집단은 섹터·회계모형으로 미리 정해져 있어(§7.3) 사용자 설정과 상관없다. 그래서 설정이 바뀌어도 다시 계산할 것은 합산뿐이다.
  - 기존 `qgv.js` 미리보기도 게시된 요인 점수를 브라우저에서 다시 묶는다(기존 실행 구조 재사용).
  - 새 서버가 필요 없다.
- **화면이 하지 않는 것:** PER·PBR 같은 요소 산식, 정규화, 비교집단 판정. 묶음에 없는 값은 만들지 않는다.
  - 합산은 `IS2.sectorQgv.preview()`(Promise) 하나로만 부른다. 나중에 Codex 실행기나 Worker로 바꿀 수 있다.
- **함께 합의할 것:**
  - Codex가 Python 기준 구현과 합산 벡터를 주면 화면 합산을 그 벡터로 고정한다.
  - 비공개 입력·결과는 공개 묶음에 넣지 않는다. 비공개 묶음은 1인 비공개 구역 경로를 쓴다.

## 4. `sector-qgv-bundle/1` (Main 제안)

| 필드 | 뜻 |
| --- | --- |
| `schema`, `data_kind` (`SYNTHETIC`/`RESEARCH`) | |
| `snapshot` | `snapshot_id`, `as_of`, `universe_id`, `universe_version`, `engine_version`, `normalization_version`, `mapping_version` |
| `sectors[]`, `templates[]`, `roles[]` | 책 10섹터, 회계모형(일반·은행·보험·증권·Mortgage REIT·순수 자산운용·Equity REIT), 축별 역할 이름 |
| `factors[]` | FactorDefinition: `factor_id, axis, role, display_name, aliases, variant_id, formula_version, unit, direction, period, overlap_group, applicable_templates, calculator_status(READY/PENDING), explain` |
| `recommendations[]` | `factor_id, sector_id|null, template_id|null, reason, evidence_level(BOOK_SECTOR/QUANT_RESEARCH/ACCOUNTING_FIT/SELF_VALIDATED), source_refs, reviewed_at` |
| `presets[]` | SectorPreset: `preset_set, version, state(draft/released), validation_state(initial/validated), sector_id, template_id, axis_weights, roles{Q,G,V:[{role, weight_bp, factors:[{factor_id, weight_bp}]}]}, missing_policy(STRICT), gate_policy(NONE)` |
| `companies[]` | `company_id, universe_code|null, sector_id, template_id, mapping_status(MAPPED/MAPPING_UNRESOLVED), lynch_tags` (설명·검색만, 점수 영향 0) |
| `scores` | `{factor_id: {company_id: {score 0–100 | null, status}}}` — 모든 READY 요소 × 모든 기업. 상태는 `VALID`·`VALID_NEGATIVE`(점수 있음) 또는 설계서 §8의 결손 상태(점수 null) |

- **비중:** 정수 bp로 둔다. 축 합 10000, 활성 축의 역할 합 10000, 활성 역할의 요소 합 10000. 음수·소수·전부 0은 거부한다.
- **거부 범위:** 위반은 첫 위반에서 묶음 전체를 거부한다.
  - 거부 코드: `AXIS_SUM`·`ROLE_SUM`·`FACTOR_SUM`·`BP_INVALID`·`MATRIX_INCOMPLETE`·`SCORE_WITH_MISSING`·`FACTOR_PENDING`·`NOT_APPLICABLE`·`PRESET_VERSION_MIXED` 등.
- **gate_policy:** 지금은 `NONE`만 받는다. 공식 value-trap 관문을 인수할 정책 형식은 합의 대상이다.
- **사용자 설정 `sector-qgv-user-config/1`:** `{schema, preset_set, version, overrides:{"SECTOR|TEMPLATE": tree}}`. override 키는 (섹터, 회계모형)이고, 나머지는 기본 프리셋을 그대로 쓴다.
