## 0. 사용자 결정 (2026-10-23)

- 시안: 손그림 칠판 아티팩트(https://claude.ai/artifact/44Gm4mhXzXUDTm7svbAvGs, PC 9장 + 모바일 9장)를 화면의 기준으로 삼는다.

- 범위: **브라우저 쪽 코드 전부 새로 작성**한다. 화면, 화면이 쓰는 계산·연결 모듈이 모두 해당한다.
- 시안에 자리가 없는 기존 기능은 **세부 화면으로 옮긴다**. 대상은 재무 상세, SEC 표지 정보, 플레이북 기록, 설정·구글 시트 연결, 가상매매, TARGET 빌더 등이다. 첫 화면은 시안처럼 짧게 둔다. 자세한 내용은 시안의 "→ 근거·자세히" 링크, "전체 메뉴", "n. 구조 트리" 아래에 둔다.
- 전환 방식: **한 번에 전환**한다.
  - 새 프론트엔드를 메뉴 0~n+1과 모바일까지 만든다.
  - 경계 시험을 옮겨 통과시킨 뒤 한 번에 배포한다.
  - 그때 옛 화면을 지운다.
  - 그때까지 실사이트는 지금 모습 그대로다.
- PR #378·#382(옛 기술 화면)는 병합하지 않는다. 노트 도구·차트 배치 로직은 새 기술 화면에서 가져다 쓴다. #384(tar 상한)는 그대로 병합한다.

## 1. 범위 해석

- "전부"는 **브라우저 코드**다. 다음은 프론트엔드가 아니므로 유지한다.
  - 공개 자료를 만드는 Python 파이프라인(`sec-qgv2.json` 등)과 정기 실행 워크플로
  - Cloudflare Worker
  - 비공개 원자료 저장소
- 계산 모듈을 새로 써도 **방법론은 바뀌지 않는다.** 새 모듈은 기존 참조 벡터(`implementation/tests/fixtures/*`, JS==Python)를 그대로 통과해야 한다. 가중치·TARGET·임계값을 임의로 바꾸지 않는다.
- 시안의 숫자는 모두 예시다. 새 화면은 **실제 공개 자료나 기기 RAM 값, 또는 NA와 사유**만 보여 준다. 예시 숫자를 화면에 두지 않는다.

## 2. 유지할 경계 (전환 PR의 통과 조건)

1. 가격·가격 파생값·보유·거래·시트 ID·토큰·환율 값은 공개 저장소·Pages·Actions 로그에 넣지 않는다. 기기에서는 RAM과 사용자 개인 시트에만 둔다.
2. NA는 0으로 채우지 않는다. NA에는 사유 코드가 있고, 화면에서 사유를 볼 수 있다("→ 근거").
3. 가격 요청은 사용자가 버튼을 누를 때만 한다(클릭 요청 원칙). Worker 허용 목록·호출 간격은 그대로다.
4. 외부 원본은 CSP로 막는다(`default-src 'self'`, 구글 로그인·시트·Worker만 허용). 글꼴은 자체 호스팅 OFL 부분집합이다.
5. Pages 가드(파일당 2 MiB, 192개, 파일별 sha256 고정)는 완화하지 않는다. 전환 PR에서 새 파일 목록으로 고정값을 바꾼다.
6. 매수·매도·주문·이체 기능과 지시 문구는 두지 않는다.

## 3. 구조

- 새 코드 위치: `implementation/src/investment_system/product/web_app/`. 전환 전까지는 배포되지 않는다. Pages는 한 층이므로 파일도 한 층에 둔다.
  - `index.html`: 셸. CSP는 기존과 같다. 인라인 스크립트·스타일은 없다(스타일은 CSSOM으로만 설정).
  - `app.css`: 시안 디자인 토큰·부품(`.sk` 손그림 테두리, `.stamp` 도장, `.chip`, `.hand`, `.hl` 형광펜, `.bar`, `.tbl`, `.node`·`.branch`, 탭바).
  - `core.js`: DOM 도우미(텍스트 노드만), 메뉴 표, 해시 라우터, 화면 등록. `shell.js`: 머리말·메뉴·모바일 탭·전체 메뉴. `parts.js`: 화면 공통 부품.
  - `screen-*.js`: 메뉴별 화면. 레인마다 자기 파일만 고친다.
- 글꼴(시안과 같음): Black Han Sans(제목·도장), Gowun Dodum(본문), Nanum Pen Script(손글씨). google/fonts 고정 커밋에서 받아 KS X 1001 부분집합 WOFF2로 자체 호스팅한다(`tools/font_subset_ksx1001.py`).
- 개발 빌드: `tools/build_web_app.py --out <빈 디렉터리>`. 공개 자료 파일은 기존 빌드와 똑같이 만들고, 화면 파일만 새 것으로 바꾼다.
- 시험: `tools/web_app_*_test.js`. 스스로 개발 빌드를 만들고 띄운다. CI 목록(`ci_node_tests.txt`, `ci_browser_tests.txt`)에 등록해 지금부터 매 PR에서 돈다.
