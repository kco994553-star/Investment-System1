## 2. 화면 계층과 표시

- **계층:** 섹터 → 하위 산업 → 기업.
- **SIC:** 기업 줄에 "원천 SIC 3674 · SEC 제출"처럼 따로 적는다. 섹터·산업 선택 목록 안에 SIC 코드를 넣지 않는다.
- **기존 4.3 "SIC 산업 사이클":** 원문(4.3.1 "SIC 기준으로 산업을 선택")과 경로·저장 키(`industry:<group>`)를 그대로 둔다. 화면 머리에 "SIC 업종군 기준(원천 분류) · 공통 산업 분류와 다름"과 둘의 관계를 적는다.
- **4.2 순환매 / 4.3 산업 사이클의 역할:**
  - 4.2 = 섹터 단위 상대 위치(ETF 비교 가격계열을 대리로 씀)
  - 4.3 = 산업 단위 사이클(산업 선택)
  - 둘 다 "위치·확률·자동 투자 제한 완성"으로 보이지 않는다.
- **ETF 대리:** "섹터 ETF는 비교 가격계열 · 구성 범위가 공통 섹터와 다를 수 있음"을 같은 줄에 보인다.
- **집계:** 원래 구성원 수, 지표별 유효 수, 실제 비교집단, 평가일을 함께 보인다. 화면 필터는 점수·순위·분모를 바꾸지 않는다.
- **새 설정 안내:** 10섹터 기본값 → 내 설정. 공격형·균형형·수비형은 이전 설정 호환으로만(DC-46 보완, #510 위 `claude/sector-default-flow`).

## 3. Main이 받아야 하는 기록 (Codex 계약에 요청)

기업 하나·평가일 하나에 한 기록. 필드 이름은 Codex 계약이 정한다. Main은 이 의미가 다 있어야 읽는다.

| 의미 | 필요한 이유 |
| --- | --- |
| 분류 기록 ID · 계약 버전 · 분류 규칙 버전 | 세 화면이 같은 기록을 읽었는지 대조 |
| 평가일 · 적용 시작/끝(`valid_from`/`valid_to`) · 평가일 단일 확인인지 원천 변경일인지 | 적용 기간 밖 판정, 다른 평가일 거부 |
| 기업 ID · 검증된 증권 ID와 그 유효기간 | #515와 같은 결합 규칙(티커 문자열 대체 없음, 종류주·ADR 구분) |
| 섹터 ID(책 10) + 섹터 상태 | 섹터만 확인된 경우를 따로 보이기 |
| 하위 산업 ID + 상태 | 산업 미확인이어도 섹터·개별 지표는 보이기 |
| 원천 SIC: 코드·관측 시각·원천 해시 | 원천으로만 표시 |
| 회계모형 | 적용 지표 안내(분류와 따로) |
| 태그 목록 | 설명·검색(점수 영향 0) |
| 비교 ETF + "구성 범위 차이" 표시 | ETF 대리 표시 |
| 다중 사업 표시(주 사업·부 사업 근거) | 다중 사업 기업의 근거 표시 |
