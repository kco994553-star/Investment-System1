## 2. 화면 동작

### 2.1 목록 (2.1.8, 리더보드 블록)

- **행마다 보이는 것:** 기업명·티커, 하는 일 한 줄, 발견 이유 한 줄, 기존 QGV 점수와 산출 상태, 최초 선정일·마지막 검토일·자료 기준일, 상태 표시(재검토 필요·일부 근거 미확인·검토 오래됨·합성).
- **기업명·티커는 목록이 갖고 있지 않다.** 기존 기업 목록(`IS2.companies`)에서 읽는다. QGV는 기존 게시본(`IS2.qgv.page()`)에서 읽는다. 섹터는 기존 분류의 SIC 업종군에서 읽는다. 새 기업 자료 저장소는 없다.
- **정렬**

| 정렬 | 순서 |
| --- | --- |
| 최근 선정순(기본) | 최초 선정일 최신 → 같으면 기업명 |
| 기업명순 | 화면 이름, 한국어 순서 |
| 기존 QGV순 | 공식 순위 오름차순, 그다음 "공식 QGV 순위 미산출 · 0점 아님" 묶음(이름순) |

  - 행에는 항상 **공식 순위 n / N**(게시본 숫자)을 쓴다. 목록 안의 줄 번호는 쓰지 않는다. 공식 순위와 목록 순서가 섞이지 않는다.
  - QGV가 없어도 목록에서 빼지 않는다. 0점으로 바꾸지 않는다.
  - 새 의외성 점수는 없다.
- **필터**
  - 자료에 실제 값이 있는 것만 고를 수 있다. 값이 하나도 없으면 "○○ 자료 없음 · 이 필터는 없음"이라고 쓴다.
  - 결과가 0건이면 "이 조건에 맞는 의외의 기업이 없습니다 · 조건은 그대로 둠"이라고 쓴다. 조건은 사용자가 "조건 모두 풀기"를 눌러야만 풀린다.
- 정렬·필터 상태는 이 페이지를 연 동안 메모리에만 둔다. 저장하지 않는다.

### 2.2 기업 상세 마크 (2.4.6)

- **위치:** 기업명 바로 옆 단추 `◆ 의외의 기업`.
  - 재검토 상태면 `· 재검토 필요`, 합성 자료면 `· 합성`이 붙는다.
- **동작:** 처음에는 접혀 있다. 클릭·Enter·Space로 펼치고 접는다(`aria-expanded`·`aria-controls`).
- **펼침 순서:**
  1. ① 이 기업을 발견한 이유. 인지도 측정 여부를 함께 보인다. 미측정이면 "미측정만으로 빼거나 저인지도로 확정하지 않음"이라고 적는다.
  2. ② 기업 유형
  3. ③ 눈여겨볼 사업 강점
  4. ④ 사업지역과 성장 여력
  5. ⑤ 추가로 주목할 신호
  6. ⑥ 함께 확인할 위험
  7. ⑦ 확인 근거·자료 기준일·마지막 검토일
- **항목마다:** "확인됨 / 일부 근거 미확인 / 미확인 / 자료 없음"을 보인다.
  - 각 줄은 "확인 · 근거 n" 또는 "미확인 · 사유"다.
- **첫 펼침에 보이는 것:** 위험(⑥)과 근거 요약(⑦의 건수·기준일·검토일).
  - 긴 출처 목록만 "출처 내역 n건 보기"로 한 번 더 펼친다.
- **기존 카드는 그대로다:** 기업 개요·QGV·기술·매크로·뉴스·포트폴리오 카드는 바꾸지 않았다.
- **어디서 들어와도 같다:** 목록 링크·검색 상자·직접 링크(코드나 기존 기업 키) 모두 같은 판독기와 같은 결과로 같은 마크를 보인다.
- **항목명 규칙:** 화면 항목명에는 "린치 유형"·"8장 특성"을 쓰지 않는다.
  - 판독기는 이 말이 든 분류 이름과 요약 줄을 거부한다(`BANNED_LABEL`).
  - 책 출처는 목록의 "선정 방법" 설명에서만 안내할 수 있다.

### 2.3 상태 (서로 다른 문구)

| 상태 | 목록 | 상세 |
| --- | --- | --- |
| 불러오는 중 | "불러오는 중" | (기다림) |

| 자료 불러오기 실패 | 실패 카드 + "다시 읽기" | "의외의 기업 자료를 읽지 못해 표시 여부를 확인하지 못함" |
| 규격 불일치 | 파일 전체를 쓰지 않음 + 거부 코드·위치 | 위와 같음, 마크 없음 |

- 계약에 일괄 만료 기간이 없어 "검토 오래됨"을 화면에서 따로 계산하지 않는다. 자료가 오래되면 Codex가 REVIEW_REQUIRED로 바꾼다.

**판단 한 줄에 보이는 것:**
- 주장(claim)
- 상태(확인·미확인·반박됨)
- 근거 번호, 반대 근거 번호
- 검토 사유

"일부 근거 미확인"은 화면에 보이는 판단 가운데 CONFIRMED가 아닌 것이 있을 때다.

**만료 기준:** Codex 계약에는 일괄 만료 기간이 없다. 그래서 화면은 "검토 오래됨"을 계산하지 않고 마지막 검토일만 늘 보인다. 자료가 오래되면 Codex가 REVIEW_REQUIRED로 바꾼다.

**판독기가 하는 검사:** 스키마의 키·상수·열거값(추가 키 거부)에 더해 다음을 거부한다.
- 상태와 표시가 어긋남 (`DISPLAY_STATE_MISMATCH`)
- 표시한 판단·위험이 기록 자신의 것과 다름 (`DISPLAY_REF`)
- 근거 ID가 없음 (`EVIDENCE_REF`)
- SELECTED인데 관문이 열려 있음(`blocked_gates`·`unresolved_core`·`material_refutations`) 또는 `selection_ready=false` (`GATES_OPEN`)
- 선정 이력 상태에 최초 선정 시각이 없음 (`FIRST_SELECTED_MISSING`)
- `publication_approved≠false` (`PUBLICATION_APPROVED`)
- 기업 유형 topic이 6종 밖 (`TOPIC_INVALID`)
- 주장에 화면 금지어 (`BANNED_LABEL`)
- 한 목록에 같은 기업이 두 번 (`DUPLICATE_COMPANY`)

**해시:** `record_hash` 등 해시는 무결성 표시일 뿐이다. 화면은 다시 계산하지 않고, 접근 권한을 뜻하지도 않는다(Codex 계약).

## 4. Codex와 남은 합의

1. **공개 목록 묶음 형식:** Codex 계약은 기업별 기록 하나다. 화면은 기록 하나, 기록 배열, 또는 합성 묶음(`{synthetic_only, cases}`)을 받는다. 게시용 묶음 형식(배열과 생성 시각 등)을 공개 승인 때 함께 정한다.
2. **화면 단어:** 강점 topic은 자유 문자열이라 화면에 그대로 보인다. 분류표가 생기면 화면 단어 표를 함께 받는다.
3. **CI 등록:** #503의 `test_discovery_company.py`는 #503 병합 때 Main이 공용 CI 목록에 넣는다.

## 5. 자료 연결과 공개 경계

- **지금:** `IS2.discovery.source()`는 `NONE`이다. 공개 파일도 요청도 없다.
- **공개 연결:** 기존 게시 승인과 공개·비공개 경계를 그대로 쓴다. 별도 승인이 필요하다.
  - 실제 기업 자료를 합성 예시와 섞지 않는다. 공개 fixture로 저장하지 않는다.
- **시험의 합성 파일**은 Codex #503 `synthetic.json`을 바이트 그대로 옮긴 것이다(`implementation/tests/fixtures/discovery_company_v1_codex_synthetic.json`, SHA-256 고정).
  - 기업은 `SYNTH:001`이고, 원문 주소는 `example.invalid`라 링크로 만들지 않는다.
  - 브라우저 시험만 실행 중에 이 기록들을 실제 기업 행에 얹어, 링크가 정확한 기존 상세로 가는지 본다. 파일로 남기지 않고, 화면에는 "합성 · 시험용"이 붙는다.
- **실제 비공개 결과는 공개 화면에 연결하지 않는다.** Codex의 첫 실자료 검토는 1개 발행사, 후보 1, 선정 0이다(#503 VALIDATION.md).
  - 그 후보 기업은 CANDIDATE라서, 연결되더라도 목록·마크에 나오지 않는다.
