> 아래 내용을 Investment-System1 저장소를 연결한 Codex 작업에 그대로 전달한다. 이 지시서는 **계획 설명에서 끝내지 않고 가능한 구현·합성 검증·허용 자료 실행까지 수행**하는 작업용이다. 시장 자료가 없으면 결과를 만들지 않고 독립적으로 가능한 작업을 완료한다.

## A. 목적과 권한

목적은 현행 QGV v2와 ① Q/G/V 축 동일가중 ② 내부 요인 동일가중 ③ 두 수준 모두 동일가중의 결과를 같은 조건에서 비교하는 것이다. **종목 보유 비중 최적화가 아니라 점수 가중치 단순화**다.

이번 사용자 요청에 한해 백테스트 전용 연구 코드·검사·문서, 작업 브랜치 및 PR, 허용된 자료를 이용한 연구 실행을 맡는다. 기존 Codex 리뷰 전용 지시를 모든 프로젝트에 걸쳐 해제하지 말고 이 작업의 좁은 범위를 기록하라. 기본 브랜치 직접 변경·강제 푸시·병합·배포·공용 가드 약화·AUTONOMY_MODE 변경은 하지 않는다. Main의 공용 작업과 충돌하지 않는다. 운영 점수·TARGET·플레이북·전진원장·매크로 게이트를 변경하지 않는다.

사용자에게 같은 결정을 반복해서 묻지 않는다. 유료 데이터·신규 계약·보호 자료 접근 등 실제 추가 승인이 필요한 부분만 차단한다. 차단된 작업 때문에 나머지 독립적인 구현·합성 검증을 멈추지 않는다. 권한 부족을 다른 인증 경로나 토큰 노출로 우회하지 않는다.

3. 기준 커밋은 `bb57398c9c22a2dfa2443c5f3a23db3848cbe5ce`, 엔진 `qgv-v2`, 계산 `qgv2-calc/2026-10-17.1`, 유형 범위 `qgv2-type-scope/2026-10-17.1`이다. 관련 최신 변경과 비교하고, 의미가 다른 새 규칙을 이 결과에 조용히 섞지 않는다. 새 기준이 필요하면 결과 열람 전에 버전 변경 이유를 문서화한다.
4. 현재 기준 문서가 PR 브랜치에만 있으면 해당 문서 브랜치/커밋을 정확히 가져온다. 자동 병합하지 않는다. 기존 S0·A0/A~G 등록부는 보존한다.
5. `research/qgv-backtest-v1-20261026` 또는 중복되지 않는 연구 브랜치/분리 작업트리에서 진행하라. Main 작업 중인 공용 파일을 건드리지 않는다. 이 지시서가 요구하는 파일 경로는 **구현할 경로**이며 이미 존재한다고 가정하지 않는다.

## C. 연구 가설과 운용 규칙 — 임의 변경 금지

- W0: 현행 기본 34/33/33 + 유형 보정 ON, 내부 공식 15요인 비중.
- W1: 최종 관문 전 축 1/3씩, 유형 비중 OFF, 내부 공식 유지.
- W2: W0 축·유형 정책 유지, Q/G/V 각각 내부 5요인 20%씩.
- W3: W1 축 정책 + 내부 각 20%.
- W1/W3는 **custom weights 트리와 type_weights=False를 함께** 사용한다. weights 없이 플래그만 꺼서 동일가중이라고 보고하지 않는다.
- 가치 함정 관문은 네 실험 모두 ON. 내부 Q가 바뀌면 관문 Q 백분위도 재계산한다. 결측 50% 규칙, 사이클 정상화, 원지표/하위 지표 산식은 유지한다. 유형 축 가중치 OFF와 경기민감 V 정상화 OFF를 혼동하지 않는다.
- COMMON은 네 실험에서 세 축이 모두 산출되는 평가일별 교집합, PRACTICAL은 각 실험 현행 자격이다. 백분위와 관문 계산은 전체 PIT 모집단에서 먼저 하고 선정만 필터링한다. 미래에 자료가 있는 회사만 남기지 않는다.
- 첫 주실험 N15·분기(2/5/8/11월 셋째 월요일, 휴장일 이월), 목표 기간 2016-02-16~2025-12-31, USD 100,000, 소수 주, 입출금·레버리지·공매도·가격 손절·TA/매크로/13F 타이밍 없음.
- 역사 S&P 500 구성 이력을 사용한다. 현재 Universe504나 TARGET19로 대체하면 탐색용일 뿐 정식 결과가 아니다. CIK당 한 번, 영구 증권 ID로 연결한다.
- S=실행일 T 직전 완료 세션. 공시는 filed<S 날짜. S 종가로 순위·목표 수량 A/(N×P)를 고정하고 T 시가에 체결한다. T 시가를 미리 써서 선정하거나 수량을 정하지 않는다.
- 신규 편입 매수·탈락 매도·유지 종목 순차이 재조정. 부족 슬롯 현금. 미체결은 같은 잔여 주문으로 첫 유효 시가 대기, 다음 정기일 잔량 취소. 현금 부족 매수는 같은 비율 축소, 음수 현금 금지. 반대 주문·분할 수량도 대사한다.
- 매수/매도 각각 10bp를 주 가정, 0/20/25/30bp를 민감도로 실행한다. 같은 gross 거래의 비용 귀속 표와 자기금융 NAV 재실행을 구분한다.
- 배당·분할·상폐·합병·분사·거래정지를 실제 사건으로 처리한다. 상폐 종목 삭제·미확인 수익률 0·최종 가격 영구 유지 금지. 정산 미확인은 INCOMPLETE_NAV.
- 투자자 세금 제외(TAX_MODE=EXCLUDED). **NOPAT의 기업 세율은 제거하지 않는다.** 현금 이자·금리 결측·벤치마크는 기준서 5절을 그대로 따른다.
- 18개 구조 설정: 4개 W×N15분기, 4개 W×N10/N20분기, W0/W3×N15/N25/N50연간. 연간은 2월 셋째 월요일 기준. 추가로 W0/W3 N15 한 기회 지연 체결. 결과가 좋은 것만 골라 재실행하지 않는다.

## D. 실행 단계 — 계획만 남기지 말 것

### 1단계: 입력 계약·자료 감사

실행 전 manifest에 소스 커밋·엔진/설정 버전·자료원·라이선스/보관권·권한·커버리지·기준 시각·기업행사·달력·기존 Holdout 상태를 기록하라. 시장 데이터의 해시와 상세 경로는 비공개에만 저장한다.

과거 구성원, 당시 SEC 제출·SIC, 가격·주식수·배당·정산·현금금리·SPY 총수익의 확보 여부를 필드별로 확인한다. 메타데이터 확인으로 해결되는 질문은 사용자에게 떠넘기지 않는다. 보호 구간은 허가 없이 열지 않는다. 무료라는 이유만으로 자동 수집·보관·재배포가 허용된다고 가정하지 않는다.

자료가 모자라면 `BLOCKED_ON_DATA`와 부족 필드·기간·영향·허용된 대안만 기록한다. 기준 기간을 몰래 줄이거나 시뮬레이션 가격을 실데이터처럼 만들지 않는다. 소표본 재현과 합성 검사로 계속 진행하라.

### 2단계: 연구 엔진과 계약 검사

기존 적합한 연구 모듈이 없을 때 아래 경로를 사용하라.

- `implementation/src/investment_system/research/qgv_backtest/config.py`: 명세·실험 ID·버전·입력 manifest 검증.
- `.../pit_adapter.py`: 과거 모집단·공시·SIC·증권 식별·가격 기준/가용 시점 경계.
- `.../scoring_adapter.py`: 운영 QGV 함수 재사용, W0~W3, COMMON/PRACTICAL.
- `.../ledger.py`: 결정·주문·체결·현금·배당·기업행사·NAV 대사.
- `.../metrics.py`: 기준서의 성과·위험·비용·대응 블록 재표집.
- `.../runner.py`: audit→synthetic→smoke→primary→sensitivity→report 및 재개.
- `implementation/tools/qgv_backtest_research.py`: 명시적 CLI.
- `implementation/tests/research/test_qgv_backtest_*.py`: 각 책임의 합성·계약 검사.

경로가 이미 있으면 같은 책임의 모듈을 재사용하며 중복 엔진을 만들지 않는다. 기존 `v2_factors.compute`, `v2_scoring.score_rows`, `qgv_v2.score_universe`는 호출만 한다. 최신 공개 Q/G 축을 과거 입력으로 넘기지 않는다. 연구 어댑터가 같은 입력의 W0 점수와 공식 결과를 재현하는지 먼저 검증하라. 레거시 toy backtest나 sec_vintage의 잘못된 가용시점 대체는 정식 실행에 쓰지 않는다.

각 작업은 실패하는 검사 작성 → 실패 이유 확인 → 최소 구현 → 검사 통과 → 자기검토 → 작은 커밋 순서로 진행한다. 독립 작업은 사용 가능한 에이전트가 있을 때만 명확한 파일 소유권으로 분리한다. 없으면 직렬로 구현하며 병렬 수행했다고 주장하지 않는다.

반드시 검사할 반례:
1. 미래 제출·정정·S 이후 가격 변형이 S까지 점수·주문을 바꾸지 않는다.
2. 성장 유형이 있는 회사에도 W1/W3의 관문 전 축이 정확히 1/3이다.
3. G의 첫 두 요인만 있으면 공식 50%와 균등 40% 자격을 구분한다.
4. COMMON 필터 전/후 백분위가 부당하게 재계산되지 않는다.
5. 같은 CIK의 종류주가 두 번 선정되지 않는다.
6. 2월 휴장·반일장·시간대·S와 T 관계를 달력으로 재현한다.
7. 분할 경제가치 보존, 배당 이중 합산 방지, 상폐 정산 미확인 차단.
8. 유지 종목 순차이만 매매, 후보 부족 슬롯 현금, 수수료 포함 자기금융.
9. 매도 정지·매수 갭·현금 부족·부분 체결·다음 재선정 취소가 올바르다.
10. 1x/2x/3x 비용 귀속 표는 같은 gross 거래를 사용하고, 독립 NAV 재실행과 구분된다.
11. 입출력 순서·동점·중단 재개에서 결과가 결정적이고 이전 완료 결과를 덮어쓰지 않는다.
12. 시장 수치·시크릿·개인정보가 공개 저장소/로그에 남지 않는다.

운영 함수를 다시 호출해 얻은 값을 기대값으로 만들어 자기 자신을 검증하지 않는다. 손계산 가능한 합성 예제·독립 대조와 실제 실패 조건을 남겨라.

### 3단계: 허용된 실데이터 소표본

자료·권한·Holdout 경계가 통과한 구간의 **첫 시간순 평가일**을 고르고 결정적인 소표본을 사용한다. 좋은 종목/시기만 고르지 않는다. 점수→선정→순수량→체결→현금→NAV를 대사한다. 이를 전략 효과 검증 완료라고 부르지 않는다.

### 4단계: 주비교 및 민감도

소표본과 데이터 검사가 통과하면 W0~W3 N15분기의 두 패널을 실행한다. 이후 등록된 N/주기/비용/지연 묶음을 실행하라. 당시 미확정인 거래가격·소속도·수정치를 미래 정보로 채우지 않는다. 모두 같은 버전·자료 조건을 사용하고 결과 차이가 입력 가용성 때문인지 점수 비중 때문인지 분리한다.

최종 평가 후보 2023~2025는 **실제 미사용과 접근 허가를 증명한 경우만** OOS로 쓴다. 기존 보호 Holdout은 열지 않는다. 이미 사용했거나 불명확하면 OOS_NOT_ESTABLISHED로 표기하고 허용된 기술적 소급 평가만 수행한다. 과거 소급 성과와 실제 전진 원장 곡선을 합치지 않는다. 마지막 결과에 맞춰 가중치를 다시 고른 뒤 같은 자료를 독립 평가라고 주장하지 않는다.

### 5단계: 결과·검토·인계

비용 후 CAGR·MDD·Sharpe·회전율·현금·미체결·커버리지·기간별 결과와 비교 그래프를 작성하라. 기준서의 경제적 허용폭과 불확실성 판정에 따라 우월성 후보/비열등 후보/열등/증거 부족/판정 불가를 구분한다. 결과가 나쁘면 그대로 보고한다. 거래 장부가 맞는 것과 투자 효과가 좋은 것은 별개다.

독립 리뷰 또는 별도 적대적 자기검토로 미래정보, 분할, 생존편향, 현금 보존, 비용·비교 분모, 미사용 구간 주장을 반박해 보라. 발견된 문제는 재현 입력과 함께 수정하고 해당 검사만 다시 실행하라. 무변경 반복 감사를 늘리지 않는다.

## E. CLI·실행 증거

아래는 **만들고 검증할 인터페이스**다. 이미 존재하는 명령인 것처럼 보고하지 않는다. 구현 후 `--help`부터 실제 실행하고 stderr·exit code를 확인하라.

```text
python implementation/tools/qgv_backtest_research.py --stage audit --spec implementation/docs/backtest/QGV_BACKTEST_SPEC_V1_20261026.json --input-manifest <승인된_비공개_manifest> --output <승인된_비공개_출력>
python implementation/tools/qgv_backtest_research.py --stage synthetic --spec implementation/docs/backtest/QGV_BACKTEST_SPEC_V1_20261026.json
python implementation/tools/qgv_backtest_research.py --stage smoke --spec ... --input-manifest ... --output ...
python implementation/tools/qgv_backtest_research.py --stage primary --spec ... --input-manifest ... --output ...
python implementation/tools/qgv_backtest_research.py --stage sensitivity --spec ... --input-manifest ... --output ...
python implementation/tools/qgv_backtest_research.py --stage report --spec ... --input-manifest ... --output ...
```

문서의 `<...>`와 `...`를 실제 경로로 치환한 명령만 실행한다. 토큰 값은 인자·문서·로그에 쓰지 않는다. 실행별 manifest는 run_id, spec_id, research_code_sha, scoring_source_sha, config hash, private data hashes, 실행 시각, 패널·기간·비용·체결 가정, Holdout 판정, 상태·오류·산출물 참조를 가진다. 0건/NA/실패/미실행을 구분한다.

## F. GitHub·Notion 출력과 종료 보고

- GitHub PR에는 연구 코드·합성 검사·방법론과 상태/차단 건수만 올린다. 실가격·원시 재무 사본·과거 종목별 V/순위·실데이터 수익률·NAV·시크릿·가격 해시를 넣지 않는다. 실제 결과는 승인된 비공개 경로에 보존한다.
- 공용 파일·기존 전진원장·운영 코드 변경이 필요하면 Main에 별도 변경안으로 남긴다. 직접 병합·배포하지 않는다.
- Notion은 기존 `투자시스템 → 관리자 / 상세 / 그래프 / 백테스트`에 상태·근거 링크를 업데이트한다. 권한이 없으면 저장 가능한 Markdown 인계본을 남기고 실제 업데이트했다고 말하지 않는다.
- 매 단계에서 짧은 진행 보고를 하되 사용자에게 불필요한 승인 질문을 반복하지 않는다. 실행 중단 시 마지막 완료 단계·재개 명령·남은 차단만 명확히 남긴다.
- 최종 보고는 한국어로: **① 기준 버전 ② 실제 변경 파일·PR ③ 실제 실행 명령/검사 결과 ④ 자료 가용성 ⑤ 실행한 실험과 못한 실험 ⑥ 비용 후 결과 또는 미산출 이유 ⑦ OOS/전진 상태 ⑧ 다음 작업·필요한 실제 승인**.

합성 시험만 통과했다면 SYNTHETIC_PASS라고 쓰고 백테스트 성공이라고 하지 않는다. 데이터가 없으면 실데이터 결과를 생성하지 않는다. 반대로 자료와 권한이 준비됐다면 계획만 제출하고 끝내지 말고 등록된 연구를 실제로 실행하라.
