## 3. #276 승인·병합 및 대체 실행 운영

#276을 승인한다.
기본 순서는 504 일괄 실행 배포 확인 → #276 병합이다.
각각 최신 HEAD의 필수 6체크 성공을 확인한다.

유지할 구현:

- 뉴욕 날짜에 따른 일일 샤드 선택.
- UTC 자정을 넘긴 대체 실행의 관측일·샤드 일관성.
- workflow 수준 concurrency.
- cancel-in-progress: false.
- 같은 관측일 원장 중복 방지와 기존 행 보존.
- 정기 / 일일 대체 / 504 일괄 실행 구분.

운영 보완:

1. 대기 중 취소된 실행이 자체 로그를 남긴다고 가정하지 않는다.
   Main이 Actions 실행 목록·상세 결과를 조회해 별도 운영 기록에 남긴다.
   실행 ID, 대상 관측일, 상태, 확인 시각을 기록한다.
   취소 원인을 입증하지 못하면 “원인 미확인”으로 둔다.

2. 예약 + 2시간 점검을 유지한다.
   22:17 UTC 예약이면 다음 날 00:17 UTC / 09:17 KST다.
   완료·진행·대기 중인 실행을 먼저 확인하고 중복 실행하지 않는다.
   실행이 없고 기록 가능 시간이 남아 있을 때 검증된 일일 대체 경로를 사용한다.
   all_shards=false를 명확히 지정한다.

3. 마감은 뉴욕 자정 전 “원장 단계 실행”이다.
   시작만 마감 전에 했다고 기록 가능하다고 보고하지 않는다.
   실행 대기와 원장 이전 단계의 소요 시간도 고려한다.
   마감은 America/New_York 기준으로 계산하고 UTC·KST로 함께 표시한다.
   RUN_CONTEXT는 안내 값이며, 원장 단계의 실제 결과를 최종 근거로 쓴다.

4. 예약 점검 작업의 존재·다음 실행·담당을 확인한다.
   세션이 종료되면 사라지는 방식이라면 그 한계를 인수인계에 명시한다.
   설정만 존재하는 상태를 무인 복구 검증 완료로 보고하지 않는다.

5. cron은 22:17 UTC를 유지한다.
   지금 queue 설정 변경이나 새 감시 시스템 구축까지 범위를 넓히지 않는다.

누락 기록:

- 원장 형식은 이번에 바꾸지 않는다.
- 누락일·확인된 사유·관련 run ID·확인 시각을 별도 운영 기록에 남긴다.
- 기록을 위해 운영 배포를 일부러 실패시키지 않는다.
- 당시 확보하지 못한 데이터를 나중에 가져와 정상 과거 관측처럼 채우지 않는다.
- 원장 형식에 누락 사유를 넣을지는 10/19 이후 2주 운영 결과로 다시 검토한다.
