저장 위치 제안: `implementation/docs/virtual_trading/REPORT_TEMPLATE_V1.md`
관련: [가상매매 v1 제안서](VIRTUAL_TRADING_V1_PROPOSAL.md) · [AI 해석 지침 v1](AI_INTERPRETATION_GUIDE_V1.md) · 디자인 캔버스 S17 일일 보고서

## 0. 개요

- 하나의 틀(①~⑬ + 최종판단 + 각주)을 **대상 3종**이 공유한다: 세트 A(공식 v1.1), 세트 B(사용자 정의), **내 실제 포트폴리오**. 비교 탭은 별도.
- 앱(S17)은 숫자 칸을 모두 채운 화면을 보여 주고, "보고서 템플릿 내보내기"로 **지침 + 채워진 템플릿**을 마크다운 한 덩어리로 복사한다.
- AI는 `【AI】` 칸만 채우고 표 구조·숫자는 그대로 둔다. 답변은 앱의 'AI 해석' 칸에 날짜와 함께 통째로 보관한다(칸별 자동 분리 없음).
- 표기 규칙: `{{변수}}` = 앱이 채움, `【AI】` = AI가 채움, `【규칙】` = 앱의 규칙 문장(AI 답이 없을 때 그대로 노출).

## 1. 사용자 결정 반영 (2026-10-11)

| ID | 결정 |
|---|---|
| D-15 | 가상매매 한도: 매수 ≤ 100만원, 매도 ≤ 100만원 각각 |
| D-17 | **내 실제 포트폴리오에도 가상매매(그림자 장부)를 붙인다** |
| D-18 | **금액 숨김은 기능으로 구현, 기본값 켜짐** |

### 1.1 그림자 장부 (D-17)
- 출발점: 사용자가 지정한 날짜의 **실제 보유 스냅샷**(Trades 탭으로 재구성한 수량·평균단가). 출발 후에는 실제 거래와 **독립**으로 움직인다.
- 규칙: 세트 A·B와 같은 가상매매 규칙 v1(목표 비중 차이 + 관문, 매수·매도 각 100만원, 다음 정규장 종가 체결, 거래일마다 100만원 가상 입금).
- 목표 비중: S14의 '내 목표(TARGET)'. 목표가 없으면 그림자 장부는 **NOT_AVAILABLE**(규칙이 비교할 기준이 없음). 화면에 "내 목표 비중을 입력하면 가상매매가 시작됩니다" 안내.
- 비교: 같은 기간 **실제 운용 vs 그림자 장부(규칙대로 했다면)** 의 수익률·거래 수·적중을 나란히 표시.
- 재출발: 사용자가 "실제 보유로 다시 맞추기"를 누르면 새 그림자 장부 ID로 시작하고, 이전 장부와 성과는 보존한다(덮어쓰기 없음).
- 저장: 사용자 시트 `VirtualMine` 탭(거래), `VirtualMeta` 탭(장부 ID·출발일·출발 스냅샷 해시·규칙 버전). 공개 저장소·로그에는 없음.
- 경계: 그림자 장부의 매수·매도는 **가상 기록**이다. 실제 계좌에 대한 지시가 아니며, 실제 보유 화면(S03)에는 6관점 어휘만 쓴다.

### 1.2 금액 숨김 (D-18)
- 위치: S17 머리글 토글 + 템플릿 내보내기 시트의 토글. 두 토글은 같은 설정을 공유한다.
- 기본값: **켜짐.** 설정은 기기에만 저장(localStorage, 실패해도 켜짐으로 동작).
- 켜짐일 때:
  - 화면: 원화 금액(평가액, 손익, 투자금, 가상 거래 금액, 현금)을 `●●●만원`으로 가리고 %·%p·비중·점수는 그대로 보인다.
  - 내보내기: 금액 칸을 `[숨김]`으로 바꾸고, 가상 거래 금액은 **한도 대비 %**(예: 매수 25%)로 바꿔 넣는다. AI가 판단 규모는 이해할 수 있게 한다.
  - 수량·평균단가도 숨긴다(금액을 역산할 수 있으므로).
- 꺼짐으로 바꿀 때 한 번 확인 창: "개인 금액이 화면/복사본에 표시됩니다."
- 종목명 가리기는 v1에서 제공하지 않는다(가리면 AI가 뉴스·경쟁사를 찾을 수 없음). 시트 ID·토큰·이메일은 어떤 설정에서도 내보내지 않는다.

## 4. AI 지침 추가 문구 (지침 v1에 덧붙임)

```

- 【규칙】 문장은 지우지 말고, 다르게 해석하면 그 아래 [의견] 줄로 덧붙인다.

- 내 실제 포트폴리오 보고서에서도 실제 계좌에 대한 매수·매도 권유를 쓰지 않는다. 그림자 장부의 매매는 가상 기록으로만 해설한다.
```

## 5. 구현 메모 (Claude Code용)

- 템플릿 생성은 기기 JS의 순수 함수: `(대상 데이터, 설정{금액숨김}) → markdown 문자열`. 같은 입력이면 같은 출력. 테스트 벡터는 Python 참조 없이 JS 단위 테스트로 충분(계산이 아니라 서식).
- 금액 숨김 변환은 템플릿·화면이 같은 함수를 쓴다(누락 방지). 테스트: 숨김 켜짐일 때 출력에 원화 금액·수량·평단 패턴이 0건.
- 내보내기·클립보드 외 경로(네트워크, 텔레메트리, 공개 JSON)로 보고서가 나가지 않음을 테스트로 확인.
- 그림자 장부는 가상매매 엔진을 그대로 쓰고 입력(출발 스냅샷·목표)만 다르다. 장부 ID별 분리 저장.
- 26E 기록(GSQ-018에 D-15·D-17·D-18 포함)은 사용자 승인 후 병합.

## 7. 행동요령 기준 — 방향이 있는 7단계 [D-19 개정안, 제안]

기존 6개 어휘(관찰/추가검토/보유맥락/비중재검토/위험재검토/차단)는 **주의 수준**만 있고 방향(긍정·부정)이 없다. 특히 긍정 신호(예: Q·G는 유지인데 V가 좋아짐 → 비중을 늘릴지 검토)를 표현할 칸이 없다. 그래서 '비중재검토'를 방향별 두 개로 나누고, 각 판단에 방향을 붙인다. 저장소에는 판정 기준이 아직 정의돼 있지 않으므로(ROADMAP 15) 이 개정안 채택 시 S13 어휘도 함께 바꾼다.

### 7.1 판단 7단계

| 우선 | 판단 | 방향 | 뜻 | 조건(하나라도 해당) | 가상매매 |
|---|---|---|---|---|---|
| 1 | **차단** | 판단 불가 | 데이터로 판단할 수 없음 | Coverage BLOCKED · 식별 모호 · 가격 결측 · 사용자 '제외' | 거래 없음 |
| 2 | **위험재검토** | ▼ 부정(위험) | 기업 자체에 문제 신호, 사람이 확인해야 함 | Q·G 평균 하락 ≥ 임계(D-8) · Coverage 악화 · **개별 이상 하락**(D-5, §7.2) · 매크로 EMERGENCY · 사용자 '보류' | 이상 하락·보류는 거래 없음(Re-check). Q·G 하락은 보유 시 매도 후보 |
| 3 | **비중축소검토** | ▼ 부정(비중) | 기업은 괜찮지만 많이 갖고 있거나 비싸짐 | 실제 > 목표 + Band(D-7) · 또는 Q·G 유지 + V 하락 ≥ 임계(D-21, 고평가 심화) | 매도 후보 |
| 4 | **비중확대검토** | ▲ 긍정 | 기업은 유지·개선, 덜 갖고 있거나 싸짐 | 실제 < 목표 − Band · 또는 Q·G 유지·상승 + V 상승 ≥ 임계(D-21, 저평가 심화) | 매수 후보 |
| 5 | **추가검토** | ● 중립(확인) | 방향은 없지만 확인할 일이 있음 | 실적 발표 예상 기간 · 유형 소속 변경 · Coverage PARTIAL | 영향 없음 |
| 6 | **보유맥락** | ● 중립 | 보유 중, 특별한 신호 없음 | 위 조건 없음 | 거래 없음 |
| 7 | **관찰** | ● 중립 | 미보유 관심 종목 | 미보유, 위 조건 없음 | 대상 아님 |

화면 표시: 칩 앞에 방향 기호(▲ 긍정, ▼ 부정, ● 중립, ■ 판단 불가)를 붙인다. 한국식 상승=빨강 관례와 헷갈리지 않도록 **판단 칩 색은 수익률 색과 다르게** 쓴다.

### 7.2 가격 하락과 V 상승의 처리 (사용자 지적 반영, D-5 개정)

**원칙: 판단은 기업과 시장을 기준으로 하고, 사용자의 매수 가격(평균단가)은 기준으로 쓰지 않는다.** 평균단가는 손익 표시에만 쓴다. 고점에 산 사람과 저점에 산 사람이 같은 기업에 대해 다른 판단을 받으면 안 되기 때문이다. 그림자 장부·가상 장부도 같다.

가격이 내려 V가 오를 때, 하락의 성격을 둘로 나눈다(Portfolio Spec §10 "하락 원인을 구조적/일시적 악재와 시장·산업 요인으로 구분"의 규칙화).

| 하락 성격 | 판정 방법 | 판단 |
|---|---|---|
| **시장·업종 동반 하락** (조정장) | 업종 기준 대비 초과수익률이 그 종목의 평소 범위 안 | Q·G 유지 + V 상승 → **▲ 비중확대검토**. 고점에 샀든 아니든 같다 |
| **개별 이상 하락** | 업종 기준 대비 초과수익률이 평소 범위를 크게 벗어남 | **▼ 위험재검토**(주) + `▲확대 후보`(보조). 기업 고유 문제가 Q·G에 아직 반영되지 않았을 수 있으므로 원인 확인 전에는 사지 않는다 |

**'평소 범위'는 종목마다 자동으로 다르다 (고정 −20% 폐기 제안):**
- 계산: 최근 20거래일 **업종 기준 대비 초과수익률**이 그 종목의 지난 1년간 20거래일 초과수익률 분포에서 **−k·σ 아래**면 이상 하락. 권장 k = 2 [D-5].
- 효과: 평소 변동이 큰 반도체는 −25%여도 업종과 같이 빠졌다면 정상이고, 변동이 작은 필수소비재는 −8%만 혼자 빠져도 이상 하락이 된다. 업종·산업·기업별 기준표를 사람이 따로 정하지 않아도 된다.
- 업종 기준: SIC 업종군 → 대표 업종 ETF 대응표(예: 반도체 SMH, 기술 XLK, 산업재 XLI, 헬스케어 XLV …) [D-22, 사용자 확인 필요]. 대응 ETF가 없으면 S&P 500. 가격은 Worker로 기기에서만 사용.
- 데이터 부족(1년 일봉 미만 등)이면 이상 하락 판정 NA, "기준 계산 불가" 표시. 이때 V 신호는 쓰지 않는다(보수적).
- 사용자가 원인을 확인하고 '확인: 일시적' 플래그를 남기면 위험재검토가 풀리고 ▲가 주 판단이 된다. '확인: 구조적'이면 위험재검토 유지. 플래그는 Track Record에 사용자 개입으로 따로 집계.

**V 상승 신호(D-21)는 그대로:** Q·G 유지·상승 + V가 20거래일 전 대비 임계 이상 상승. 가상매매에서는 Band 안 기울기(목표 + Band까지)로만 쓴다. 추가 매수가 반복돼도 Band 상한에서 멈추므로 한 종목 쏠림은 막힌다.

**기존 문서와의 관계:** Portfolio Spec §10의 "−20% 하락은 자동매수가 아니라 Re-check" 원칙(자동매수 금지, 원인 재검토)은 유지하고, **−20%라는 고정 숫자만 종목별 변동성 기준으로 바꾸는 제안**이다. 채택 시 26E 결정으로 기록한다.

### 7.3 겹칠 때 표시

- **주 판단 1개(우선순위 최상) + 보조 칩**. 방향이 다른 신호가 겹치면 보조 칩에 방향 기호를 함께 쓴다.
  - Q·G 하락 + 비중 초과 → `▼ 위험재검토` `▼비중`
  - 개별 이상 하락 + V 상승 → `▼ 위험재검토` `▲확대 후보`
  - 업종 동반 하락 + V 상승 → `▲ 비중확대검토` (위험재검토 아님)
  - 비중 부족 + 실적 예정 → `▲ 비중확대검토` `●추가검토`
- 사유 코드는 모두 나열하고, 코드마다 출처 관점(기업분석·포트폴리오 적합·위험·계좌 상황·매크로)을 붙인다. 기술 관점은 GSQ-015에 따라 v1 판정에 쓰지 않는다.
- 요약 집계는 주 판단만 센다: 예) `▲3 · ▼4(위험 2 · 축소 2) · ●12`.
- 정렬: 주 판단 우선순위 → 신호 크기 순.

## 8. AI 해석을 웹 안에 자동으로 넣는 방법 [D-20, 제안]

### 8.1 구조: 구글 시트 '받은편지함/보낸편지함'
앱은 AI API를 직접 부르지 않는다. 사용자의 비공개 시트를 우체통으로 쓴다.

1. **앱 → ReportInbox 탭**: 앱을 열면(미국 장 마감 이후) 그날 템플릿(금액 숨김 기본 적용)과 해시·템플릿 버전·상태 `NEW`를 한 행으로 쓴다.
2. **예약 AI → ReportOutbox 탭**: 사용자의 AI 예약 작업이 정해진 시각에 `NEW` 행을 읽고, 지침대로 【AI】 칸을 채운 결과를 해시와 함께 쓰고 Inbox 상태를 `DONE`으로 바꾼다.
3. **앱 ← ReportOutbox**: 다음에 앱을 열면 해시가 같은 결과만 'AI 해석' 칸에 표시한다(모델 이름·생성 시각 표시). 해시가 다르면 "다른 날짜 데이터에 대한 해석"으로 표시하지 않는다.
4. **숫자 점검**: 앱이 AI 답의 숫자를 뽑아 데이터 블록에 없는 숫자가 있으면 "블록에 없는 숫자 n개" 경고를 단다.

AI 공급자를 바꿔도 앱은 그대로다(시트 형식만 계약).

### 8.2 예약 AI 선택지

| 선택지 | 장점 | 한계 |
|---|---|---|
| **ChatGPT 예약 작업 + 구글 시트 연결** (권장 1순위, 사용자 요금제 활용) | 유료 요금제 사용량 여유, 웹 검색으로 ⑧ 뉴스 가능, 시트 읽기·쓰기 범위 제공(2026-06 이후 재연결 필요) | 예약 작업은 최대 1시간에 1번. 쓰기는 '중요 동작'이라 승인 설정 필요. 2026년 9~10월 예약 실행 중 쓰기 실패 사례 보고 → 실패 시 수동으로 대체 |
| Claude 예약 작업 + 구글 시트 연결 | 시트 쓰기 안정적, 같은 지침 | Claude 사용량이 넉넉하지 않음 |
| 구글 시트 =AI() 함수(Gemini) | 시트 안에서 바로 생성 | Google AI Pro 등 유료 필요, 셀 단위, 편집 시 재계산, 웹 검색 여부 불명 → 짧은 요약용 |
| Cloudflare Workers AI | 앱 버튼으로 즉시, 무료 한도 | 작은 모델이라 품질 낮음, 뉴스 불가, Worker 변경 승인 필요 |
| 수동 복사·붙여넣기 | 항상 가능 | 매일 손이 감 |

### 8.3 운영 규칙
- 예약 시각 예: 매일 08:30, 12:30 KST(앱이 아침에 쓴 `NEW`를 처리, 하루 최대 2회).
- 시트에는 금액 숨김 상태로만 쓴다(기본). 종목·비중·점수는 AI 공급자에게 전달됨을 설정 화면에 고지한다.
- 시트 ID·토큰은 예약 작업 지시문에 넣지 않는다(사용자가 AI 쪽에서 파일을 직접 선택).
- 실패하면 앱은 'AI 해석 없음 · 규칙 문장 표시'로 동작하고, 수동 붙여넣기 버튼은 항상 남긴다.
- 이 경로(개인 데이터가 사용자 AI 계정으로 가는 흐름)는 새 데이터 경계이므로 26E 결정(GSQ-019)으로 기록한다.
