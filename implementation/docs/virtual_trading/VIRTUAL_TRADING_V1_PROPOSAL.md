## 1. 위치: 기존 설계 어디에 들어가나

가상매매는 새 모듈이 아니라 이미 설계된 흐름의 빈칸을 채운다.

| 기존 설계 | 해당 내용 | 가상매매와의 관계 |
|---|---|---|
| Simulation Spec §11 Current Mode, `SimulationMode.FORWARD` | 현재 Snapshot 기준 Forward 상태를 만들고 이후 실제 데이터만 누적 | 가상매매 = Forward 모의투자의 **일일 실행 규칙** |
| Track Record Spec §2·§11 Portfolio Decision Record | 편입·제외·증감 당시 이유와 Snapshot 보존, 이후 성과 연결 | 가상 거래 1건 = Decision Record 1건 |
| ROADMAP 항목 16 | 모의투자/전진검증 **시작일·대상·전략버전·보관 범위 사용자 결정 대기** | GSQ-018이 이 결정을 겸한다 |
| S10 검증·연구 '모의투자' 탭 | 탭은 설계돼 있고 규칙이 비어 있음 | 화면 위치 |
| Portfolio Spec §10·§11 | −20% 하락은 자동매수 아님(Re-check), Band·거래비용 고려 | 규칙 제약으로 그대로 사용 |
| S13 6관점 판단 어휘 | 관찰/추가검토/보유맥락/비중재검토/위험재검토/차단 | 실제 포트폴리오 화면의 어휘는 유지. 가상 장부 안에서만 매수·매도 동사 사용 |

**경계:** 가상매매는 실제 주문·이체가 아니다. 모든 가상매매 화면에 "가상 시뮬레이션 · 실제 추천 아님 · 주문 기능 없음"을 고정 표시한다. 실제 포트폴리오(S03·S14) 화면에는 매수·매도 지시를 넣지 않는다.

## 2. QGV 영역 재구성 (저장소 기준)

외부 규격 ⑤의 12개 영역을 저장소의 실제 구조로 대응시킨다. 없는 것은 NOT_AVAILABLE로 둔다.

| 외부 규격 영역 | 저장소 대응 | 상태 |
|---|---|---|
| Quality | Q 7요소: 경쟁우위 0.20 · ROIC−WACC 0.20 · 시장지위 0.15 · FCF품질 0.15 · 마진품질 0.10 · 재무건전성 0.10 · 경영진 0.10 | STANDARD v1 · UNCALIBRATED |
| Growth | G 6요소: 향후3~5년 0.25 · 성장효율 0.20 · 매출성장 0.15 · EPS·주당FCF 0.15 · 지속성 0.15 · 산업대비초과 0.10, 기본 기간 3Y | STANDARD v1 · UNCALIBRATED |
| Competitive Position | Q의 경쟁우위·시장지위 요소로 흡수(별도 축 아님) | 위와 같음 |
| Valuation | V 7요소: 내재가치 0.25 · 역DCF 0.20 · 동종비교 0.15 · 과거밸류 0.15 · 안전마진 0.10 · 섹터맥락 0.10 · 테마프리미엄 0.05. **가격 필요 → 기기 JS** | Initial Prior, UNCALIBRATED. DCF 파라미터 미확정 시 NOT_AVAILABLE |
| Expectations | V의 역DCF 요소 | 위와 같음 |
| Safety Margin | V의 안전마진 요소 | 위와 같음 |
| Confidence | QGV 결과의 confidence, Coverage(READY/PARTIAL/BLOCKED) | 있음 |
| Key Drivers | Analysis 출력 key_drivers(3~5개) | 있음(데이터 coverage 따라 NA) |

| 시나리오 | 부정/중립/긍정 시나리오 | 설계 있음, 실데이터 연결 전 NA |

| Macro Layer | **QGV 밖**(Module Map: Technical·Macro는 상위 Investment System에서 결합) | 매크로 축으로 분리 표시 |

추가로 보고서에 반드시 따라 붙는 저장소 규칙:
- 총점은 저장소에 **두 정의가 공존**한다. ① 기업분석 스냅샷 `total_score` = (Q+G)/2, V 미포함, 유형조정 identity(Standard v1 문서·analysis.py). ② GSQ-017 유형 엔진 `adjusted_score` = 유형 혼합 가중(예: 성장형 Q30·G50·V20, 미분류 34·33·33, 축별 15~60 클램프 후 재정규화)으로 Q·G·V 합산, OFFICIAL_PROVISIONAL(company_types.py). ②는 V가 가격 필요라 기기 JS에서만 완성되고 아직 JS 이식·화면 연결 전이다. **보고서 "QGV 총점" = ②(유형 가중 Q·G·V)로 통일 제안**, ②가 NA일 때만 ①을 "Q·G 점수"로 표시 [D-14]. 원점수 Q·G·V는 항상 함께 표시.
- 가상매매 관문(D-8)은 가격에 따라 매일 움직이는 V 대신 **가격 없는 Q·G 변화**를 쓴다. 가격 변동만으로 매매 관문이 흔들리지 않게 하기 위함이다.
- 유형 조정: Standard v1은 identity, GSQ-017 유형 v1은 PROVISIONAL. 원점수와 유형조정 점수를 모두 표시한다.
- 실증 유효성은 **NOT VALIDATED**. 모든 화면에 `STANDARD v1 · UNCALIBRATED` 배지.

## 4. 가상매매 규칙 v1 (제안값, 결정 필요 항목은 [D-n] 표시)

### 4.1 장부
- 세트 A, 세트 B 각각 **독립 가상 장부**. 실제 모의투자 NAV와 절대 합산하지 않는다.
- 세트 A 대상 = 공식 Portfolio v1.1 19종목과 목표 비중. 세트 B 대상 = 사용자가 시트에 정의한 임의 포트폴리오.
- 자금 [D-1]: (권장) **거래일마다 100만원 가상 입금**, 매수는 이 입금과 가상 현금에서 지출, 미사용분은 가상 현금으로 남음. 하루 한도 = **매수 ≤ 100만원, 매도 ≤ 100만원 각각 별도**(D-15, 사용자 결정 2026-10-10). 매도대금은 현금에 들어가지만 한도를 늘리지 않는다.
  대안: 고정 시드 없이 매수 한도만 100만원(입금 없음, 첫날부터 매수 불가) → 비권장.
- 휴장일: 거래 0, 보유 평가만. 시장별 휴장일은 해당 종목에만 적용.

### 4.2 판단 시점과 체결 가정 (미래정보 금지)
- 판단 입력: **직전 완료 정규장** 기준 데이터만(해당일 공개 JSON Q·G 스냅샷, 그 시점 종가).
- 체결 [D-2]: (권장) **다음 완료 정규장 종가** 체결. 판단에 쓴 종가로 바로 체결하면 미세한 미래정보가 된다.
- 비용 [D-3]: (권장) 매매 수수료·세금 0으로 시작하고 "비용 미반영" 배지. 또는 고정 bps.
- 수량 [D-4]: (권장) **소수점 수량 허용**(전 시장 동일, "소수점 가정" 배지). 정수 주를 강제하면 일본 종목(100주 단위)은 100만원으로 사실상 매수 불가.

### 4.3 매수·매도·보유 조건
세트의 **목표 비중과 가상 장부 실제 비중의 차이**를 중심으로 하고, QGV·데이터·매크로·사용자 플래그를 관문(Gate: PASS/HOLD/BLOCK)으로 쓴다. 점수 변화만으로 바로 사고팔지 않는다(Portfolio Spec §4).

공통 관문 (하나라도 걸리면 해당 종목 그날 매매 없음 = 보유):
- 데이터: Coverage BLOCKED, 가격 결측, 스냅샷 없음 → HOLD (사유 코드 `DATA_*`)
- 사용자 보류 플래그(뉴스 등) → HOLD (`USER_HOLD`)
- **개별 이상 하락**(업종 기준 대비 20거래일 초과수익률이 종목 자신의 1년 분포 −2σ 아래, [D-5]·[D-22]) → **Re-check, 자동 매수·매도 없음** (`RECHECK_ABNORMAL_DROP`). 평균단가는 판단 기준으로 쓰지 않음
- 매크로 EMERGENCY → 신규 매수 BLOCK (`MACRO_EMERGENCY`). 단 8축 매핑 채택 전에는 국면 NA이므로 이 관문은 비활성 표시 [D-6]

매수 후보:
- 실제 비중 < 목표 비중 − Band [D-7, 권장 1%p], 또는
- Q·G 유지·상승 + V가 20거래일 전 대비 임계 이상 상승 [D-21] → 목표 + Band까지 매수 가능(Band 안 기울기)
- QGV 관문 PASS: Q·G 데이터 READY 또는 PARTIAL, 직전 스냅샷 대비 Q·G 평균 하락폭 ≤ 임계 [D-8]

매도 후보 (가상 보유분 안에서만):
- 실제 비중 > 목표 비중 + Band, 또는
- Q·G 유지 + V가 20거래일 전 대비 임계 이상 하락 [D-21] → 목표 − Band까지 매도 가능, 또는
- QGV 위험: Q·G 평균 하락폭 > 임계 [D-8], 또는 Coverage가 BLOCKED로 악화, 또는
- 사용자 '제외' 플래그

금액 배분:
1. 매도 후보에 매도 한도(100만원)를 초과분 크기 비례로 배분한다.
2. 매수 후보에 매수 한도(100만원)를 부족분 크기 비례로 배분한다. 매수는 가상 현금 잔고를 넘을 수 없다.
3. 종목당 하루 최소 거래액 [D-9, 권장 1만원] 미만이면 거래하지 않는다.
4. 같은 종목을 같은 날 사고팔지 않는다.

기술적 지표: GSQ-015에 따라 **표시 전용**이며 Model Indicator 세트가 미확정이다. v1 규칙에는 넣지 않는다. 추후 Technical Execution Zone(ENTRY/ADD/WAIT/RISK_REDUCTION) 확정 시 v1.1에서 관문으로 추가하고, 그 전후 성과를 별도 실험으로 비교한다(Simulation Spec §14).

### 4.4 뉴스
자동 뉴스 신호 없음(NEWS_NO_SOURCE). 사용자가 S07이나 종목 화면에서 '보류' 또는 '제외' 플래그를 날짜와 메모와 함께 시트에 기록한다. 플래그가 붙은 거래는 Track Record에서 **사용자 개입 거래**로 따로 집계해 "뉴스 판단이 도움이 됐는지"를 측정한다.

### 4.5 판단 이유 표기
규칙이 남기는 사유 코드 → 한국어 고정 문장. 예:
`UNDERWEIGHT_GAP`(목표 대비 부족 2.3%p) · `OVERWEIGHT_GAP` · `QG_DECLINE` · `COVERAGE_BLOCKED` · `USER_HOLD` · `RECHECK_ABNORMAL_DROP`(업종 대비 이상 하락) · `V_IMPROVED`(Q·G 유지 중 V 개선) · `USER_CONFIRMED_TEMPORARY` · `BAND_INSIDE`(범위 안, 보유) · `LIMIT_EXHAUSTED`(한도 소진).
외부 규격 예시의 "계약 관련 불확실성" 같은 서술은 규칙이 만들지 않는다. 필요하면 사용자 메모로 남는다.

### 4.6 앱을 매일 열지 않는 경우
가격 계산은 기기에서만 하므로 Actions가 대신 실행할 수 없다. 앱을 연 날 **빠진 거래일을 순서대로 재생**한다. 각 날짜에는 그날 날짜의 공개 스냅샷과 그날 종가만 쓴다. 그날 스냅샷이 없으면 그날은 NOT_AVAILABLE, 거래 없음. 재생 결과는 매번 같아야 한다(결정적 계산).

### 4.7 저장
- 사용자 구글 시트에 탭 추가 [D-10]: `VirtualA`, `VirtualB`(거래: 날짜, 종목, 매수/매도, 금액, 수량, 사유 코드, 규칙 버전), `VirtualFlags`(보류·제외 플래그).
- 체결가는 같은 날짜 일봉으로 다시 계산 가능하므로 시트에는 수량·금액·날짜만 둔다.
- 공개 저장소·Pages·Actions 로그에는 가상 장부, 가격, 손익을 넣지 않는다. 공개되는 것은 가격 없는 Q·G 스냅샷과 규칙 버전 문서뿐이다.
