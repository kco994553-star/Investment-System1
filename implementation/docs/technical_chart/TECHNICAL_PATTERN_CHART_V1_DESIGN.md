## 1. 목적과 범위

### 1.1 목적

두 가지 용도를 처음부터 같은 구조에서 지원한다. 구현은 단계별로 한다.

| 용도 | 무엇을 돕는가 |
| --- | --- |
| 장기 보유 | 신규 진입 검토, 추가 매수 검토, 위험 점검 |
| 스윙 (수일~수주) | 진입 조건, 무효화 기준, 청산 시나리오, 판단 기록 |

두 모드는 같은 봉 모델·같은 패턴 엔진·같은 공식 탐지 이력을 쓴다. 모드는 화면 강조점과 기록 양식만 다르다.

### 1.2 범위

- 초기 시간 단위는 **일봉과 주봉만**이다.
- 판단은 **완결된 봉**으로만 한다. 진행 중인 봉은 화면에 "잠정"으로 표시한다.
- 분봉·실시간·주문 연동은 범위 밖이다.
- 주문·매매·자금 이동 기능은 **어떤 단계에서도 만들지 않는다.** "매수" 버튼, 증권사 연결, 주문 전송 경로를 두지 않는다. 화면 문구는 "가정 진입", "주문 아님"을 쓴다.
- 패턴은 QGV 점수와 TARGET 규칙을 바꾸지 않는다. 나란히 보여 줄 뿐이다.

### 1.3 단계

| 단계 | 내용 |
| --- | --- |
| 1단계 | 확대·이동·측정·십자선 / 일봉↔주봉 전환(날짜 범위 유지) / 캔들+거래량 / 스윙 고점·저점 구조 / 지지·저항 가격 구간 / 박스 상향 돌파·하향 이탈 / 이중 바닥·이중 천장 / 패턴 카드 / 모든 신호의 확인·실패·무효화·만료 상태 / 미래 정보 누출·과거 신호 변경 내부 테스트 |
| 2단계 | 되돌림(리테스트)·돌파 실패 상세 / 스윙 손익비·수량·시나리오 비교 / 사용자 리플레이와 판단 기록 / 장기·스윙 기록과 집계 분리 |
| 3단계 | 삼각형, 깃발·페넌트, 머리어깨·역머리어깨 / 그 밖의 패턴은 정의·검증 부담 순으로 우선순위 |

## 3. 재사용과 신규 범위

### 3.1 그대로 재사용

- Worker `private-history/1` 응답과 `PrivateHistory.validateHistory` 검증 규칙.
- Google 세션·승인 Origin·RAM 전용·`pagehide` 정리 규칙.
- `PriceStore`의 요청 큐(`exclusive`)·간격·재시도 규칙. 차트 요청도 같은 큐를 탄다.
- `ResearchIndicators.calculate`의 ATR14(RAW 기준). 패턴 허용오차의 단위로 쓴다. 새 ATR 구현을 만들지 않는다.
- 기존 SVG 렌더러. 대체 경로(라이브러리 실패·시험용)로 남긴다.
- 일별 가격 표(`data-history-table`). 접근성 대체 표로 넓힌다.
- 기존 "QGV 맥락 (격리 · 공식 점수 아님)" 섹션 원칙. 합치지 않고 나란히.
- JS 순수 모듈 + Python 참조 구현 + 고정 벡터 방식(`playbook-engine.js`↔`qgv/playbook.py`, `price-store.js`↔`qgv/price_store.py`와 같은 방식).
- 설정 파일 방식(`playbook-config-defaults.js`↔`playbook_v1.json`). 패턴 파라미터도 같은 방식으로 둔다.
- calc_version 원칙. 규칙 버전이 다르면 이력과 집계를 섞지 않는다.

### 3.2 새로 만드는 것

- 봉 모델 모듈: 정규화, 주봉 생성, 완결·잠정 판정, 자료 품질 표시.
- 패턴 엔진(순수 함수): 피벗, 구간, 박스, 이중 바닥·천장, 상태 기계.
- 공식 탐지 이력: 추가만 하는 상태 전이 기록, 중복 처리, 규칙 버전.
- 렌더러 어댑터와 Lightweight Charts 렌더러.
- 상호작용: 십자선, 측정, 길게 누르기, 선택 패턴 강조.
- 패턴 카드 UI.
- 종목 범위 해석기(보유+TARGET+관심)와 요청 중복 제거.
- 2단계: 사용자 가정 층, 스윙 계산기, 판단 기록, 리플레이, 집계.
- 시험: PIT 접두 불변성, 미래 변형, 잠정 봉, 주봉 경계, JS↔Python 벡터, 네트워크 기록 시험.

| 접근성 | 캔버스 기반이다. `aria-` 속성·`tabIndex` 설정이 없다. 접근성은 우리 DOM 층이 맡아야 한다. |
| 모바일 | 터치 이동·핀치 확대(`handleScroll`·`handleScale`), 관성 스크롤, 길게 누르기 추적 모드(`trackingMode`)가 있다. |
| 확장 | v5 다중 pane(`addPane`, 거래량 분리), 시리즈 마커(`createSeriesMarkers`), 사용자 그리기 primitive(`ISeriesPrimitive`). 구간·박스·강조를 그릴 수 있다. 측정 도구는 없다. 직접 만든다. |

정적 검색은 증명이 아니다. "번들했으니 비공개가 검증됐다"고 말하지 않는다. §4.5의 실제 네트워크 시험이 통과해야 한다.

### 4.3 권장

**Lightweight Charts 5.2.1을 렌더링 층으로만 채택한다. 전면 재작성은 하지 않는다.**

이유:

1. 1단계 필수 기능(확대·이동·십자선·모바일 길게 누르기·거래량 pane)이 내장돼 있다. SVG로는 사실상 차트 라이브러리를 새로 만들게 된다.
2. 캔버스라 1500봉 이동·확대가 모바일에서 가볍다.
3. 기존 실험에서 같은 버전으로 360·390·1280px 동작을 이미 확인했다.
4. 정적 검토상 네트워크·저장 API가 없다. 로고를 끄면 CSP도 그대로다.
5. 데이터 경로·지표·카드·검증 규칙은 그대로 두고 렌더러만 바꾼다.

조건:

- 버전 5.2.1 고정. 자동 업그레이드 금지. 올릴 때는 이 표를 다시 채운다.
- CDN을 쓰지 않는다. Pages에 파일로 포함한다. `pages_artifact_guard.py`에 SHA-256을 고정한다.
- LICENSE, NOTICE(업스트림 v5.2.1 바이트 그대로), 제3자 고지(fancy-canvas MIT, tslib 0BSD)를 Pages에 함께 둔다.
- `attributionLogo:false`. 차트 바로 아래에 NOTICE 문구와 TradingView 링크를 텍스트로 표시한다. 링크는 `rel="noopener noreferrer"`, 추가 파라미터 없음. 이것이 README의 "사용자가 보는 페이지에 링크" 요구를 충족한다고 해석한다. 구현 PR에서 문구를 다시 확인한다.
- 기존 TradingView 위젯은 **기본 꺼짐 결정을 유지**한다. 패턴 차트는 위젯과 다른 것임을 화면에 적는다("TradingView 위젯 아님 · 이 기기에서 그림").
- 렌더러 어댑터 뒤에 둔다. 기존 SVG 렌더러는 대체 경로로 남긴다. 동등성 시험을 통과하면 기본을 바꾼다(§18 Q6).

### 4.4 어댑터 계약 (렌더러가 아는 것만)

렌더러는 화면용 값만 받는다. 패턴 판단을 하지 않는다.

- 입력: 봉 배열(날짜·OHLCV·완결 여부), 오버레이 목록(선·구간·박스·마커, 각 객체의 출처 `AUTO`·`USER_ASSUMPTION`), 선택 객체 id, 보이는 날짜 범위.
- 출력 이벤트: 십자선 위치(봉 index·날짜), 보이는 범위 변경, 객체 선택, 측정 시작·끝.
- 렌더러는 네트워크·저장소·QGV·패턴 엔진을 호출하지 않는다.

### 4.5 실제 네트워크 시험 계획

목표: 차트 표시 중 **TradingView로 종목·가격이 가지 않음**을 실제 요청 기록으로 보인다.

1. Playwright 컨텍스트 전체 요청을 **막지 않고 기록**한다. `page.on('request')`, `context.on('request')`, CDP `Network`(서비스 워커·prefetch·beacon·WebSocket 포함).
2. 합성 봉을 넣고 일봉·주봉 전환, 확대·이동, 십자선, 길게 누르기, 카드 선택, 측정을 모두 실행한다.
3. 판정:
   - `tradingview.com`, `tradingview-widget.com`, 그 밖의 제3자 호스트로 가는 요청 0건.
   - 모든 요청 URL·헤더·본문에 시험 종목 코드와 시험 가격 문자열이 없다. 단, 비공개 Worker로 가는 기존 이력 요청은 따로 분류한다(라이브러리 동작이 아니다).
   - `Referer`가 붙은 제3자 이동 0건.
4. 대조군: 위젯을 켠 실행을 따로 돌려 위젯 요청이 잡히는지 확인한다. 기록 장치가 실제로 잡는다는 증거다.
5. 실제 기기: 사용자 기기에서 원격 디버깅으로 HAR를 받아 같은 판정을 한다. HAR는 저장소에 올리지 않는다. 개수·호스트 이름만 보고한다.
6. CSP 위반 콘솔 0건도 함께 본다. CSP는 방어선이지 증명이 아니다.

## 6. 가격 데이터와 비공개 경계

### 6.1 초기 종목 범위

- 보유 종목(기기 ACTUAL), TARGET(현재 v0 19, 확정 후 v1), 관심 종목(기기 즐겨찾기)만.
- 세 목록의 합집합을 Worker 기호로 바꾸고 중복을 없앤다. Worker 허용 목록 밖이면 `WORKER_ALLOWLIST`로 NA.
- 지금 `PrivateHistory`는 TARGET 19만 허용한다. 보유·관심 종목을 받으려면 허용 목록을 Worker 시장 목록 기준으로 넓혀야 한다(1단계 작업 P1-11).
- 504 전체 확장은 Worker 호출량·기기 메모리·성능을 보고한 뒤에만 한다(§6.4).

### 6.2 경계 (기존 결정 유지)

- 가격과 가격 파생값(피벗 가격, 구간 경계, 패턴 상태, 손익비)은 기기 RAM, 비공개 Worker, 사용자 비공개 시트에만 있다.
- 공개 저장소·Pages 데이터·Actions 로그·아티팩트·공개 JSON에 넣지 않는다. 오류 메시지·콘솔·관측 로그에도 값을 넣지 않는다. 코드와 개수만 쓴다.
- localStorage·sessionStorage·서비스 워커 캐시에 가격을 넣지 않는다.
- 기기 백업은 지금처럼 가격 없는 상태를 유지한다.
- 근거: GSQ-007~010, GSQ-023(기기 RAM + 사용자 비공개 시트), 기존 `price-store.js`·`private-history.js` 규칙.

### 6.3 요청 규칙

- 사용자가 차트를 열거나 버튼을 누를 때만 요청한다(§18 Q4). 여러 종목 점검도 명시적 버튼 동작으로만 요청하고, 기존 큐·간격·허용 목록·중복 방지 규칙을 그대로 쓴다. 클릭 방식만으로 공급자 이용 조건 준수가 입증된다고 표현하지 않는다.
- 종목당 세션에 **5y 한 번**을 기본으로 한다. 일봉 약 1260봉(상한 1500 안)으로 일봉·주봉을 모두 만든다. 응답은 약 150KB 수준으로 Worker 상한 512KB 안이다.
- RAM 캐시 키는 기호. 이미 받은 범위가 요청 범위를 덮으면 다시 받지 않는다.
- 같은 세션에서 새 봉이 완결된 뒤 갱신이 필요하면 `1mo`만 받아 날짜로 합친다. 이미 있는 날짜의 값이 다르면 덮어쓰지 않고 `PRICE_REVISED` 코드를 남긴다. 공식 이력에는 `DATA_REVISION` 전이를 추가한다(§8.6).
- 모든 요청은 `PriceStore`의 같은 큐·간격(5.2초)·재시도 규칙을 탄다. 가상매매 실행과 겹치지 않는다.
- `Prices_D`의 종가는 원시 종가 일치 확인에만 쓴다. 캔들은 만들 수 없다.

### 6.4 504 확장 전 보고 항목 (추정과 측정 방법)

| 항목 | 현재 추정 | 측정 방법 |
| --- | --- | --- |
| Worker 호출 수 | 종목당 1건. 40종목이면 간격 5.2초로 약 3.5분. 504종목이면 약 44분. 분당 12건 상한에 걸린다. | 실행 보고에 요청 수·RATE_LIMITED 수·총 소요 시간(개수만). |
| 기기 메모리 | 봉 1개 객체 약 100~150바이트 가정. 504×1260봉 ≈ 63만 봉 ≈ 64~95MB. 모바일에서 위험. | `performance.memory`(지원 브라우저)와 실제 기기에서 단계별 측정. |
| 계산 시간 | 미측정. | 종목당 패턴 엔진 실행 시간 분포(중앙값·최대). |
| 저장 | 1단계는 기기 RAM만 쓴다(결정 Q1=A). 5년 조회는 최대 활용 범위다. | 실제 요청 범위(봉 수)·중복 요청 방지 건수·메모리 사용량을 측정해 보고한다(P1-12). |

이 표를 채워 보고하기 전에는 504로 넓히지 않는다.

## 7. 봉 모델

### 7.1 일봉

- 필드: 세션 날짜(거래소 현지 날짜), 원시 open·high·low·close, adjusted_close(별도), volume, session_status(COMPLETE·IN_PROGRESS·UNKNOWN), 출처, read_at.
- 세션 날짜: Tiingo·KRX는 `session_date`를 쓴다. Yahoo는 timestamp를 거래소 시간대로 바꾼다(기존 `sessionDate`와 같은 규칙).
- 패턴 탐지에는 **COMPLETE 봉만** 쓴다. IN_PROGRESS·UNKNOWN은 화면에만 "잠정"으로 그린다(외곽선만, 텍스트 "잠정").
- 대체 출처의 당일 봉은 기존 규칙대로 UNKNOWN이다. 완결로 올리지 않는다.

### 7.2 원시 OHLC와 조정 종가

- 패턴 엔진은 **원시 OHLC와 원시 종가만** 쓴다. adjusted_close를 섞지 않는다.
- 캔들의 close만 조정값으로 바꾸지 않는다. 봉 안의 기준이 달라지기 때문이다.
- adjusted_close는 장기 수익률 비교 같은 별도 표시에만, 별도 이름으로 쓴다.

### 7.3 기업행사와 가격 기준 연속성 (사용자 결정 Q3, 2026-10-17)

- 현재 Worker 응답에는 분할·배당 이벤트 목록이 없다. 원시 OHLC에서 분할 전후 가격 단위가 다를 수 있다.
- 기존 설계(`technical_live_data/DESIGN.md` §3.3)는 새 조정 방법이나 임의 기준의 불연속 판정을 금지한다. 이를 따른다. 가격을 임의로 보정하지 않는다.
- **1단계부터 적용한다.** 가격 기준의 연속성을 확인하지 못한 창은 정상 패턴으로 판정하지 않는다. 그 창의 객체는 `PRICE_BASIS_CONTINUITY_UNCONFIRMED`로 **판정 불가**이고, 카드에 사유를 표시한다. "미확인" 문구만 붙여 정상 판정하지 않는다.
- 연속성 확인에는 분할 이벤트가 필요하다. 그래서 Worker 분할 이벤트 PR(별도 PR)을 **1단계 의존 작업 P1-W**로 앞당긴다(§16.1).
  - P1-W가 들어오면 분할 효력일을 패턴 창의 경계로 쓴다. 창이 분할일을 가로지르면 `CORPORATE_ACTION_IN_WINDOW`로 판정 불가다. 가격을 다시 계산해 이어 붙이지 않는다.
  - P1-W 전이나 이벤트 조회가 실패한 종목은 창 전체가 연속성 미확인이므로 판정 불가다.
- 배당은 원시 OHLC 단위를 바꾸지 않으므로 연속성 판정 대상이 아니다. 조정 종가와 섞지 않는 원칙(§7.2)은 그대로다.

### 7.4 주봉

- 완결 일봉만 모은다. 묶음 기준은 세션 날짜의 ISO 주(월~일)다.
- O = 주 첫 세션 open, H = 최댓값 high, L = 최솟값 low, C = 마지막 세션 close, V = 합계.
- 그 주의 한 봉이라도 OHLC가 없으면 주봉 OHLC는 NA다. 거래량이 하나라도 없으면 주봉 거래량은 NA다. 부분 합을 쓰지 않는다. 실제 0 거래량과 결측을 구분한다.
- **주 완결 규칙 W1** (거래소 달력 없이 판정):
  - 그 주 금요일 세션 봉이 COMPLETE이면 완결이다. 미국·한국·일본 정규장은 토·일 세션이 없다.
  - 아니면 다음 주 이후의 COMPLETE 일봉이 처음 나타날 때 완결이다(금요일 휴장 등).
  - 그 전에는 잠정 주봉이다. 진행 중 일봉이 섞인 주도 잠정이다.
- 주봉의 `known_at`은 완결을 알게 된 일봉 세션 날짜다. 금요일 완결이면 그 금요일, 휴장으로 미뤄지면 다음 주 첫 세션이다.
- W1은 달력 추정보다 늦을 수 있다. 대신 미래 정보를 쓰지 않는다.

### 7.5 결측과 갭

- 결측 봉(OHLC null): 보간하지 않는다. 피벗 판정 창(좌우 k봉) 안에 결측이 있으면 그 피벗은 판정하지 않는다. 패턴 창 안에 결측이 있으면 그 객체는 `MISSING_BARS_IN_WINDOW`로 NA다.
- 가격 갭(전일 종가와 시가 차이)은 실제 가격이다. 그대로 쓴다. 시가가 이미 경계를 넘은 돌파는 카드에 "갭 돌파"로 표시한다. 스윙 진입 가정에 영향을 준다(§12.2).
- 세션 누락(공급자가 하루를 빠뜨림)은 날짜 간격만으로 판단하지 않는다. 달력이 없기 때문이다. 대신 `Prices_D` 종가와 날짜 집합이 다르면 `SESSION_SET_MISMATCH`를 자료 품질에 표시한다.

### 7.6 최소 봉 수

부족하면 그 항목은 `INSUFFICIENT_BARS`로 NA다. 0이나 대체값을 넣지 않는다.

| 항목 | 일봉 최소 | 주봉 최소 | 근거 |
| --- | --- | --- | --- |
| ATR14 | 15 | 15 | 기존 정의(첫 TR은 2번째 봉, 14개 평균) |
| 피벗 | 2k+1 = 7 | 2k+1 = 5 | 좌우 k봉 |
| 지지·저항 구간 | ATR 15 + 구간 조회 창 | 같음 | §9.3 |
| 박스 | ATR 15 + 최소 길이 + k | 같음 | §9.4 |
| 이중 바닥·천장 | ATR 15 + 최소 간격 + 2k | 같음 | §9.5 |
| 거래량 참고 조건 | 20 | 10 | §9.6 |

## 8. 패턴 공통 규칙

### 8.1 상태 기계

모든 **신호**(박스 돌파·이탈, 이중 바닥·천장)는 같은 상태를 쓴다.

| 상태 | 뜻 | 들어가는 조건 |
| --- | --- | --- |
| CANDIDATE (형성 중) | 일부 조건만 충족 | 화면에만 표시. 공식 이력에 쓰지 않는다. 검증 표본이 아니다. |
| FORMED (형성 완료·확인 대기) | 형성 조건 모두 충족 | 마지막 형성 조건이 알려진 완결 봉 |
| CONFIRMED (확인) | 확인 조건 충족 | 확인 조건을 만족한 완결 봉 |
| FAILED (확인 후 실패) | 확인 뒤 실패 창 안에 되돌아옴 | 되돌아온 완결 봉 |
| INVALIDATED (무효화) | 확인 전 무효화 기준 돌파 | 무효화 완결 봉 |
| EXPIRED (만료) | 확인 전 최대 대기 초과 | 대기 한도를 넘긴 완결 봉 |

- CONFIRMED 뒤 실패 창이 끝날 때까지 FAILED가 없으면 "확인 유지(관찰 창 종료)"를 덧붙인다. 상태는 CONFIRMED 그대로다.
- 종료 상태: FAILED, INVALIDATED, EXPIRED, 관찰 창이 끝난 CONFIRMED.
- 내부 전이 SUPERSEDED: 중복 처리나 피벗 교체 때 쓴다. 신호 결과가 아니다.
- 지지·저항 구간은 신호가 아니라 **구조 객체**다. 상태는 ACTIVE, BROKEN, EXPIRED다. 구간 이탈 신호와 되돌림은 2단계에서 신호로 만든다.

### 8.2 "알 수 있게 된 시점"

모든 전이는 두 시각을 가진다.

- `known_at`: 그 사실을 알게 되는 **완결 봉의 세션 날짜**. 판정의 기준이다.
- `computed_at`: 기기에서 계산한 실제 시각. 감사용이다.

피벗은 미래 k봉이 있어야 확정된다. 그래서 봉 i의 피벗은 `known_at = 봉 i+k`다. 피벗이 생긴 봉 날짜(`anchor_at = 봉 i`)와 따로 적는다. 카드와 검증은 `known_at`을 쓴다.

### 8.3 판정 기준값 고정

- 확인·무효화 기준가는 **FORMED가 된 시점의 ATR**로 계산해 고정한다. 이후 ATR이 바뀌어도 기준가를 다시 계산하지 않는다.
- 카드에 고정된 기준가와 그때의 ATR 날짜를 보여 준다.

### 8.4 중복 탐지

- 객체 id = 기호 + 시간 단위 + 패턴 종류 + 규칙 버전 + 기준 피벗들의 `anchor_at`. 같은 id는 같은 객체다.
- 이중 바닥: 새 두 번째 저점(P2)이 알려질 때 가장 가까운 과거 저점부터 조건을 본다. 처음 맞는 P1 하나만 쓴다. P2 하나에 후보 하나다.
- 박스: 같은 시간 단위·종류에서 FORMED 박스는 한 번에 하나다. 새 박스가 기존 박스와 기간이 겹치면 새 박스는 기존 박스가 종료 상태가 된 뒤에만 만든다.
- 같은 날 같은 종류로 확인된 여러 신호는 검증에서 하나의 "사건 묶음"으로 센다(§14.2).

### 8.5 갱신 정책

- 공식 이력은 **추가만** 한다. 과거 전이를 고치거나 지우지 않는다.
- 새 봉이 들어오면 새 전이만 붙는다.
- 접두 불변성: 날짜 t까지 자료로 계산한 이력 = 전체 자료로 계산한 이력 중 `known_at ≤ t`인 부분. 이것이 깨지면 버그다(§13).

### 8.6 자료 수정

- 공급자가 과거 봉 값을 바꾸면 이력을 다시 쓰지 않는다.
- `DATA_REVISION` 전이를 그 시점에 추가한다. 영향을 받은 객체에 "자료 수정 후 재계산 결과 다름" 표시를 붙인다.
- 재계산 결과는 별도 "수정 자료 기준" 보기로만 보여 준다.

### 8.7 규칙 버전

- `pattern-rules/1`. 파라미터 묶음의 정규 JSON SHA-256을 함께 기록한다.
- 규칙·파라미터를 바꾸면 새 버전이다. 버전이 다르면 이력·집계를 섞지 않는다. 이전 버전 이력은 보존한다.
- 사용자가 화면에서 파라미터를 바꿔 보는 것은 "사용자 설정 실행"이다. 공식 이력에 쓰지 않는다(§11.4).

## 9. 패턴 정의 (1단계)

모든 정의는 완결 봉만 쓴다. 가격은 원시 OHLC다. ATR(t)는 봉 t 종가 시점의 ATR14다.

### 9.1 스윙 피벗

- 입력: high, low, ATR. 최소 봉: §7.6.
- 피벗 고점 후보: 봉 i의 high가 앞 k봉의 high보다 **크고**, 뒤 k봉의 high **이상**이다. 같은 값이면 앞의 봉을 쓴다(동률 규칙). 피벗 저점은 반대.
- 알게 되는 시점: 봉 i+k 완결.
- 진폭 필터(SWING_MIN_ATR, 추가 전용):
  - 확정된 피벗 목록은 고점·저점이 번갈아 나온다.
  - 새 후보가 마지막 확정 피벗과 반대 종류이면 진폭 ≥ SWING_MIN_ATR × ATR(i+k)일 때만 확정한다.
  - 새 후보가 같은 종류이고 더 극단이면(더 높은 고점), 새 피벗을 확정하고 이전 피벗에 SUPERSEDED 전이를 `known_at = i+k`로 붙인다. 이전 기록은 지우지 않는다.
  - 같은 종류이고 덜 극단이면 버린다.
- 결측: 판정 창 안에 결측 봉이 있으면 판정하지 않는다.
- 산출: 피벗 목록(anchor_at, known_at, 종류, 가격), 구조 설명.
- 구조 설명: 마지막 두 고점·두 저점으로 "고점·저점 상승", "고점·저점 하락", "혼재" 중 하나. **국면 판정이 아니다.** 기존 카드의 "승인된 국면 정의 없음"은 그대로 둔다.

### 9.2 일봉·주봉 일치

- 주봉 구조 설명과 주봉 구간을 일봉 신호 옆에 둔다.
- 일치: 일봉 상향 신호 + 주봉 "고점·저점 상승"이고 주봉 저항 구간 아래가 아님.
- 충돌: 일봉 상향 신호인데 주봉 "고점·저점 하락"이거나 가격이 주봉 저항 구간 안·바로 아래.
- 중립: 그 밖. 주봉 자료 부족이면 NA.
- 하향 신호는 반대로 본다. 이 판정은 표시용이다. 점수나 확률이 아니다.

### 9.3 지지·저항 가격 구간

- 입력: 확정 피벗(고점은 high, 저점은 low), ATR. 조회 창 ZONE_LOOKBACK.
- 찾는 법: 시점 t에서 `known_at ≤ t`이고 창 안에 있는 피벗 가격을 정렬한다. 이웃 간격 ≤ ZONE_TOL_ATR × ATR(t)이면 같은 묶음이다(단일 연결). 묶음 폭이 2 × ZONE_TOL_ATR × ATR(t)를 넘으면 가장 큰 간격에서 나눈다.
- 구간: 묶음 가격의 최솟값~최댓값. 덧붙이는 여유폭 없음.
- 형성: 접촉 수 ≥ ZONE_MIN_TOUCHES. 고점·저점이 섞이면 "역할 혼재"로 표시한다.
- 상태:
  - ACTIVE: 형성됨.
  - BROKEN: 완결 종가가 구간 밖으로 BREAK_BUFFER_ATR × ATR(형성 시점) 이상 벗어남. 방향을 기록한다.
  - EXPIRED: 마지막 접촉이 조회 창 밖으로 밀려남.
- 표시: 시점마다 다시 계산하지 않는다. 새 피벗이 알려질 때만 다시 묶는다. 묶음이 바뀌면 이전 구간에 SUPERSEDED, 새 구간을 추가한다.
- 접촉 수는 표시용이다. "강도 점수"나 확률로 바꾸지 않는다.

### 9.4 박스(범위) 상향 돌파·하향 이탈

- 입력: 확정 피벗, 완결 종가, ATR.
- 형성 조건(시점 t, 모두 충족):
  1. 창 [s, t]의 길이가 BOX_MIN_BARS 이상 BOX_MAX_BARS 이하.
  2. 창 안 확정 피벗 고점 2개 이상이 상단 띠 [U − ZONE_TOL_ATR×ATR, U] 안. U = 창 안 피벗 고점 최댓값.
  3. 창 안 확정 피벗 저점 2개 이상이 하단 띠 [L, L + ZONE_TOL_ATR×ATR] 안. L = 창 안 피벗 저점 최솟값.
  4. 창 안 모든 완결 종가가 [L, U] 안. 고가·저가가 잠깐 넘는 것은 허용한다.
  5. 높이 U − L이 BOX_HEIGHT_ATR 최소~최대 × ATR.
  - s는 조건 2·3을 만족하는 가장 이른 피벗의 anchor_at이다.
  - ATR은 FORMED 시점 값으로 고정한다.
- 알게 되는 시점: 마지막 조건을 채운 피벗의 `known_at`(또는 그 뒤 첫 완결 봉).
- 확인:
  - 상향 돌파 CONFIRMED: 완결 종가 > U + BREAK_BUFFER_ATR × ATR.
  - 하향 이탈 CONFIRMED: 완결 종가 < L − BREAK_BUFFER_ATR × ATR.
  - 박스 하나에서 두 신호 중 먼저 확인된 하나만 남는다. 다른 하나는 같은 봉에 INVALIDATED다.
- 실패: 확인 뒤 FAIL_WINDOW 안에 완결 종가가 다시 [L, U] 안이면 FAILED.
- 무효화: 확인 전, 반대쪽 확인이 먼저 나면 그 방향 신호가 INVALIDATED다. 카드의 무효화 기준가는 상향 신호는 L − 여유, 하향 신호는 U + 여유다.
- 만료: 창 길이가 BOX_MAX_BARS를 넘을 때까지 확인이 없으면 EXPIRED.
- 거래량: 확인 봉 거래량 ≥ VOL_MULT × 최근 VOL_AVG_N 평균이면 "거래량 동반", 아니면 "거래량 미동반", 결측이면 NA. 확인을 막지 않는다.
- 갭: 확인 봉 시가가 이미 기준가 밖이면 "갭 돌파".
- 중복: §8.4.

### 9.5 이중 바닥·이중 천장

이중 바닥 기준이다. 이중 천장은 위아래를 바꾼다.

- 입력: 확정 피벗 저점 P1, P2와 그 사이 피벗 고점 H, 완결 종가, ATR.
- 형성 조건(P2가 알려진 시점 t = known_at(P2)):
  1. 간격: DB_SEP_MIN ≤ anchor(P2) − anchor(P1) ≤ DB_SEP_MAX (봉 수).
  2. 높이 차: |P2 − P1| ≤ DB_TOL_ATR × ATR(t).
  3. 깊이: H − max(P1, P2) ≥ DB_DEPTH_ATR × ATR(t). H는 P1·P2 사이 확정 피벗 고점의 최댓값. 넥라인 = H.
  4. P1·P2 사이 완결 종가가 min(P1, P2) 아래로 내려가지 않음.
  5. P2 이후 t까지 완결 종가가 넥라인 위로 확인되지 않음(이미 넘었으면 형성 전에 지나간 것으로 보고 만들지 않는다).
- 선택: §8.4. P2 하나에 가장 가까운 P1 하나.
- 확인: 완결 종가 > H + BREAK_BUFFER_ATR × ATR(t). 이 봉이 확인 봉이다.
- 실패: 확인 뒤 FAIL_WINDOW 안에 완결 종가 < H.
- 무효화: 확인 전 완결 종가 < min(P1, P2) − BREAK_BUFFER_ATR × ATR(t).
- 만료: P2가 알려진 뒤 (anchor(P2) − anchor(P1))봉 안에 확인이 없으면 EXPIRED. 패턴 폭과 같은 대기다. 새 파라미터가 아니다.
- 의도적으로 넣지 않은 조건: 앞선 하락 추세 요구. 파라미터를 늘리기 때문이다. 3단계 이후 변형으로 따로 검증한다.
- 거래량·갭 표시: §9.4와 같다.

### 9.6 거래량 참고 조건

- 평균은 확인 봉 **이전** VOL_AVG_N개 완결 봉의 거래량 평균이다. 확인 봉을 넣지 않는다.
- 결측이 섞이면 평균은 NA다.
- 이 값은 근거 표시만 한다. 확률·점수로 바꾸지 않는다.

### 9.7 잠정 봉 미리보기

- 진행 중 봉이 기준가를 넘은 상태면 카드에 "잠정 봉 기준 조건 충족 · 확정 아님"을 쓸 수 있다.
- 이력·검증·기록에 쓰지 않는다. 다음 화면 갱신 때 사라질 수 있다.

## 10. 패턴 정의 (2·3단계 개요)

상세 정의는 해당 단계 설계에서 이 문서와 같은 형식(입력·최소 봉·찾는 법·형성·확인·알게 되는 시점·실패·무효화·만료·결측·기업행사·잠정 봉·중복·버전·파라미터 근거·민감도)으로 쓴다.

### 10.1 2단계: 되돌림과 돌파 실패

- 되돌림: 상향 확인 뒤 R봉 안에 완결 봉 저가가 [U − 여유, U + 여유] 안에 들어오고, 종가가 U − 여유 위에서 끝남. 이후 그 봉 고가를 넘는 완결 종가가 나오면 "되돌림 유지 확인".
- 돌파 실패 상세: FAILED의 깊이(구간 안 어디까지), 반대쪽 경계 도달 여부, 걸린 봉 수.
- R은 FAIL_WINDOW 배수 중에서 고르고 근거와 민감도를 적는다. 새 상수를 늘리지 않는 쪽을 먼저 검토한다.
- 지지·저항 구간 이탈과 역할 전환(저항→지지)을 신호로 올린다.

### 10.2 3단계 후보와 우선순위

| 패턴 | 핵심 정의 요소 | 정의·검증 부담 |
| --- | --- | --- |
| 삼각형(대칭·상승·하강) | 낮아지는 고점 2개 이상 + 높아지는 저점 2개 이상, 피벗을 지나는 두 추세선, 수렴점 | 중간: 선 맞춤 허용오차, 수렴점 거리 |
| 깃발·페넌트 | 짧은 기간의 큰 움직임(깃대) + 반대 방향 좁은 통로 | 중간~높음: 깃대 크기·기간, 되돌림 비율 |
| 머리어깨·역머리어깨 | 세 피벗(가운데 가장 극단), 어깨 높이 허용오차, 두 골짜기를 지나는 넥라인, 넥라인 기울기 한도 | 높음: 파라미터 많음, 표본 적음 |
| 컵앤핸들, 쐐기, 원형 바닥, 채널 | 곡선·선 맞춤, 길이 | 높음 |
| 캔들 패턴(장악형 등) | 1~3봉 규칙 | 정의는 쉽지만 표본이 많아 다중 검정 부담이 크다 |

순서 제안: 삼각형 → 머리어깨 → 깃발·페넌트 → 나머지. 이유: 삼각형은 1단계 피벗을 그대로 쓴다. 머리어깨는 이중 바닥 구조를 확장한다. 깃발은 새 개념(깃대)이 필요하다.

## 11. 패턴 카드와 상호작용

### 11.1 카드 필드

| 필드 | 내용 |
| --- | --- |
| 이름·시간 단위 | 예: "박스 상향 돌파 · 일봉" |
| 현재 상태 | §8.1 상태 + 마지막 전이의 known_at |
| 탐지 근거 | 기준 피벗 날짜, 접촉 수, 고정 ATR과 그 날짜, 거래량 동반 여부, 갭 여부 |
| 미충족 조건 | CANDIDATE·FORMED일 때 남은 조건 목록 |
| 무효화 | 기준가와 조건 문장. 예: "완결 종가가 박스 하단 − 여유 아래" |
| 일봉·주봉 | 일치·충돌·중립·NA와 그 이유 |
| 자료 품질 | 출처, read_at, 지연 UNKNOWN, 결측, 자료 수정, 세션 집합 불일치. 가격 기준 연속성 미확인·창 안 기업행사는 품질 표시로 끝내지 않고 **판정 불가**와 사유로 표시한다(§7.3, 결정 Q3). |
| 투자 유용성 | **"미검증"** 고정(§14.2 연구 완료 전). "형태 일치 ≠ 상승 확률"을 함께 쓴다. |
| 규칙 버전 | `pattern-rules/1` + 파라미터 해시 앞 8자 |

금지:

- 검증되지 않은 성공 확률, 승률, 신뢰도 %, 별점, 강도 점수.
- 형태 적합도를 상승 가능성처럼 쓰는 문구.
- 접촉 수·거래량 배수를 점수로 합치는 것.

### 11.2 카드와 차트 연동

- 카드를 고르면 차트가 패턴 범위로 확대한다. 범위 = 첫 기준 피벗 ~ 확인 봉(없으면 마지막 봉), 앞뒤로 패턴 폭의 20% 여유. 이 여유는 화면용이다. 탐지와 무관하다.
- 강조: 기준 피벗 마커, 경계선·박스, 확인 봉(마커 + 세로 띠), 무효화 기준선(점선).
- 고른 패턴만 보인다(기본). "모든 패턴 보기"를 켜면 나머지는 흐리게 보인다.
- 아무것도 고르지 않으면 지지·저항 구간과 최근 신호 3개까지만 보인다.

### 11.3 조작

- 데스크톱: 휠 확대, 끌기 이동, 마우스 십자선, Shift+끌기 측정.
- 모바일: 핀치 확대, 끌기 이동, **길게 누르기 → 십자선 추적**. 추적 중 상단 고정 칸에 날짜, O/H/L/C, 거래량, 봉 상태(확정·잠정), 그 봉에서 바뀐 패턴 상태를 보여 준다.
- 측정: 두 점의 가격 차, 비율, 봉 수, 달력 일수, ATR 배수.
- 키보드: 차트 초점에서 ←/→ 한 봉, Shift+←/→ 열 봉, +/− 확대, Home/End 처음·끝, Enter 십자선 위치의 객체 선택.
- 일봉↔주봉 전환: 보이는 날짜 범위를 유지한다. 일봉→주봉은 그 날짜를 포함한 주로, 주봉→일봉은 주의 첫·마지막 세션으로 바꾼다.

### 11.4 자동 객체와 사용자 객체

- 자동 객체: 실선, 라벨 "자동".
- 사용자 객체: 파선, 다른 색 계열, 라벨 **"사용자 가정"**.
- 자동 객체를 끌면 사용자 복사본이 생긴다. 원본 자동 객체는 그대로다.
- 사용자가 파라미터를 바꾸면 "사용자 설정 실행" 결과가 별도 층에 나온다. 공식 이력은 그대로다.
- 사용자 가정은 공식 탐지 이력을 **절대 바꾸지 않는다.** 저장 위치도 다르다(§18 Q2).

### 11.5 접근성

- 차트 컨테이너: `role="application"`이 아닌 `role="group"` + 요약 라벨(종목, 시간 단위, 보이는 기간, 선택 패턴).
- 십자선 이동은 `aria-live="polite"` 칸에 날짜·OHLCV·상태를 읽어 준다.
- 카드는 버튼·목록으로 만든다. 색만으로 상태를 나타내지 않는다(라벨·선 모양 함께).
- 대체 표: 일봉·주봉 표와 패턴 전이 표. 기존 `data-history-table`을 넓힌다.
- 390px 가로 넘침 0을 유지한다.
- SVG 대체 경로와 접근성 대체 표는 LWC 기본 전환 뒤에도 유지한다. 대체 경로에서는 기능 제한(확대·이동·측정 없음 등)을 화면에 표시한다(결정 Q6).

## 12. 장기 보유 모드와 스윙 모드

### 12.1 장기 보유 모드

- 주봉 구조·주봉 구간을 먼저 보여 준다. 일봉 신호는 시점 참고다.
- QGV 상태와 기술적 상태를 **나란히** 보여 준다. QGV v2 점수·calc_version은 기존 공개 값을 그대로 읽어 표시한다.
- 패턴은 QGV 점수·TARGET 규칙·플레이북 판단을 바꾸지 않는다. 입력으로도 쓰지 않는다.
- 기록 양식(2단계):
  - 목적: 신규 진입 검토 / 추가 매수 검토 / 위험 점검
  - 가설
  - 확인할 것
  - 재검토 조건(날짜, 봉 수, 가격 구간 도달, 패턴 상태 변화)
  - 당시 보인 패턴 id·상태 사본, QGV 표시값 사본(calc_version 포함)
- 기존 플레이북 기록과는 id로만 연결한다. 플레이북 기록 형식은 바꾸지 않는다.

### 12.2 스윙 모드 (2단계)

계산 항목:

- 가정 진입가, 무효화 가격, 목표 구간.
- 예상 손실 = 진입가 − 무효화 가격 (주당).
- 예상 이익 = 목표 구간 하단·상단 − 진입가 (범위로).
- 손익비 = 예상 이익 / 예상 손실 (범위로).
- 수량 = 사용자가 넣은 위험 금액 / 주당 예상 손실, 내림. 정수 주.

비교 시나리오:

- A. 확인 봉 종가 진입 가정.
- B. 다음 세션 시가 진입 가정(갭 반영).
- C. 되돌림 대기 지정가 가정. **미체결 가능성**을 표시한다. 되돌림이 FAIL_WINDOW 배수 안에 오지 않으면 "미체결"로 끝난다.

반드시 함께 쓰는 문구:

- "갭·슬리피지·비용 때문에 실제 손실은 무효화 가격 기준 손실보다 커질 수 있다."
- "목표 구간은 참고 구간이다. 예측이 아니다."
- "주문 아님 · 가정 계산."

규칙 유래와 사용자 가정 구분:

- 규칙 유래 기본값: 무효화 = 패턴 무효화 기준가, 목표 구간 = 박스 높이 투영(관례) 또는 다음 반대 구간. 라벨 "규칙 유래".
- 사용자가 바꾼 값은 라벨 "사용자 가정". 두 값을 같은 칸에 덮어쓰지 않는다.

시간 기준 재검토: 진입 가정 뒤 T봉 안에 목표·무효화 어느 쪽도 닿지 않으면 "재검토"로 표시한다. T는 사용자가 넣는다. 기본값을 두지 않는다(새 파라미터를 만들지 않기 위해).

## 13. 시점 일관성(PIT)과 사용자 리플레이

### 13.1 원칙

- 미래 봉으로 확정되는 피벗은 **알게 된 시점에만** 기록한다.
- 과거 날짜까지만 자료를 넣으면 그 날짜의 탐지 결과가 그대로 나와야 한다.
- 확정된 신호 이력과 그 뒤의 상태 변화는 따로 기록한다(전이 목록).
- 나중 자료로 과거 탐지를 더 이른 시점으로 옮기지 않는다.

### 13.2 내부 시험 (1단계 필수)

| 시험 | 방법 | 통과 기준 |
| --- | --- | --- |
| 접두 불변성 | 합성 시리즈 여러 개(고정 seed). 모든 t에 대해 bars[0..t]로 실행 | 결과 = 전체 실행 중 known_at ≤ t인 전이와 완전 일치 |
| 미래 변형 | t 이후 봉을 극단값·무작위로 바꿔 실행 | known_at ≤ t인 전이가 바뀌지 않음 |
| 시점 하한 | 모든 피벗 전이 | known_at ≥ anchor_at + k봉 |
| 잠정 봉 | 끝에 IN_PROGRESS·UNKNOWN 봉 추가 | 이력 변화 없음 |
| 주봉 경계 | 금요일 휴장·주 중간 결측·잠정 일봉 포함 주 | W1대로 완결 시점이 정해짐. 잠정 주는 패턴에 안 쓰임 |
| 기준값 고정 | FORMED 뒤 ATR이 크게 바뀌는 시리즈 | 확인·무효화 기준가 불변 |
| 중복 | 같은 입력 두 번, 순서 바꾼 입력 | 같은 객체 id·같은 전이 |
| 자료 수정 | 과거 봉 값을 바꾼 두 번째 응답 | 원래 전이 보존 + DATA_REVISION 추가 |
| JS↔Python | 고정 벡터 | 전이 목록 완전 일치 |
| 렌더러 누출 | 리플레이 모드 | 렌더러·DOM·접근성 표에 t 이후 봉이 없다 |

### 13.3 사용자 리플레이 (2단계)

- 시작 날짜는 기기가 적격 날짜 중 무작위로 고른다. seed를 기록한다. 사용자가 다시 뽑으면 건너뛴 날짜도 기록한다. 고른 날짜만 남기는 선택 편향을 줄이기 위해서다.
- 미래 봉은 **숨기는 것이 아니라 넘기지 않는다.** 렌더러·패턴 엔진·표에 t까지만 준다. 자동 축척으로 미래 범위가 새는 것도 막는다.
- 사용자는 판단을 먼저 저장한다. 저장 뒤에만 다음 N봉을 공개한다. 저장한 판단은 고칠 수 없다. 덧붙임만 된다.
- 리플레이 기록은 실시간 기록과 다른 종류(`REPLAY`)다. 섞어서 집계하지 않는다.
- 장기·스윙 기록을 따로 집계한다. 규칙 버전별로도 나눈다.
- 리플레이 결과는 사용자 연습 기록이다. 패턴의 투자 유용성 증거로 쓰지 않는다.

## 14. 검증: 구현 정확성 vs 투자 유용성

두 가지를 섞지 않는다.

### 14.1 (1) 구현 정확성

질문: 정의대로 찾는가? 미래 정보가 새지 않는가?

- 패턴마다 손으로 만든 합성 시리즈: 양성(정확히 맞음), 음성(조건 하나씩 어김), 경계값(허용오차 정확히 위·아래), 결측·갭·잠정 봉.
- §13.2 시험 전부.
- JS와 Python 참조 구현의 고정 벡터 일치.
- 시험 자료는 합성만 저장소에 둔다. 실제 종목 자료로는 기기에서만 돌리고 개수만 보고한다.

### 14.2 (2) 투자 유용성

질문: 확인 뒤 성과가 의미 있는가? 비용·실패를 넣어도 그런가?

이 연구는 1단계 범위 밖이다. 시작 전에 따로 사전 등록 문서를 쓰고 사용자 승인을 받는다.

- 측정: 확인 뒤 고정 기간 수익률(진입은 다음 세션 시가 가정), 최대 역행폭(MAE), 최대 순행폭(MFE), 실패·무효화 비율, 무효화 선도달 비율, 비용·슬리피지 시나리오별 결과.
- 비교 기준: 같은 종목·같은 기간의 무작위 날짜 진입, 보유 유지.
- 체리피킹 금지: 종목·기간·패턴·기간 길이를 결과를 보기 전에 고정한다. 모든 결과를 보고한다.
- 겹치는 신호: 같은 종목에서 기간이 겹치는 신호는 사건 묶음으로 센다. 겹치지 않는 부분 표본과 블록 부트스트랩을 함께 본다.
- 선택 편향: 현재 504는 살아남은 종목이다(생존 편향). TARGET 소속은 그 시점 소속으로 쓴다.
- 다중 검정: 패턴 × 파라미터 × 기간 × 시간 단위 조합 수를 적는다. 보정(예: Holm 또는 BH, 필요하면 White reality check 계열)을 적용한다. 같은 자료로 최적 파라미터를 고르고 같은 자료로 성과를 말하지 않는다.
- **보호된 Holdout의 접근 범위를 이 설계는 넓히지 않는다.** Holdout 보호 상태는 UNCONFIRMED이며 쓰지 않는다. Holdout 기간·자료를 보지 않는다.
- 가장 깨끗한 증거는 전진 관측이다. 1단계 배포 뒤 공식 이력이 쌓이는 것 자체가 사전 등록 효과를 낸다(§18 Q2와 연결).
- 결과가 나오기 전까지 카드의 "투자 유용성"은 "미검증"이다.

설계 선택 승인이다. **구현 착수 승인이 아니다.** 착수는 §15의 다섯 조건을 보고한 뒤 사용자가 따로 결정한다. 별도의 3개월 신규 기능 일괄 동결은 두지 않는다.
