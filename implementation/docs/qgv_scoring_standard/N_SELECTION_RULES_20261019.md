# N10·N15·N20 선정 규칙 정리 — 16절 · 핵심/일반 등급 · 같은 발행사 (2026-10-19)

소유자 지시(요지):
16절, 핵심/일반 등급, 이후 사용자 결정의 우선순위를 확인한다.
승인된 규칙은 적용하고 실제 충돌만 보고한다.
N별로 비중 한도 아래 구성이 가능한지 보고, 불가능하면 부족 비중과 원인을 보인다.

공식 백분위 모집단의 기존 중복 처리 규칙은 보존한다.

## 1. 요약

- **실제 충돌: 0건.** 겹치는 원문은 모두 뒤 결정이 우선순위를 명시했거나, 서로 다른 대상(R-B·R-C)이다.
- **16절을 N 선정에 적용했다.** 단일 종목 10%, 업종 묶음 40%(반도체+반도체 장비 한 묶음), 최소 10종목. N마다 동일 비중 100/N으로 검사한다.
- 업종 묶음 40%를 넘게 되는 행은 건너뛰고 다음 자격 순위가 자리를 받는다. 하위 묶음 4종목 상한과 같은 방식이다.
- 자격 행이 모자라면 채우지 않는다. 비중도 다시 나누지 않는다. 부족 비중과 원인을 보인다.
- **핵심/일반 등급은 R-C(TARGET v1) 규칙이다.** N 세트는 R-B(동일 비중)라서 비중을 바꾸지 않는다. N15에 등급 비중을 넣은 16절 검사만 참고로 보인다.
- **같은 발행사 한 자리는 승인 원문이 없다.** 선정은 바꾸지 않는다. "같은 발행사 합산 비중"을 계산해 `권장안 · 결정 필요`로 보인다.
- 현재 게시본(가격 없음)으로 보면 한도 때문에 부족이 생길 수는 없다. 반도체 묶음 한도는 N10·N15에서만 작동할 수 있다.
- 다만 가격 없는 적격 상한 168곳 중 126곳은 업종 묶음이 승인 규칙으로 정해지지 않는다. 그래서 기기에서는 40% 검사가 대부분 "확인 불가"로 나올 것으로 본다.

### 4-2. 구현 불일치 (충돌 아님 · 이번 PR 범위 밖)

1. **TARGET v1 작성 화면이 일반 6%를 거부한다.**
   - `src/investment_system/qgv/playbook_v1.json:2913-2930`의 `target_v1.grades`는 아직 `GENERAL 4~5`다.
   - `playbook-screen.js:113` `targetValidate`가 이 값으로 검사한다. 그래서 P11의 일반 6% 행은 `TARGET_THESIS_OR_GRADE_INVALID`가 된다.

2. **D-CV9 표기.**
   - `CENTRAL_V_PUBLICATION_DESIGN_20261018.md:153`, `:368`은 "한 CIK 한 순위(결정 D-CV9)"라고 쓴다.

### 4-3. 빈칸 — 소유자 결정 필요

1. **업종 묶음이 정해지지 않는 행.**
   - 승인 규칙은 19종목 배정(§7-2), SIC 하위 묶음 6개(#20), XLK·XLI 대체(#20, ETF 입력 필요)뿐이다.
   - 그 밖의 행은 묶음이 없다. 지금은 잠정 규칙대로 상한을 걸지 않고 "업종 묶음 미정"으로 센다.
   - 선택지: (a) 현행(미정·확인 불가 표시) (b) 게시본 `industry_group`(SIC 업종군 v0, 11개)을 대체 묶음으로 사용 (c) §7-1 업종 + ETF 대응(D22 초안) 확정 뒤 사용.

## 5. N 선정에 적용한 규칙

순서대로 적용한다. 공식 기본 프로필(balanced · 관문 켬 · 공식 비중)만 쓴다.

| 키 | 내용 | 근거 |
| --- | --- | --- |
| `OFFICIAL_RANK` | 공식 순위가 있는 Universe 행 | D11·D12 |
| `AXES_50` | Q·G·V 세 축 모두 산출 | P10(b) |

| `FINANCIAL_SAFETY` | 순부채/EBITDA ≥ 3 또는 이자보상 < 3 제외 | P10(b) |
| `FINANCIAL_SAFETY_NA` | 두 지표 중 하나라도 NA면 제외 | P15 |
| `SUBGROUP_MAX_4` | 하위 묶음당 최대 4. 미정은 상한 없음(잠정) | P10(c), P9 |
| `LIMITS_16` (새) | N마다 100/N 비중으로 단일 10%·업종 묶음 40%·최소 10 | P10(c), P2~P4 |

동작:
- N마다 따로 고른다. 공식 순위 순으로 내려가며 자격 행을 넣는다.
- 넣으면 업종 묶음 합이 40%를 넘는 행은 건너뛴다(`SECTOR_GROUP_MAX_40`). 다음 자격 순위가 자리를 받는다. 하위 묶음 상한과 같은 대체 방식이다. 10/14 카드 규칙의 "제외·다음 순위 대체·한도 재검사"와도 같다.
- 동일 비중 100/N은 그대로다. 행이 모자라도 다시 나누지 않는다.
- 업종 묶음별 최대 종목 수: N10 4개(4 × 10% = 40%), N15 6개(6 × 6.67% = 40%), N20 8개(8 × 5% = 40%).
- 단일 종목 상한: N ≥ 10이면 100/N ≤ 10%라 항상 통과한다.
- 반도체 묶음 밖의 묶음은 하위 묶음 하나뿐이라 4종목 상한이 먼저 걸린다. 그래서 40%가 실제로 작동하는 곳은 반도체 묶음(반도체 4 + 장비 4)이다. N20에서는 8개까지 허용되어 작동하지 않는다.

상태 값(`sets.N*.status`, 화면 `data-model-feasible`):

| 값 | 뜻 | 화면 문구 |
| --- | --- | --- |
| `FEASIBLE` | N개 구성, 16절 모두 통과 | `N15 · 16절 한도 아래 구성 가능 · …` |
| `SHORTFALL` | N개를 못 채움 | `N10 · 구성 불가 · 부족 비중 20.00% (8/10 · 채우지 않음 · 비중 재조정 없음) · 원인: 반도체 묶음 40% 한도로 4종목 초과, 대체 후보 부족, 최소 10종목 미달 · …` |
| `UNVERIFIED` | N개 구성. 업종 묶음 미정 비중 + 가장 큰 묶음 비중이 40%를 넘을 수 있어 확인 불가 | `N20 · 20종목 구성 · 업종 묶음 40% 확인 불가 · …` |
| `FAIL` | 한도 위반(선정 방식상 생기지 않음. 검사만 둠) | `16절 한도 위반` |

확인 불가 판정은 보수적이다. 미정 행이 모두 한 묶음이고 그 묶음이 가장 큰 알려진 묶음과 같다고 가정해도 40% 이하일 때만 통과로 본다.

화면 속성: `data-model-limits="N10"`, `data-model-feasible`, `data-model-shortfall-pct`, `data-model-group-status`, `data-model-group-pct`, `data-model-unknown-pct`, `data-model-group-skipped`, `data-model-causes`.
