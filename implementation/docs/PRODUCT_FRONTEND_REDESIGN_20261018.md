# Investment-System1 — 프론트엔드·분석·연구 통합 지시

사용자 지시일: 2026-10-18 KST

이 문서 전체를 Claude Code Main에게 전달한다. 기존 진행 작업을 인수하여 진행하며, 새 프로젝트를 만들거나 기존 엔진을 처음부터 재작성하라는 지시가 아니다.

## 0. 가장 먼저 반영할 사용자 정정

1. 내가 만들려던 사용자 프리셋은 **공격형·균형형·수비형**이다. 현재 코드의 `balanced / quality / growth / value`를 그 의미와 같다고 해석하지 마라. 특히 `balanced = Q34/G33/V33`이라는 현재 코드 값이 내가 의도한 균형형의 확정 정의라는 뜻은 아니다.
2. 공격형·균형형·수비형이라는 제품 방향은 확정이다. 다만 각 프리셋의 수치·제약·영향 범위는 기존 결정과 설계를 확인해 정리해야 한다. 공격형=성장형, 수비형=우량형 같은 임의 치환이나, 근거 없는 새 가중치 확정은 하지 마라.
3. **13F 가중치 기능**은 기관 관심도 슬라이더가 아니다. 과거 13F 보유와 유사한 기업을 선정하게 만드는 **Q/G/V 축 가중치와 Q1~Q5·G1~G5·V1~V5 세부 요인 가중치**를 탐색하고, 다른 기간의 유사도와 투자 성과를 검증하는 연구 기능이다.
4. 가중치 편집은 Q/G/V 3개만 제공하면 불완전하다. **축 비중과 축 내부 요인 비중의 2단계 편집**이 필요하다.
5. 레이더는 별도의 ‘QGV 보완 레이더’가 아니다. **Q축·G축·V축에 약 3개 이상의 추가 축을 합친 하나의 n각형**이다.
6. 화면은 GitHub 구조를 그대로 복제할 필요가 없다. 하지만 기존 정보의 의미·계산 기준·정렬 규칙·자료 상태·근거·사용자 결정과 연결 흐름은 유지해야 한다.
7. 사용자는 RIG 같은 내부 엔진명을 모른다. 일반 화면에서는 ‘뉴스·공시 / 기업 관계 / 영향 경로 / 근거 보기’처럼 이해할 수 있는 표현을 쓴다.

## 4. QGV와 공격형·균형형·수비형

### 4.1 공식 점수와 정보

- 최신 승인된 QGV v2를 기준으로 Q/G/V, 15개 세부 요인, 원자료, 계산 근거, 기업 유형, 비교 모집단, 버전과 시점을 표시한다.
- 각 요인은 원자료 값 → 변환·비교 기준 → 요인 점수 → 축 내부 비중 → 최종 기여도를 내려가며 볼 수 있게 한다.
- 정상/부분/미산출/해당 없음/오래됨/사용 중지를 구분한다. 값이 일부 있으면 유효한 값은 보여 주고, 없는 값의 이유와 영향도 보여 준다.
- 원래 가중치 기준 충족률·확보 요인 수·누락 항목·원래/적용 가중치를 함께 표시한다. 결측을 0점으로 넣거나 특정 요인에 임의로 몰아주지 않는다.
- 현재 최소 충족·필수 안전·버전 혼합·철회 제외 규칙을 유지한다. 점수를 표시할 수 있는 것과 TARGET 후보 자격은 구분한다.
- Q/G가 공개 파일에 있고 V가 가격을 이용해 기기에서 계산되는 현재 경계를 확인하고 따른다. 비공개 가격·포트폴리오·개인 결과를 공개 파일로 옮기지 않는다.

### 4.2 두 단계 가중치 편집

- Q/G/V 축 비중과 축마다 Q1…Q5/G1…G5/V1…V5 비중을 모두 편집·초기화·비교·저장할 수 있게 한다.
- 축 내 비중과 전체 기여 비중을 함께 표시한다. 합계, 0비중, 잠금, 범위, 결측 처리의 의미를 명확히 한다.
- 공식 프로필은 보존하고 개인 미리보기/연구 프로필을 별도로 버전 관리한다.
- 변경 전후 축 점수·종합점수·순위·커버리지·후보 자격·영향받는 안전 조건을 비교한다.
- 기존 v1 미리보기나 단순 가중평균 시연을 v2 엔진 연결 완료로 보고하지 않는다.
- 특히 `_published_axis`/`publishedAxis`가 공개 Q/G를 재사용하는 경로를 확인한다. 세부 비중을 바꿨는데 공식 축 점수를 그대로 재사용하는 오류를 막고, 요인부터 재집계하며 의존 조건도 재평가한다.
- 같은 기본 설정·입력에서 현재 공식 엔진과 일치하는 것을 먼저 확인한다. 공식 기록을 변경하지 않는 연구/개인 계산 경로로 연결한다.

### 4.3 사용자 프리셋

- 제품의 프리셋 선택은 **공격형 / 균형형 / 수비형 / 사용자 설정**으로 설계한다.
- 기존 전략 성향 계약, 과거 사용자 결정, 코드의 축 비중 프리셋을 비교해 의미·적용 범위·구현 상태를 보고한다.
- 우선 QGV 가중치 프로필로서 필요한 항목을 정리한다. 현금 비중·포트폴리오 집중도·매매 시점·TA·매크로 규칙까지 자동으로 바꾸는 것으로 확대하지 않는다. 기존 설계에 그 연결이 있으면 별도 항목으로 제시한다.
- 각 프리셋에 목적, 축 비중, 세부 요인 비중, 유지되는 안전 조건, 기대되는 선택 성향, 한계, 검증 상태를 표시할 구조를 만든다.
- 승인된 정확한 수치가 있으면 근거를 연결한다. 없으면 후보안과 검증 계획을 제시하고 미정으로 남긴다. 이름만 바꾸어 기존 4개 프리셋을 3개로 치환하지 않는다.
- 수비형이라는 이름이 손실 방지나 낮은 실현 변동성을 보장하지 않는다. 명칭과 실제 위험 특성을 별도로 검증한다.

### 4.4 리더보드

- 기존 사양과 현재 소비 코드에서 기본 정렬·동점·필터·순위 기준을 복원한다. 기본은 현재 승인된 **QGV 높은 순**이다.
- 정렬 선택기: QGV/Q/G/V, 기업명·티커, 관심기업, 시가총액, 선택 기간 수익률, 안전마진, 자료 기준일. 실제 제공되는 열부터 연결한다.
- 오름/내림·기본값 복귀를 PC/모바일에서 제공한다. 표시 문자열이 아니라 구조화된 수치로 정렬한다.
- 수익률 기간 선택과 정렬을 분리한다. 기존 1D/5D/20D를 보존하고 60D/1Y 등은 자료·거래일·가격 조정·배당 포함 여부를 정의해 확장한다.
- SIC 산업, 기업 유형, 분석 가능 상태, 점수·시총·안전마진·최신성·실적 일정 등의 필터를 연결한다.
- 공식/개인, 원점수/유형 반영 값은 실제 별도 값이 있는 경우에만 구분 표시한다. 없는 값을 이름만 바꿔 만들지 않는다.
- NA는 양방향 정렬에서 마지막, 순위 없음은 숫자로 채우지 않는다. 필터로 원래 순위를 다시 매기지 않는다.
- 분석 모집단·현재 순위 가능 수·표시 수를 구분한다. 504 요인 모집단, 현재 화면 대상, 기기 시총 부분집합을 같은 범위라고 주장하지 않는다.
- 현재 QGV 동점 규칙과 시총 동점 규칙을 각각 보존한다. 신규 표시 정렬이 공식 순위를 바꾸지 않게 한다.
- 컨센서스/조건별 가치/재평가/실적 일정/변동성·낙폭/모의·연구 보내기 등 기존 정보 목적을 재사용한다. 미연결 열의 사유를 표시한다.

### 4.5 하나의 n각형 레이더

- Q/G/V + 추가 약 3축 이상. 추가 축은 변동성·낙폭·유동성 등 QGV와 다른 시장 특성을 후보로 조사한다. 이 예시가 축의 최종 확정은 아니다.
- 한 기업, SIC 비교군, 산업 평균, 경쟁기업 평균/개별기업을 같은 도형에서 선택·비교하게 한다.
- 원자료 단위·기간·정규화·높을수록 뜻하는 것·비교군 구성과 수를 보여 준다. 위험이 큰 값을 좋은 점수처럼 오해하게 하지 않는다.
- 동종 자료·동일 시점 기준으로 비교한다. 부족한 비교군이나 결측 축은 비워 표시하며 0 또는 평균으로 메우지 않는다.
- 면적을 새 종합점수로 사용하지 않는다. 비교선이 많으면 선택형으로 줄이고 원자료 표도 제공한다.

## 5. 13F 기반 가중치 연구

목적: 과거 기관 공개 보유와 비슷한 기업을 선택하는 QGV 가중치 후보를 찾고, 그 후보가 이후에도 설명력과 투자 효과가 있는지 검증한다.

- 기존 기관별/기업별/내 기업 겹침·분기 변화 조회는 유지한다.
- 먼저 Track C와 Investor-QGV 자산을 조사하고, 현재 운영 13F의 최신 두 분기 수집과 장기 연구 패널을 구분한다.
- 필요한 연결을 명시한다: 다년 기관×분기 보유, 정정 계보, 공개 시각, 시점별 CUSIP·종류주·기업 식별, 당시 모집단, 당시 15요인, 가격·기업행사·상장폐지, 후보 가중치 계산, 탐색기, 평가·등록부.
- 현재 파서·검증·계층·통계 커널을 재사용할 수 있어도 장기 자료와 현재 v2 계산 연결이 없는 상태를 완성으로 부르지 않는다.
- 축 비중만 / 세부 비중만 / 둘 다 변경하는 실험을 분리한다. 탐색 범위·제약·목적함수·시도 수를 기록한다.
- 보유 유사도: 상위 N 겹침·정밀도/재현율·순위 유사도 등. 보고금액 비중은 단위·분모·적격성이 검증된 연구 자료에서만 사용한다.
- 모집단 밖·식별 불명·13F 비대상 자산을 기관의 부정 선택으로 간주하지 않는다. 연결률·제외·미확인 수를 보고한다.
- 분기말 보유와 실제 공시 공개 시각은 다르다. 보유를 사후 설명하는 실험과 공개 후 실행 가능한 전략을 구분한다.
- 시간순 학습→검증→미사용 기간 평가를 분리하고, 미래 공시·정정·가격을 사용하지 않는다.
- 가중치 변화로 후보 자격·커버리지도 변할 수 있으므로 공통 적격 모집단과 실제 적용 모집단의 결과를 따로 본다.
- 가중치를 고정한 뒤 시장 총수익·현행 QGV·단순 기준과 별도로 수익/위험을 비교한다. 유사도가 높다고 수익성이 검증됐다고 하지 않는다.
- 여러 가중치가 같은 선택을 만들 수 있다. 후보군·범위·기간별 안정성을 보여 주고 ‘기관의 진짜 가중치 복원’이라고 주장하지 않는다.
- 공식 기본값을 자동 변경하지 않는다. 연구 결과→개인 실험 적용→공식 채택은 구분한다.
- 화면 흐름: 기관·기간 선택 → 자료 연결률 → 탐색 범위 → 가중치 트리 비교 → 미사용 기간 유사도 → 투자 성과 → 연구 프로필 저장.

## 6. 기술적 분석

- 기존 추세·모멘텀·거래량·상대강도·가격 구조·변동성 목적과 SMA/EMA·RSI/MACD·ATR/Bollinger 등 실제 구현을 재사용한다.
- 일봉/주봉, 확대·이동·교차선·측정, 가격/거래량, 지표 토글, 사건·거래·평균매입가를 연결한다. 미구현 항목은 구분한다.
- 지표/패턴의 ‘정도’는 탐지 민감도와 구체 파라미터로 보여 준다. 무엇이 바뀌는지·유효 범위·기본값 복귀를 제공하고 공식 이력을 덮지 않는다.
- 기존 승인된 패턴 단계와 착수 조건을 유지한다. 박스 돌파/이탈, 이중 바닥/천장부터라면 **실패·무효화·만료**도 같은 단계에 포함한다.
- 형태 적합도와 상승 확률을 구분한다. 미래 봉이 필요한 고점/저점은 확인 가능한 시점 이후에만 기록한다.
- 기업행사·가격 기준 연속성을 확인하지 못하면 관련 구간은 판정 불가와 사유를 표시한다. 임의 보정하지 않는다.
- 장기·스윙 둘 다 제품 범위다. 진입·무효화·목표·손익비·수량·시나리오 비교의 구현 단계는 기존 승인과 자료 상태에 맞춘다.
- 사용자가 차트 위에 선·영역·메모·시나리오를 그려 저장하게 한다. 종목·봉 주기·조정 기준·시간/가격 좌표에 붙여 확대/이동해도 유지한다.
- 사용자 그림·가정과 공식 탐지 기록을 구분하고, 사용자가 그린 선을 공식 감지 증거로 쓰지 않는다.
- 가격 요청 범위·호출량·메모리·저장·Worker 정책은 기존 결정을 따른다. LWC 번들·출처 표기·외부 요청 여부는 실제 네트워크로 확인한다.

## 7. 매크로와 사건 영향 경로

- 기존 성장·물가·유동성·통화정책·신용·노동·재정·외환 8축과 수준/방향/모멘텀/예상 대비/스트레스/신뢰도 6차원을 보존한다.
- 별도의 5개 위험 경고등과 현재 참고 모드도 보존한다. 재가동을 디자인 변경에 끼워 넣지 않는다.
- 경기와 주식시장 각각의 현재 추정 위치, SIC 산업 사이클·순환매 위치, 근거와 상향/유지/하향 조건을 보여 주는 모델을 설계한다.
- 실제 관측 시계열과 설명용 사이클 도식은 구분한다. 근거 지표·사건은 발표 시점의 수직선으로 연결하고, 당시에 알 수 있었던 자료를 사용한다.
- 확률은 모델·표본·기간·검증 근거가 있을 때만 표시한다. 그 전에는 가설/미산출로 두고 자료 신뢰도를 확률로 바꾸지 않는다.
- 사용자의 예상 위치·이유·시각을 저장하고 시스템 추정과 나란히 비교한다. 공식 과거 위치를 덮지 않는다.
- 사건 영향 기능의 사용자 명칭은 우선 ‘영향 경로’로 두고 후보 이름을 제안한다. 기존 관계망·근거·노출 경로를 확장하고 별도 중복 그래프를 만들지 않는다.
- 예: 강우 → 작황 → 원두 공급/가격 → 계약·헤지/원가 → 기업 이익. 예: 경쟁사 인수 → 업계 재편 → 잠재 인수 후보. 두 경우 모두 전제·시차·반대 경로·상쇄 요인·반증 조건을 표시한다.
- 비가 많으면 반드시 수확이 늘어난다거나 경쟁사의 인수가 다음 인수를 확정한다는 단순 규칙을 만들지 않는다. 확인된 관계, 추론, 아직 검증하지 않은 가설을 나눈다.

## 8. 뉴스·공시·기업 관계

- 기존 공개 피드와 관계망 도메인을 각각 확인한다. 공개 뉴스 피드가 있다는 이유로 풍부한 관계망까지 화면에 연결됐다고 보지 않는다.
- 공시·확정 / 뉴스·신호, 사실/추정/미확인, 출처·발표·수집 시각, 신규/중복을 유지한다.
- 실적·제품/서비스·인수합병·법률/규제 등 기존 분류와 중복 사건 묶기를 재사용한다.
- 중요도 기준을 보존한다: 보유 중요 소식 → 관심 중요 소식 → 내 기업에 직접 연결된 중요 소식 → 조사 후보 → 기타 내 기업 → 시장. 같은 그룹의 시간 정렬도 명확히 한다.
- 검색값이 없으면 매크로 관점의 발견 후보를 무작위로 보여 줄 수 있지만, 추천 근거·자료 시각을 표시하고 중요 소식 피드를 밀어내지 않는다.
- 기업 즐겨찾기는 단일 관심 목록을 공유한다. 뉴스와 관계 화면이 별도의 관심 목록·사건 사본을 만들지 않는다.
- 공급망·고객·경쟁·밸류체인 관계와 계약 상태, 관계 강화/약화·신규/종료를 구분한다. 뉴스↔관계망 이동 때 선택 사건·기업·필터를 유지한다.
- 요약은 5줄 이내로 사실, Q/G 영향 가설, 단기/구조적·호재/악재, 영향 기간·조건을 표시하고 원문 근거를 연결한다.
- 주가 반영 여부는 직접 확인 가능한 사실이 아니다. 사건 전후 가격·거래량·시장/산업 대비 반응과 불확실성을 보여 준다. 근거 없는 반영률·Q/G 점수 변화·확률을 만들지 않는다.
- 운영 점수에 자동 가산하지 않는다. 뉴스 해석과 정식 재무 점수 갱신을 분리한다.

- 개발자 기본값은 설정과 명시적 예시를 뜻한다. 사용자의 실제 보유·현금·거래·수익률을 가상 값으로 채우지 않는다.
- 인증/동기화가 없으면 이를 신규 백엔드로 표시한다. 로그인 모양만 있는 화면을 구현 완료로 부르지 않는다.
- 익명 데이터를 계정으로 가져올 때는 충돌·계정 간 격리·가져오기 선택을 처리한다. 개인 투자 자료를 외부 도구로 보내는 범위를 명시한다.

## 11. 시스템 트리·예시·온톨로지

- 각 영역에 ‘이 분석은 어떻게 만들어지나’를 접어서 제공한다. 투자시스템 전체 트리도 별도 메뉴로 제공한다.
- 트리는 데이터 → 지표 → 판단 → 비교 → 시나리오/기록의 흐름을 보여 준다. 코드 폴더 구조를 복사하지 않는다.
- QGV는 축→요인→원지표·비중·비교군까지, 기술/매크로/뉴스/포트폴리오는 입력·규칙·출력·검증까지 내려가게 한다.
- 아래에 작은 예시 값과 계산 과정을 제공한다. 실제 자료면 출처·시점을, 합성 예시면 지속적인 예시 표시를 붙인다.
- 기존 발행사·증권·상장 식별을 재사용한다. 티커를 영구 기업 ID로 쓰거나 관계망용 두 번째 기업 레지스트리를 만들지 않는다.
- 산업(SIC/GICS), 투자 유형, 전략 테마는 목적이 다른 독립 분류다. 서로를 상하위로 강제하지 않는다.
- 기업·증권·공시·뉴스 사건·관계·관측·요인/점수·프로필·포트폴리오·시나리오·실험 사이의 실제 식별자 연결표를 만든다.
- 공개 시각/기준 기간/수집 시각/계산 버전을 구분하고, 공식/개인·실제/모의·사실/가설·관측/추정 관계를 보존한다.

## 12. Lab: 가중치 효과와 전진검증

- 현재 고정 QGV 가중치가 투자 결과에 효과가 있는지 검증하는 실험을 유지한다. 13F 가중치 탐색 때문에 기존 주검정을 몰래 변경하지 않는다.
- N10/15/20, QGV 단독, QGV+기술적 분석, 이후 승인된 매크로 조합을 비교한다. 현재 등록된 주검정·대조군·미사용 기간을 확인해 따른다.
- 현행 비중, 축 균등, 내부 요인 균등, V 제거 등 기존 비교 실험의 의미와 모집단 차이를 보존한다.
- 공격형/균형형/수비형과 13F 학습 후보는 별도 실험 ID·버전으로 등록한다.
- 시장 비교는 동일 기간/통화의 S&P 500 총수익을 기본으로 기존 승인된 추가 지수를 사용한다. 가격수익과 총수익을 혼동하지 않는다.
- 수익률 외 변동성·최대낙폭·회복 기간·하방 위험·위험조정 성과·시장 대비 초과성과·회전율·거래비용·집중도·자료 커버리지를 정의하고 평가한다.
- 분기/연도/시장 국면, 비용 민감도, 불확실성·기간별 안정성을 보고한다. 최적 결과 하나만 골라 제시하지 않는다.
- 생존편향, 과거 편입/퇴출, 상장폐지, 기업행사, 당시 공시·자료 공개 시점, 체결 시점, 결측 수익 처리를 검증한다.
- 문서/합성 시험/현재 생존 기업 탐색/정식 PIT 실험/전진검증을 별도 상태로 표시한다. 전진 원장의 과거 기록을 수정하지 않는다.

## 13. 실행 순서와 병렬 작업

Main은 전체 통합·결정 기록·공통 파일·CURRENT_HANDOFF를 소유한다. specialist는 겹치지 않는 브랜치와 write-set으로 작업하고 Main이 통합한다.

0단계: 최신 인수, 기능 대응표, 결정 정정, 중복 자산 확인, 전체 페이지의 정보구조·데이터 계약 확정.
1단계: 기존 엔진 의미를 바꾸지 않는 검색·앱 셸·디자인 체계·리더보드·상세·자료 상태·뉴스/보고 연결 개선.
2단계: 승인 조건을 충족한 가중치 편집·차트·노트·프롬프트·개인화 연결. 미정인 백엔드는 별도 설계/연구 상태로 유지.
3단계: 13F 탐색·새 프리셋 수치·산업 사이클/확률·영향 경로 정량화 등 추가 모델을 자료와 평가 기준에 맞춰 구현·검증.

병렬 lane:
- A: 디자인·앱 셸·검색·반응형·접근성.
- B: QGV 정보/리더보드·2단계 비중·프리셋 계약·레이더.
- C: 13F/Track C 재사용 조사·연구 어댑터·검증 설계.
- D: 기술적 분석·차트 데이터·패턴/노트 계약.
- E: 매크로·뉴스·관계망·영향 경로 연결.
- F: 포트폴리오·보고·프롬프트·개인화.

실제 동시 실행 수는 자원과 write-set 충돌에 맞춰 조정한다. `app.js` 같은 공통 파일을 여러 lane이 동시에 수정하지 않는다. 좁은 모듈·어댑터 단위로 반환하고 Main이 합친다.

- 모든 lane이 끝날 때까지 기다리지 말고 의존성이 없는 승인 작업은 계속한다.
- 대기하면 무엇을 기다리는지, 기다리는 작업만 무엇인지, 병렬로 진행한 작업은 무엇인지 적는다. 할 일이 남았는데 ‘할 일 없음’이라고 하지 마라.
- 이미 승인된 디자인·구현 세부를 반복 승인받지 않는다. 새로운 방법론·유료 자료·실제 권한 변경 등의 미정 사항은 근거와 구체 대안을 묶어 제시한다.
- 기존 운영·배포·PR 필수 체크를 완화하지 않는다. 실패 이유를 확인하고 영향받는 검증만 다시 하되 필수 게이트는 지킨다.
